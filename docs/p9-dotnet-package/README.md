# P9 — .NET Package

> **Pre-alpha, experimental.** P9 builds the .NET binding of the frozen sas-pairing native ABI v1. It is not production-security approved, not audited, and not formally verified. The protocol is implemented only by the native Rust core; C# binds C.

**Status: P9 IN PROGRESS — P9.4 COMPLETE.** P9.1 (.NET package foundation + exact ABI v1 interop), P9.2 (Runtime / Authority / Host lifecycle wrapper, [P9-D-002](decisions.md#p9-d-002--net-lifecycle-ownership-public-errors-and-fail-closed-state)), P9.3 (Windows listener ownership + cooperative network driver, [P9-D-003](decisions.md#p9-d-003--net-windows-listener-cooperative-drive-event-and-connection-ownership)), and P9.4 (run + ceremony control + SAS presentation, [P9-D-004](decisions.md#p9-d-004--net-run-identity-explicit-ceremony-control-and-sas-binding)) are complete. Next: P9.5 (PairingResult API + ownership), not started. Roadmap: [P9 — .NET Package](../../roadmap/P9-dotnet-package.md). Decisions: [decisions.md](decisions.md). Package: [`dotnet/`](../../dotnet/README.md).

## P7 wrapper handoff

The mandatory obligations of [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9) and where P9 meets them.

| # | Obligation | P9 state |
|---|---|---|
| 1 | Bind exactly ABI v1; check `sas_pairing_abi_version() == 1` before any other call | P9.1: the loader preflights all 25 exports and requires version `1` before publishing the binding; `0` and any other value fail permanently |
| 2 | One native image, retained for the process lifetime; never `NativeLibrary.Free`; no unload, reload, reset, or alternate copy | P9.1: one `NativeLibrary.Load` from an explicit path, retained; no free or reset path exists; a second initialization opens nothing |
| 3 | Tell consumers that `SAS_PAIRING_FATAL` needs an OS process restart | P9.2: `SasPairingNativeException.ProcessRestartRequired` is true exactly for status 900; the wrapper latches it process-wide and refuses every later normal operation locally (cleanup still runs); no reset, reload, or re-initialize exists; post-load initialization failures also require a restart |
| 4 | Caller-memory contract | P9.2 for the lifecycle: stack-local output slots passed for one synchronous call, the binary scope pinned for one call with its exact length (null with length 0 when empty), nothing retained, no native allocation; P9.3 for the network: the socket in a stack-local in/out slot, every Bootstrap field pinned for one call (null with length 0 when empty), 17 stack-local event records and distinct `out_count` / `out_failure`, every record copied before the call returns; P9.4 for the ceremony: one zeroed aligned stack action or presentation record per call, copied only on `OK`, a decision's exact 32 identity bytes pinned for the call, the Bootstraps through the one shared marshalling path; P9.5 for results |
| 5 | Listener handoff through the in/out slot | P9.3: the token is updated from the slot before any status is thrown (`INVALID` → transferred and the handoff descriptor's `SafeSocketHandle` invalidated without closing it; the offered value → still the caller's; anything else → contract violation with the token conservatively consumed); the caller's `Socket` never shares a descriptor with native (P9-D-003 W), so no managed disposal or finalizer can close the native-owned socket |
| 6 | Cooperative bounded drive; consume every event, also when `out_failure` is not OK | P9.3: one native drive per `Drive()` and one recheck per `RecheckAfterResume()`, no background driver; every event of an `OK` call is mapped in order before `out_failure` takes effect (`FailedClosed`, connections disposed, `Fatal` latched without discarding the batch) |
| 7 | SHOULD close a connection after `RUN_UNTRACKED` | P9.3: the event reports `RunUntracked` and `ShouldDisposeConnection`, and the consumer is told to call `evt.Connection?.Dispose()` after the batch; the drive never closes it itself |
| 8 | Explicit ceremony steps, `WRITE_PENDING` handling, decisions bound to the exact `ceremony_identity` | P9.4: one native call per step with no chaining, driving, or retry (source-guarded); status 205 is a thrown "did not run", the action's `WritePending` a "ran, frame retained"; MATCH, MISMATCH, and CANCEL pass the presented 32-byte `SasPairingCeremonyIdentity` unchanged and native alone judges it |
| 9 | Never construct, parse, or send frames; never confirm a final ACK | P9.1: no protocol code exists in C# (scope-guarded); P9.4: no final-ACK confirmation exists under any name (reflection- and source-guarded), and the real ceremony's final ACK is confirmed by the native library inside a drive |

| 11 | Own the comparison UX and trust policy; no status is a trust verdict | P9.2: the public `SasPairingStatus` (48 values) and the exceptions describe operation outcomes only, with no trust, attack, or compromise property (reflection-checked); P9.4: the presentation is display data (`DecimalDisplay`, `CeremonyIdentity`) with no match, approval, or trust property, and the package never compares displays or approves |

## Loader contract (P9-D-001)

`NativeAbiV1Loader.Process.Initialize(path)` is the one internal entry. It requires an 8-byte pointer width, a fully qualified path to an existing file (canonicalized), makes exactly one `NativeLibrary.Load`, preflights the 25 exports by exact name, binds the function table, and requires `sas_pairing_abi_version() == 1`. Pre-load failures may be retried; post-load failures are permanent for the process and keep the image. Once ready, every later call returns the identical binding without reading its path. Nothing is searched, discovered, or downloaded, and the image is never freed, unloaded, reloaded, or replaced. One `SasPairing` assembly instance in the default load context owns the one image; another load context is outside the supported model.

## Lifecycle contract (P9-D-002)

`SasPairingRuntime.Create(path)` initializes the one P9.1 process loader (translating its failure into `SasPairingInitializationException` by an exhaustive switch, with no inner private exception), obtains the one process context, and calls `sas_pairing_runtime_create`; `RegisterAuthority(ReadOnlySpan<byte>)`, `GetStatus()`, and `CreateHost()` follow. Each requires `OK` and a non-zero handle or a valid status snapshot (`Ready` 1–10, `Busy` 0, `Exhausted` 0), else `SasPairingContractException`. Admission of a normal operation: disposed check (`ObjectDisposedException`), then the contract latch, then the `FATAL` latch, then the one native call. Cleanup (`Dispose`) is never admission-checked: one native call per object (`host_destroy`, `authority_release`, `runtime_destroy`), after which the object and every descendant are disposed locally whatever the status, and a failure is then thrown once. Disposing and re-creating a runtime reuses the image, the context, and both latches, and resets no security accounting.

## Network contract (P9-D-003)

The application binds and listens; `SasPairingWindowsListenerSocket.FromSocket(socket)` (Windows only) moves the listening socket into a package-owned duplicate descriptor and closes the caller's `Socket`. `AttachWindowsListener(token, local, expected)` is a normal operation (host disposed check, the token's single-attempt gate, admission, one native call); the slot decides ownership before any status is thrown, and attach drives nothing. `DetachListener()` is repeatable cleanup that disposes every connection locally and keeps the host. `Drive()` is one bounded native drive and `RecheckAfterResume()` one native recheck; a non-zero function status returns no batch, while on `OK` every event is mapped in order before a non-zero `out_failure` fails the host closed. One native connection handle is one `SasPairingConnection` (`IDisposable`, one native close). Run handles stay internal exact references and results stay runtime-owned internal references until P9.4 and P9.5. The network states are `Detached`, `Attached`, `ListenerDisabled` (connections continue), and `FailedClosed` (every connection gone).

## Ceremony contract (P9-D-004)

One exact native run handle is one `SasPairingRun`, the same object in `StartInitiator(...).Run`, every later `SasPairingLocalAction.Run`, and every `SasPairingEvent.Run` of that run; its request ID is routing metadata only (unknown for a local start until a drive event names the run, learned once, never changed, never public on the run). Each of the nine steps is one native call under the runtime lock (known-ended check, then admission, then the call) with no chaining, driving, or retry. A successful record is checked against the frozen per-method outcome table before any lifetime change; status 205 means the step did not run, while `WritePending` on a returned action means it ran and its frame awaits a drive. Presentation is read-only and returns null or `CeremonyIdentity` + `DecimalDisplay` (`NNNN NNNN NNNN`); decisions pass the exact 32-byte identity, which only native judges. Reject, cancel, and deadline end the run; native 204, `ConnectionEnded`, `OwnershipUncertain`, and `OwnerLoopClosed` apply their exact lifetime effects in one handler; `Fatal` only latches. No final-ACK API and no result API exist.
