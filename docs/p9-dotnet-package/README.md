# P9 — .NET Package

> **Pre-alpha, experimental.** P9 builds the .NET binding of the frozen sas-pairing native ABI v1. It is not production-security approved, not audited, and not formally verified. The protocol is implemented only by the native Rust core; C# binds C.

**Status: P9 COMPLETE — .NET PACKAGE + WINDOWS X64 NATIVE DISTRIBUTION.** All six increments are complete: P9.1 (.NET package foundation + exact ABI v1 interop, [P9-D-001](decisions.md#p9-d-001--net-abi-v1-binding-and-loader-architecture)), P9.2 (Runtime / Authority / Host lifecycle wrapper, [P9-D-002](decisions.md#p9-d-002--net-lifecycle-ownership-public-errors-and-fail-closed-state)), P9.3 (Windows listener ownership + cooperative network driver, [P9-D-003](decisions.md#p9-d-003--net-windows-listener-cooperative-drive-event-and-connection-ownership)), P9.4 (run + ceremony control + SAS presentation, [P9-D-004](decisions.md#p9-d-004--net-run-identity-explicit-ceremony-control-and-sas-binding)), P9.5 (PairingResult API + ownership, [P9-D-005](decisions.md#p9-d-005--net-pairingresult-ownership-reads-and-immutable-snapshots)), and P9.6 (.NET / native distribution + final P9 closure, [P9-D-006](decisions.md#p9-d-006--net-managed-package-native-artifact-distribution-and-p9-closure)). The authoritative summary is the [P9 final closure](final-closure.md). Next: P10 (consumer integration / DovahLink example), not started. ## Loader contract (P9-D-001)

`NativeAbiV1Loader.Process.Initialize(path)` is the one internal entry. It requires an 8-byte pointer width, a fully qualified path to an existing file (canonicalized), makes exactly one `NativeLibrary.Load`, preflights the 25 exports by exact name, binds the function table, and requires `sas_pairing_abi_version() == 1`. Pre-load failures may be retried; post-load failures are permanent for the process and keep the image. Once ready, every later call returns the identical binding without reading its path. Nothing is searched, discovered, or downloaded, and the image is never freed, unloaded, reloaded, or replaced. One `SasPairing` assembly instance in the default load context owns the one image; another load context is outside the supported model.

## Lifecycle contract (P9-D-002)

`SasPairingRuntime.Create(path)` initializes the one P9.1 process loader (translating its failure into `SasPairingInitializationException` by an exhaustive switch, with no inner private exception), obtains the one process context, and calls `sas_pairing_runtime_create`; `RegisterAuthority(ReadOnlySpan<byte>)`, `GetStatus()`, and `CreateHost()` follow. Each requires `OK` and a non-zero handle or a valid status snapshot (`Ready` 1–10, `Busy` 0, `Exhausted` 0), else `SasPairingContractException`. Admission of a normal operation: disposed check (`ObjectDisposedException`), then the contract latch, then the `FATAL` latch, then the one native call. Cleanup (`Dispose`) is never admission-checked: one native call per object (`host_destroy`, `authority_release`, `runtime_destroy`), after which the object and every descendant are disposed locally whatever the status, and a failure is then thrown once. Disposing and re-creating a runtime reuses the image, the context, and both latches, and resets no security accounting.

## Network contract (P9-D-003)

The application binds and listens; `SasPairingWindowsListenerSocket.FromSocket(socket)` (Windows only) moves the listening socket into a package-owned duplicate descriptor and closes the caller's `Socket`. `AttachWindowsListener(token, local, expected)` is a normal operation (host disposed check, the token's single-attempt gate, admission, one native call); the slot decides ownership before any status is thrown, and attach drives nothing. `DetachListener()` is repeatable cleanup that disposes every connection locally and keeps the host. `Drive()` is one bounded native drive and `RecheckAfterResume()` one native recheck; a non-zero function status returns no batch, while on `OK` every event is mapped in order before a non-zero `out_failure` fails the host closed. One native connection handle is one `SasPairingConnection` (`IDisposable`, one native close). Run handles stay internal exact references and results stay runtime-owned internal references until P9.4 and P9.5. The network states are `Detached`, `Attached`, `ListenerDisabled` (connections continue), and `FailedClosed` (every connection gone).

## Ceremony contract (P9-D-004)

One exact native run handle is one `SasPairingRun`, the same object in `StartInitiator(...).Run`, every later `SasPairingLocalAction.Run`, and every `SasPairingEvent.Run` of that run; its request ID is routing metadata only (unknown for a local start until a drive event names the run, learned once, never changed, never public on the run). Each of the nine steps is one native call under the runtime lock (known-ended check, then admission, then the call) with no chaining, driving, or retry. A successful record is checked against the frozen per-method outcome table before any lifetime change; status 205 means the step did not run, while `WritePending` on a returned action means it ran and its frame awaits a drive. Presentation is read-only and returns null or `CeremonyIdentity` + `DecimalDisplay` (`NNNN NNNN NNNN`); decisions pass the exact 32-byte identity, which only native judges. Reject, cancel, and deadline end the run; native 204, `ConnectionEnded`, `OwnershipUncertain`, and `OwnerLoopClosed` apply their exact lifetime effects in one handler; `Fatal` only latches. No final-ACK API exists.

## Result contract (P9-D-005)

A result is THIS endpoint's local verified completion only: not peer completion, final-message receipt, a bilateral commit, or trust. One exact native result handle is one `SasPairingResult`, delivered only as `SasPairingEvent.Result` (`HasResult` is exactly `Result is not null`) and owned by the runtime: it survives connection close, detach, owner-loop failure, host and authority disposal, and `FATAL`, and ends only by `Dispose()` (one consuming native destroy) or the runtime's disposal (no child destroy; disposed locally). A handle delivered twice is a contract violation, also after disposal. `Read()` is data access (admitted after `FATAL`, refused after a contract violation; `Dispose()` always runs): one info, the info validated (32 identity bytes, peer role 1 or 2, source-proven bounds 64 / 16,384 / 8,192 / 38), one copy per field at exactly the info length, any `BUFFER_TOO_SMALL` or length mismatch a contract violation, nothing partial, the result left open on failure. `SasPairingResultData` is an immutable detached snapshot of exact bytes (the peer Bootstrap frame is never parsed, nothing is decoded), the PEER's role, and the P9.4 ceremony identity. There is no result polling, lookup, trust, enrollment, or persistence.
