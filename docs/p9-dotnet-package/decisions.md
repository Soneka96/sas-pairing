## P9-D-001 — .NET ABI v1 Binding and Loader Architecture

- **Inputs:** the frozen ABI v1 surface (version 1, 25 exports, 48 statuses, 84 namespace values, 11 scalar constants, 6 records; [manifest](../p7-native-abi/abi-v1-manifest.md), [`sas_pairing.h`](../../core/include/sas_pairing.h)); the loader invariant of [P7-D-002](../p7-native-abi/decisions.md#p7-d-002--native-library-residency-and-loader-lifetime) and [ABI contract §14](../p7-native-abi/abi-contract.md#14-native-library-loading-and-residency) (one native image per OS process, resident until exit, no unload, reload, or alternate copy, process restart as the only recovery from `SAS_PAIRING_FATAL`); the wrapper handoff of [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff) item 13 and [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9), which names `NativeLibrary.Free` explicitly for P9; the P8 Dart implementation ([P8-D-001](../p8-dart-package/decisions.md#p8-d-001--dart-native-binding-and-loader-architecture)) as reference evidence for wrapper semantics, not as a source. .NET facts that shape the design: `NativeLibrary.Load(string)` loads a module by path and returns an OS handle, `NativeLibrary.TryGetExport` looks a symbol up without calling it, and only `NativeLibrary.Free` releases a handle (nothing frees it implicitly); `[DllImport]` / `[LibraryImport]` resolve a library name through the runtime's probing and the OS search order; `delegate* unmanaged[Cdecl]<...>` is an allocation-free, exactly typed unmanaged function pointer; C# statics are per assembly instance, so another `AssemblyLoadContext` loading the assembly gets its own.
- **Decision (owner-selected in the P9.1 task):**
  - **A. Package.** `dotnet/` holds one library project `SasPairing` (package ID, root namespace, and assembly `SasPairing`, version `0.1.0-dev.1`, `net10.0`) and one test project `SasPairing.Tests` (xUnit v3), in `dotnet/SasPairing.sln`. .NET 10 is the current LTS baseline for this new experimental package; there is no multi-targeting, `netstandard`, or downgrade. The library has no runtime package dependency. `IsPackable` is `false` in P9.1: no NuGet package is built or published; P9.6 decides distribution.
  - **B. Build settings.** Nullable reference types, implicit usings, unsafe blocks (for `Interop/` only), warnings as errors, `latest-recommended` built-in analyzers, deterministic builds, XML documentation generation, and locked restore (`packages.lock.json` committed). No warning is suppressed. The SDK is pinned by `dotnet/global.json` to `10.0.401` with `rollForward: latestPatch` (a later 10.0.4xx patch is accepted; no other feature band or major version), and `dotnet test` uses the Microsoft.Testing.Platform runner selected there.
  - **C. Exact ABI v1 only.** The wrapper binds exactly `SAS_PAIRING_ABI_VERSION = 1`, required by a C# literal that the tests compare with the header and the manifest. There is no ABI negotiation, fallback, legacy mode, compatibility shim, or second ABI. `sas_pairing_abi_version()` returning anything but `1` fails initialization.
  - **D. Explicit native image, never default resolution.** No `[DllImport]`, `[LibraryImport]`, `extern` method, `DllImportResolver`, library basename, or OS / runtime search is used. The one production load is `NativeLibrary.Load(path)` of a validated, canonical, fully qualified path, followed by `NativeLibrary.TryGetExport` of each frozen export by exact name.
  - **E. One private function table.** `AbiV1FunctionTable` holds exactly 25 `internal readonly delegate* unmanaged[Cdecl]<...>` fields, each named exactly as its export and resolved by that name (`nameof`), so a field and its symbol cannot drift apart. There are no 25 P/Invoke methods, no managed delegates, and no public function pointer.
  - **F. Type mapping.** `int32_t` → `int` (`sas_pairing_status_t`); `uint32_t` → `uint` (every `uint32_t` namespace); `uint64_t` → `ulong` (the six opaque handles, `0` invalid, never a pointer or identity); `uint8_t` → `byte`; `size_t` → `nuint`; `uintptr_t` → `nuint` (`sas_pairing_socket_t`, invalid `nuint.MaxValue`); pointers → unmanaged pointer types; inline arrays → fixed buffers. `size_t` and `uintptr_t` are never `ulong`, even where both are 8 bytes. The raw layer spells every ABI identifier exactly as the header does (constants, records, fields, exports); idiomatic C# names begin with the high-level API in P9.2.
  - **G. Records.** The six frozen records are internal `LayoutKind.Sequential` structs with fixed buffers for inline arrays and no managed array, string, `bool`, `char`, or reference, so each is blittable with exactly the native layout (bytes view 16/8, bootstrap view 64/8, event 128/8, result info 56/4, action 24/8, SAS presentation 56/4, with the manifest offsets).
  - **H. Pointer width.** Initialization requires `IntPtr.Size == 8` before any path work or load; the 64-bit layouts are never reinterpreted in a 32-bit process.
  - **I. Loader.** One internal `NativeAbiV1Loader` with a process instance (`NativeAbiV1Loader.Process`). Order: (1) pointer width 8; (2) the explicit path must be non-empty, fully qualified (`Path.IsPathFullyQualified`), and an existing file, and is canonicalized (full path, final link target); (3) exactly one `NativeLibrary.Load` of the canonical path; (4) the image is retained; (5) all 25 exports are preflighted by exact name (a lookup, never a call); (6) the function table is bound; (7) `sas_pairing_abi_version()` is called, the only native call during initialization; (8) it must return `1`; (9) the binding is published. Initialization is serialized by a lock, so concurrent callers load one image.
  - **J. Loader states.** `Uninitialized`, `Ready`, `PermanentlyFailedAfterLoad`. Pre-load failures (`UnsupportedPointerWidth`, `InvalidLibraryPath`, `OpenFailed`: `NativeLibrary.Load` threw, so no handle exists) leave the loader `Uninitialized` with nothing retained, and a later call may retry after the cause is fixed. Post-load failures (`MissingSymbol`, `BindingFailed`, `AbiVersionQueryFailed` for version `0`, `AbiVersionMismatch` for any other value) are permanent for the loader: the handle stays retained and is never freed, no other path is ever inspected or loaded, no second image is opened, and every later call throws the same exception, whose message says to correct the native library and restart the OS process. Version `0` means the native query itself failed; it is never "an old ABI" or "try again". A missing export is never optional and no partial table is kept.
  - **K. Ready is final.** Once ready, every later initialization returns the identical `NativeAbiV1` without inspecting its path argument, opening anything, or querying again. There is no reset, reload, or replacement, in production or for tests: state-machine tests construct their own loaders over fake platforms, never through the process loader.
  - **L. No release of the image.** Production never calls `NativeLibrary.Free`; there is no `Dispose`, `SafeHandle`, finalizer, `ProcessExit` or `AssemblyLoadContext.Unloading` handler, or other path that releases the module. The retained handle is intentionally kept until the OS process exits, because the native state is module state of the loaded image (P7-D-002): freeing it would end that state, and reloading would start fresh state, which is not a supported recovery.
  - **M. Assembly load context.** The supported model is one `SasPairing` assembly instance, loaded normally into the default `AssemblyLoadContext`, owning the one native image of the OS process. Loading the assembly again in another load context (or a copied native module) would create a second loader; that is outside the supported model, is never presented as a recovery mechanism, and cannot be detected or prevented by the wrapper. P9.1 builds no cross-load-context logic.
  - **N. Private raw interop.** Every raw type (constants, records, function table, loader, platform seam, failure categories, initialization exception) is `internal` under `dotnet/src/SasPairing/Interop/`, visible only to `SasPairing.Tests` through `InternalsVisibleTo`. P9.1 exports no public type at all; no handle, pointer, function pointer, record, constant, or `NativeLibrary` handle is public now or as the basis of the later API. P9.2 defines the public initialization error surface.
  - **O. Unsafe code is localized.** Every `unsafe` declaration lives under `Interop/` and is preceded by a `// UNSAFE:` justification: the bytes-view record (a raw `const uint8_t *`), the records with inline arrays (fixed buffers), and the function table (unmanaged function pointers and their casts). Nothing else is unsafe.
  - **P. No protocol or cryptography in C#.** No frame building or parsing, hashing, MAC, SAS, request ID, transcript, deadline, opportunity accounting, or START limiting; no networking, thread, task, or timer. The native Rust core stays the only protocol implementation, and no status is a trust verdict.
  - **Q. Source of the binding.** The C# ABI definition derives from the frozen header and manifest only, never from the Dart generated bindings, and depends on nothing in `dart/`.
  - **R. Platform scope.** Windows (x64) is the only pairing-networking platform, as P7 defines. On Linux the same ABI v1 library is loaded in CI only to verify the version and exports; that is not Linux pairing support.
- **Why:** an explicit absolute path with no search keeps the one-image decision with the application and makes the loaded file auditable; function pointers resolved by exact name give one exact, private table instead of runtime-generated marshalling stubs; separating pre-load from post-load failures follows P7-D-002 exactly (before an image exists nothing needs undoing; after it exists nothing can be undone); checking every constant, record, and signature against the header and the manifest makes drift a test failure instead of a silent incompatibility.
- **Unchanged:** every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision; the frozen protocol candidate.
- **Status:** decided by the owner for P9.1, 2026-10-04; implemented in `dotnet/` (P9.1).

## P9-D-002 — .NET Lifecycle Ownership, Public Errors, and Fail-Closed State

- **Inputs:** the seven frozen lifecycle exports and their exact semantics in [`sas_pairing.h`](../../core/include/sas_pairing.h) and [ABI contract §5](../p7-native-abi/abi-contract.md#5-runtime-lifecycle), [§6](../p7-native-abi/abi-contract.md#6-fatal-semantics), [§15](../p7-native-abi/abi-contract.md#15-authorities), and [§16](../p7-native-abi/abi-contract.md#16-hosting-contexts), rechecked against `core/src/abi` for P9.2: `sas_pairing_runtime_create` creates the one runtime of the process (`ALREADY_INITIALIZED` while one is active, never replaced; no platform gate); `sas_pairing_runtime_destroy` removes the runtime from its slot first and then destroys its hosts and releases its authorities (cleanup, allowed in the fatal state, never clears it); `sas_pairing_authority_register` copies `scope_len` bytes (not a C string; `NULL` only with length 0, which the core answers with `INVALID_SCOPE`; on non-Windows the OS ownership lease fails closed with `UNSUPPORTED_PLATFORM`); `sas_pairing_authority_release` destroys every host of the authority, then removes its handle, then runs the core release, and the handle and its hosts are consumed whatever is returned (for example `OWNERSHIP_UNCERTAIN`), with process-session accounting never reset; `sas_pairing_authority_status` reports `READY` with 1–10, or `BUSY` or `EXHAUSTED` with 0; `sas_pairing_host_create` is accounting neutral and does no networking; `sas_pairing_host_destroy` invalidates the host handle whatever is returned. A caught panic makes the process permanently fatal: the four creates and the status query (normal) then return `SAS_PAIRING_FATAL` without entering the core, while destroy, release, and host destroy (cleanup) still work. The P9-D-001 loader, which this decision builds on unchanged. The P8 Dart lifecycle ([P8-D-002](../p8-dart-package/decisions.md#p8-d-002--dart-lifecycle-ownership-and-fail-closed-state)) as reference evidence for wrapper semantics, not for C# surface syntax.
- **Decision (owner-selected in the P9.2 task):**
  - **A. Public types.** P9.2 introduces exactly ten public types in namespace `SasPairing`: `SasPairingRuntime`, `SasPairingAuthority`, `SasPairingHost` (sealed classes, `IDisposable`), `SasPairingInitializationFailure`, `SasPairingInitializationException`, `SasPairingStatus`, `SasPairingNativeException`, `SasPairingContractException`, `SasPairingAuthorityState`, and the immutable `readonly record struct SasPairingAuthorityStatus(State, RemainingOpportunities)`. No raw handle, pointer, function pointer, native record, `NativeAbiV1`, `AbiV1FunctionTable`, loader, `NativeLibrary` handle, `NativeInitializationException`, or lifecycle service is public, now or as a member type.
  - **B. Lifecycle convention.** `IDisposable.Dispose()` is the one deterministic cleanup convention, with `bool IsDisposed { get; }` on all three wrappers. There is no `Close`, no finalizer, no `SafeHandle`, and no `CriticalFinalizerObject`: these handles take part in explicit parent-to-child native cascades that a per-handle release object would duplicate or reorder. An undisposed wrapper keeps its native object until its parent is disposed or the process exits.
  - **C. Runtime factory.** `SasPairingRuntime.Create(string nativeLibraryPath)` (synchronous; a null path is `ArgumentNullException`) initializes the one P9.1 process loader (no discovery or default resolution; once loaded, later paths are ignored), translates a loader failure, obtains the one process context, admits a normal operation, calls `sas_pairing_runtime_create`, and requires `OK` and a non-zero handle. A second `Create` while a runtime is active is answered by the native library (`AlreadyInitialized`); the active runtime is never returned or aliased. Loader idempotence is not runtime creation.
  - **D. Initialization failures.** `SasPairingInitializationFailure` has exactly the seven P9.1 loader categories (`UnsupportedPointerWidth`, `InvalidLibraryPath`, `OpenFailed`, `MissingSymbol`, `BindingFailed`, `AbiVersionQueryFailed`, `AbiVersionMismatch`). `SasPairingInitializationException` has `Failure` and `ProcessRestartRequired` (false for the three pre-load categories, true for the four post-load ones). The private-to-public translation is one exhaustive `switch` by name (no integer index, `Enum.Parse`, reflection, or default-to-other); a future internal category fails loudly until it is given a public meaning, and the tests enumerate every category. The message text is preserved, but the private `NativeInitializationException` is never the thrown type and never the `InnerException`. No native status is invented for a loader failure.
  - **E. Native statuses.** `SasPairingStatus : int` has the 48 frozen statuses with exactly their native values, in idiomatic PascalCase (`Ok = 0` … `ConnectionEnded = 405`, `Fatal = 900`). `SasPairingNativeException` has `Operation` (the public operation), `StatusCode` (the exact `int`, known or not), `KnownStatus` (null for a value the enum does not name: an unknown non-zero status is a failure, never success, and never blindly cast), and `ProcessRestartRequired` (true only for 900; unknown is not fatal). Statuses are operation outcomes: no property or message classifies a peer as trusted, malicious, attacking, or compromised.
  - **F. Contract violations.** An `OK` whose outputs break the frozen contract (a zero create handle; an authority state other than `READY` 1–10, `BUSY` 0, or `EXHAUSTED` 0) throws `SasPairingContractException` (`Operation`, `ProcessRestartRequired` always true) and latches a process contract violation. No wrapper is constructed from it.
  - **G. Use after dispose.** Every operation on a disposed wrapper throws the idiomatic `ObjectDisposedException` locally, without a native call; no synthetic native status is used.
  - **H. Process context.** One internal `NativeProcessContext` per process sits below every runtime. It holds the one verified binding and the lifecycle-native service over it, and two latches that are never reset: native `FATAL` observed and wrapper contract violation observed. Production obtains it from one static `NativeProcessContextSource` over `NativeAbiV1Loader.Process`: no second image, alternate loader, or loader reset. Disposing a runtime and creating another reuses the same context, binding, and latches. Tests construct their own contexts and sources over fake lifecycle services and fake platforms; there is no `ResetForTesting`.
  - **I. Normal and cleanup operations.** Normal: runtime create, authority register, authority status, host create. Cleanup: runtime destroy, authority release, host destroy. This is the native fatal classification of ABI contract §6. A normal operation is admitted in this order: (1) the object-local disposed check (`ObjectDisposedException`); (2) the contract latch (`SasPairingContractException`); (3) the fatal latch (`SasPairingNativeException` with `StatusCode` 900, `KnownStatus` `Fatal`, `ProcessRestartRequired` true); (4) the native call. Steps 1–3 make no native call. Cleanup is never admission-checked: an undisposed wrapper always makes its one cleanup call, also after either latch.
  - **J. Native fatal.** Whenever any lifecycle export returns 900, normal or cleanup, the fatal latch is set before the exception is thrown. There is no reset, clear, recover, reload, re-initialize, or alternate-library operation; runtime disposal and re-creation do not clear it (a later `Create` fails locally with no `runtime_create` and no load). Only an OS process restart recovers.
  - **K. Lifecycle-native service.** One internal `INativeLifecycleApi` with exactly seven methods, one per lifecycle export, returning raw statuses and handles and interpreting nothing; production `FfiNativeLifecycleApi` calls the P9.1 function table. All of its pointer code (stack-local output slots passed for the one synchronous call, the scope pinned for the one call) stays under `Interop/` behind a `// UNSAFE:` justification; no public wrapper is `unsafe`. No output pointer escapes a call, and no native allocation exists.
  - **L. Authority scope.** `RegisterAuthority(ReadOnlySpan<byte> scope)`: arbitrary binary, passed as the exact span bytes and `scope.Length`; an empty span passes a null pointer and length 0 and the native core answers `InvalidScope`. No string, encoding, terminator, copy into text, or duplicated scope validation; the pointer is not retained.
  - **M. Ownership graph.** Runtime → Authority → Host, by private parent references and child sets. Native parent cleanup performs the real cascade, so the wrapper makes exactly one cleanup call per `Dispose`: `Host.Dispose` → one `host_destroy`; `Authority.Dispose` → one `authority_release` and no `host_destroy`; `Runtime.Dispose` → one `runtime_destroy` and no release or destroy of any descendant. After the native attempt, whatever its status, the object is disposed, every descendant is marked disposed locally, the child sets are cleared, and the object is removed from its parent; then a non-zero status is thrown as `SasPairingNativeException`. A later `Dispose` of the object or of a cascaded child makes no native call and throws nothing. A cleanup failure is consuming: never retried.
  - **N. Authority status.** `GetStatus()` validates one native snapshot: `READY` requires 1 ≤ remaining ≤ 10 (the frozen core maximum, a private constant, not configurable), `BUSY` and `EXHAUSTED` require 0; anything else (including state `INVALID`, an unknown state, `READY` 0, `READY` 11, `READY` `uint.MaxValue`) is a contract violation. The wrapper keeps no previous count, expected decrement, budget, or limiter: snapshots `READY 1`, `READY 10`, `READY 4` in that order are each accepted; the native core is the only accounting authority.
  - **O. Identity and leakage.** Wrappers use reference identity (no `Equals` or `GetHashCode` over a handle, scope, or parent). No public `Handle`, `NativeHandle`, or `RawHandle`; no handle or scope byte in `ToString`, an exception message, or library logging (the library logs nothing).
  - **P. Concurrency.** Calls on one runtime and its authorities and hosts are serialized by one lock of that object tree, so concurrent `Dispose` calls make one native call. Everything is synchronous: no `Task`, `ValueTask`, `async`, thread, timer, channel, or background worker.
  - **Q. Runtime is not a security reset.** Destroying and re-creating a runtime reuses the loaded image and the process context and resets no authority opportunity accounting, START limiting, or other same-process security state ([P6-D-002](../p6-remediation/decisions.md#p6-d-002--f-003-owner-session-policy)), and no latch. It is never described as a fresh security session; only an OS process restart is.
  - **R. Scope of P9.2.** No listener, socket, network drive, event, connection, run, ceremony control, SAS presentation, result, Bootstrap, protocol, or cryptography, and no placeholder public type for any of them; P9.3–P9.5 own them. Linux: runtime creation works and authority registration fails closed with `UnsupportedPlatform`; that is not Linux pairing support.
- **Why:** `IDisposable` is the idiomatic, analyzable deterministic-cleanup contract of .NET, and a throwing first `Dispose` is the only honest way to surface a native cleanup failure that has nevertheless consumed the handle; mirroring the native cascade locally (one native call, local invalidation of descendants) keeps the managed graph exactly as valid as the native one and never issues a cleanup call the native library already performed; latching both native `FATAL` and impossible success outputs process-wide, below every runtime, is the fail-closed reading of P7-D-001 and P6-D-004, while leaving cleanup open matches the native fatal classification; keeping the loader exception private and translating it exhaustively gives consumers one stable public error type per class of failure without committing to internal structure.
- **Unchanged:** P9-D-001 and the P9.1 loader, binding, and layouts; every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision.
- **Status:** decided by the owner for P9.2, 2026-10-04; implemented in `dotnet/` (P9.2).

## P9-D-003 — .NET Windows Listener, Cooperative Drive, Event, and Connection Ownership

- **Inputs:** the five frozen network exports and their exact semantics in [`sas_pairing.h`](../../core/include/sas_pairing.h), [ABI contract §17](../p7-native-abi/abi-contract.md#17-windows-listener-ownership), [§18](../p7-native-abi/abi-contract.md#18-network-drive-connections-runs-and-events), [§19.1](../p7-native-abi/abi-contract.md#191-delivery-and-lifetime), and [§20.13](../p7-native-abi/abi-contract.md#2013-untracked-runs-wrapper-handoff) ([P7-D-006](../p7-native-abi/decisions.md#p7-d-006--windows-listener-ownership-and-responder-configuration) to [P7-D-010](../p7-native-abi/decisions.md#p7-d-010--pairingresult-ownership-and-foreign-access), [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff)), rechecked against `core/src/abi` (`listener.rs`, `network.rs`) for P9.3: attach adopts the socket by writing `SAS_PAIRING_SOCKET_INVALID` to the in/out slot only after its pre-adoption checks (structure, platform, `Bootstrap::new`, fatal, handles, already attached) and then answers `OK`, `LISTENER_SETUP_FAILED`, or `FATAL`, with the library closing the socket in every adopted case; detach is idempotent cleanup that keeps the host; a drive makes one bounded owner-loop step (at most one readiness wait of at most 250 ms) and a recheck one deadline sweep, both reporting at most 17 events (`SAS_PAIRING_MAX_DRIVE_EVENTS`); the drive's `out_failure` is only ever `OK`, `NETWORK_POLL_FAILED`, `OWNERSHIP_UNCERTAIN` (failed closed during the call), `OWNER_LOOP_CLOSED` (already failed closed; nothing driven, no event), or `FATAL` (`owner_failure_status` and `convert` in `network.rs`); a connection step whose adapter reported no event and only a result or a retained frame has step kind `NONE`; connection close is cleanup, invalidates the connection and its runs first, and answers `OWNERSHIP_UNCERTAIN` when the loop failed closed; results are runtime storage, survive connection close, detach, host destroy, authority release, and owner-loop failure, and end only with result destroy or runtime destroy. The .NET 10 sources of `System.Net.Sockets` (`Socket.Dispose(bool)`, `SafeSocketHandle.CloseAsIs` and `ReleaseHandle`, `Socket.DuplicateAndClose`, `Socket(SocketInformation)`), reviewed for the socket handoff and probed on .NET 10.0.12. The P8 Dart network wrapper ([P8-D-003](../p8-dart-package/decisions.md#p8-d-003--dart-windows-listener-cooperative-drive-and-connection-lifetime)) as reference evidence for wrapper semantics, not for C# surface syntax.
- **Source-review finding that shapes the socket handoff.** Invalidating the caller's own `Socket.SafeHandle` with `SafeHandle.SetHandleAsInvalid()` does prevent the managed close, but a later `Socket.Dispose()` then never returns: `Socket.Dispose(true)` calls `SafeSocketHandle.CloseAsIs`, which takes ownership of the close and spins until `ReleaseHandle` has run, and `ReleaseHandle` never runs for a handle marked invalid (probed: `Dispose` of an invalidated listening `Socket` did not return). No public .NET API lets a `Socket` give up its OS handle without closing it, and P9-D-001 forbids a WinSock P/Invoke. The descriptor native adopts must therefore never be one that a caller-held `Socket` object owns. `Socket.DuplicateAndClose(Environment.ProcessId)` plus `new Socket(SocketInformation)` (public, Windows-only) produce a second descriptor of the same listening socket in this process and close the caller's descriptor through .NET's own normal close (probed: the duplicate keeps listening and accepts after the original is closed). Only that package-owned handoff `Socket` is ever offered to native, only its `SafeSocketHandle` is invalidated, and it is never disposed afterwards, so neither a double close nor a hang is possible. This replaces the task's literal "invalidate the caller's `SafeSocketHandle`" mechanism, as the task's item 20 provides when source review proves a different .NET-safe design necessary.
- **Decision (owner-selected in the P9.3 task; A–V are the task's frozen points, W–Z the consequences of the source review):**
  - **A. Bootstrap.** `SasPairingBootstrap` is an immutable binary input: the constructor `(ReadOnlySpan<byte> applicationIdentity, ReadOnlySpan<byte> keyAlgorithm, ReadOnlySpan<byte> publicKey, ReadOnlySpan<byte> sharedContext)` copies all four spans; the four properties are `ReadOnlySpan<byte>` views of package-owned copies (no `byte[]`, `Memory<byte>`, or writable segment is exposed). No string constructor, encoding, terminator, or NUL semantics.
  - **B. One validator.** The native core (`Bootstrap::new`) is the only Bootstrap validator; C# checks no alphabet, bound, frame size, application, or peer rule. A refusal is `SasPairingStatus.InvalidBootstrap` from attach.
  - **C. Caller listener.** The application supplies an already-bound, already-listening Windows `System.Net.Sockets.Socket`. Trusted caller precondition (not checkable): a valid Windows socket, bound, listening, owned exclusively by the caller, never used for asynchronous operations, and not used or closed concurrently. The package never binds, listens, chooses an address, interface, port, or backlog, configures a firewall, or discovers peers, and offers no helper that does.
  - **D. One-use handoff token.** `SasPairingWindowsListenerSocket.FromSocket(Socket)` converts the socket into the token; on any platform other than Windows it throws `PlatformNotSupportedException` before touching the socket. The token's only state property is `bool IsTransferred`.
  - **E. Ownership before adoption.** From `FromSocket` until native adoption the socket belongs to the caller **through the token** (the token's package-owned handoff descriptor; see W). A pre-adoption attach failure (`InvalidArgument`, `UnsupportedPlatform`, `InvalidBootstrap`, or `Fatal`, `InvalidHandle`, or `ListenerAlreadyAttached` with the slot unchanged) leaves `IsTransferred` false, closes nothing, invalidates nothing, and the token may be attached again.
  - **F. Adoption.** When the slot reads `SAS_PAIRING_SOCKET_INVALID` after the call, native owns the socket: before any status is processed or thrown, the token becomes transferred, the handoff descriptor's `SafeSocketHandle` is invalidated with `SetHandleAsInvalid()` (never closed), and the token drops its last reference to the handoff `Socket`, which is never disposed. This applies to `OK`, `ListenerSetupFailed`, and `Fatal` after adoption.
  - **G. No raw handle.** No `SOCKET` value, `nint`, `nuint`, `IntPtr`, `SafeSocketHandle`, or `Socket` can be read from the token or from any public member.
  - **H. Attach is normal work.** Order under the runtime lock: (1) host disposed check (`ObjectDisposedException`); (2) the token's single-attempt gate; (3) `AdmitNormal` (contract latch, then fatal latch); (4) one native attach; (5) the slot is inspected and the token updated; (6) the slot transition is validated; (7) the status is processed; (8) on `OK` the host becomes `Attached`. Attach drives nothing, accepts nothing, and creates no connection, event, or ceremony.
  - **I. Cleanup.** `DetachListener()` and `SasPairingConnection.Dispose()` are cleanup: never admission-checked, allowed after native `FATAL` and after a wrapper contract violation.
  - **J. One bounded drive.** `SasPairingHost.Drive()` makes exactly one `sas_pairing_host_drive`: no retry, loop, or scheduling. It may wait once for up to about 250 ms, so it should not be called on a UI thread, and calling it in a tight loop without a scheduling policy is a misuse (persistent readiness can return at once).
  - **K. One recheck.** `RecheckAfterResume()` makes exactly one `sas_pairing_host_recheck_after_resume`, for trusted outer code that observed an OS resume; the package subscribes to no power event, WMI, callback, or timer.
  - **L. No background driver.** No `async`, `Task`, `ValueTask`, timer, thread, thread-pool item, channel, callback, `IAsyncEnumerable`, or loop that drives.
  - **M. Two statuses.** The function status and `out_failure` are different: a non-zero function status returns no batch and is thrown through `ThrowIfFailed` (`FATAL` latches); by itself it changes no network state (for example `ListenerNotAttached`, `HandlesExhausted`, `UnsupportedPlatform`, `InvalidHandle`).
  - **N. Events first.** On `OK`, every one of the `out_count` records is mapped in native order before `out_failure` takes effect; a non-zero `out_failure` never discards the batch. Then: `FATAL` is latched without throwing; every remaining connection of the host is disposed locally and every run reference invalidated; the host becomes `FailedClosed`; the batch is returned with `Failure`. Allowed `out_failure` values are `NetworkPollFailed`, `OwnershipUncertain`, `OwnerLoopClosed` (with zero events), and `Fatal`; an unknown non-zero value is preserved and fails the host closed the same way; a different known status (for example `InvalidHandle`) is impossible in ABI v1 and is a contract violation, raised after the events were mapped. The package never fabricates a later native status: after `FailedClosed` a further `Drive()` still makes its native call.
  - **O. One connection object.** One exact native connection handle maps to one `SasPairingConnection` (`IDisposable`, `IsDisposed`), stored in its host's private map under the runtime lock; every later event of that handle carries the same object. A second `ConnectionAccepted` of a live handle, and a step or closed event of a handle the host does not hold, are contract violations; no wrapper is manufactured.
  - **P. Connection identity.** A connection is never a socket, request ID, peer identity, or trust identity, and exposes none.
  - **Q. Runs internal.** Run handles stay package-internal until P9.4: each connection keeps exact `NativeRunRef` objects keyed by the native run handle (the same handle is the same reference), with the request ID as metadata only; a new handle under a reused request ID is a new reference and never retargets an old one; a visible ending (an inbound event without a run, other than `START_DUPLICATE` or `RUN_UNTRACKED`; a deadline with a request ID; a result) invalidates the references under that request ID; an invisible ending may leave a stale reference until a later local action, the connection's end, or a network teardown.
  - **R. Results internal and runtime-owned.** Each non-zero event result is retained once in the runtime's internal result store; a handle seen before (live or invalidated) is a contract violation. Results are not owned by a connection, host, or authority: they survive connection close, detach, owner-loop failure, host and authority disposal, and a contract violation later in the same batch; only runtime disposal invalidates them. P9.3 calls no `result_destroy` and reads no result; the public event says only `HasResult`. P9.5 owns the public result surface.
  - **S. `RUN_UNTRACKED`.** Such an event has `RunUntracked` true and `HasTrackedRun` false; no run reference is created, evicted, or reused. `ShouldDisposeConnection` is true exactly when `RunUntracked` is set and the event names a connection: after processing the whole batch the consumer SHOULD call `evt.Connection?.Dispose()`. The drive never disposes it itself (every event must be delivered first, cleanup can fail, and the native library leaves the policy to the wrapper).
  - **T. Four network states.** `SasPairingHostNetworkState`: `Detached` (initial; after detach, after an adopted attach failure, after host or parent disposal), `Attached` (after attach `OK`), `ListenerDisabled` (a `ListenerDisabled` event: no new accepts, existing connections continue and stay valid), `FailedClosed` (a non-zero `out_failure`, or `OwnershipUncertain` from a connection close: every connection invalid). They are never collapsed.
  - **U. Metadata only.** Event kinds, step kinds, protocol events, reasons, deadline kinds, cancel states, cancel reasons, `WritePending`, and statuses are operational metadata copied from native, never trust verdicts. The public enums carry exactly the frozen numeric values (native `SAS_PAIRING_EVENT_INVALID` is not a public event kind; `SasPairingStepKind.None` is a legitimate step kind). The record checks are structural only: known enum values, only the two frozen flag bits, `reserved == 0`, `request_id_len <= 64` with zero bytes past it, connection presence by kind, no run, result, or flag on a non-step event, never both a run and a result, no run with `RUN_UNTRACKED`. Request IDs are exposed as the exact 0–64 bytes (`ReadOnlySpan<byte>`), never text. C# rebuilds no state machine and judges no sequence.
  - **V. Serialization.** P9-D-002's one lock per runtime tree stays: attach, detach, drive, recheck, and connection close are serialized with the lifecycle calls, and a drive holds the lock for its bounded wait. This is an intentional primitive-API trade-off for P9.
  - **W. Package-owned handoff descriptor.** `FromSocket` calls `Socket.DuplicateAndClose(Environment.ProcessId)` and `new Socket(SocketInformation)`: the caller's `Socket` object is closed by .NET at that moment (disposing it again later is a harmless no-op) and the token owns the duplicate descriptor of the same listening socket. Only that descriptor is offered to native, and only its `SafeSocketHandle` is invalidated after adoption; the caller's `Socket` never shares a descriptor with native, so no managed disposal of any object the caller holds can close the native-owned socket, and nothing can hang. A `Socket` that `DuplicateAndClose` refuses (for example one already disposed) throws from `FromSocket`.
  - **X. The token is `IDisposable`.** Because the token owns the handoff descriptor until adoption, it implements `IDisposable` (no finalizer): `Dispose()` before transfer closes the handoff descriptor through .NET; after transfer it does nothing (native owns the socket); a later attach of a disposed token fails locally with `ObjectDisposedException` and no native call. A `Dispose()` that races an in-flight attach is deferred to the end of that attempt and closes the descriptor only if native did not adopt it. This departs from the task's item 20 ("no `IDisposable` normally"), as that item provides.
  - **Y. Single-attempt gate.** One token is offered to at most one native attach at a time: a concurrent second attempt fails locally with `InvalidOperationException` and makes no native call (no process reset exists). After a pre-adoption failure the token is reusable; after adoption, or after an impossible slot (Z), every later attach fails locally with `InvalidOperationException`.
  - **Z. Impossible slot.** The only valid post-call slot values are the offered socket and `SAS_PAIRING_SOCKET_INVALID`. Any other value latches a `SasPairingContractException`; because the caller can no longer know who owns the socket, the token is conservatively consumed exactly as on adoption (F) before the exception is thrown: a possible leak after an impossible ABI output is preferred to a double close of a socket native may own. `OK` with the socket still in the slot, `ListenerSetupFailed` with the socket still in the slot, and a pre-adoption status (`InvalidArgument`, `InvalidHandle`, `UnsupportedPlatform`, `InvalidBootstrap`, `ListenerAlreadyAttached`) with an empty slot are contract violations too; none marks the host `Attached`. After an adopted failure the host is `Detached`; before adoption its previous state is kept.
- **Detach, connection cleanup, and the parent cascade.**
  - `DetachListener()` is repeatable: every explicit call on a live host makes the native idempotent detach (after detach, after a failed attach, after `FATAL` or a contract violation), so detach, attach, detach works. In a `finally` path the host becomes `Detached`, every connection wrapper of it is disposed locally, and their run references are invalidated, whatever the status; then a non-zero status is thrown. No connection is closed individually, and the host, authority, and runtime stay valid (no accounting reset). Replacement is detach, then attach; there is no replace or rebind operation.
  - `SasPairingConnection.Dispose()`: the first call makes exactly one `sas_pairing_connection_close` (cleanup), then in a `finally` path the connection is disposed, removed from its host, and its runs invalidated; a non-zero status is then thrown once and never retried (`InvalidHandle`, `ListenerNotAttached`, `UnsupportedPlatform`, `Fatal`, unknown). `OwnershipUncertain` means the owner loop failed closed: every sibling connection is disposed locally (no native call) and the host becomes `FailedClosed` before the exact native exception is thrown. `Fatal` latches globally but does not dispose siblings, which remain available for explicit cleanup. A later `Dispose` makes no call and throws nothing. A `ConnectionClosed` event disposes the same object locally before the batch is returned, with no native call.
  - The P9-D-002 cascade keeps one native call per parent: `Host.Dispose` → one `host_destroy` (no detach, no connection close); `Authority.Dispose` → one `authority_release`; `Runtime.Dispose` → one `runtime_destroy`; in each case every descendant host becomes `Detached` and every connection is disposed locally. Runtime disposal also invalidates the internal result store.
- **Private network service.** One internal `INativeNetworkApi` with exactly five methods (attach, detach, drive, recheck, connection close), raw statuses and values only; production `FfiNativeNetworkApi` calls exactly those five fields of the one P9.1 function table and is built from the same binding as the lifecycle service in the one `NativeProcessContext` (no second library, loader, or context). Attach passes the offered socket in a stack-local in/out slot and returns the slot's value after the call. Bootstrap marshalling is one `Interop` path, reusable by P9.4: a field of length 0 is `data = NULL, len = 0`, any other field the exact pinned bytes and length, pinned for the one synchronous call only; `expected = null` passes a null view pointer. Drive and recheck always pass 17 stack-local zeroed `sas_pairing_event_t` records and a distinct `out_count` and `out_failure` (initialized to 0 and `OK`), never a size query, and copy every produced record into managed data before returning; more than 17 is a contract violation. No pointer escapes and nothing native is retained.
- **Why:** handing native a descriptor that no caller-held .NET object owns is the only public-API way to give native exclusive ownership without a double close or a hang, and it keeps the one-owner invariant of ABI contract §17.4 true in managed code; mapping every event before acting on `out_failure`, keeping one object per native connection, and mirroring the native invalidations locally (never the reverse) make the managed graph exactly as valid as the native one, as P8-D-003 established for Dart; keeping runs and results internal until P9.4 and P9.5 lets their public surfaces be designed over exact handles that are already retained correctly.
- **Unchanged:** P9-D-001 (no P/Invoke, explicit-path loader, private interop) and P9-D-002 (lifecycle, errors, latches, one lock per runtime tree); every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision.
- **Status:** decided by the owner for P9.3, 2026-10-04; implemented in `dotnet/` (P9.3).

## P9-D-004 — .NET Run Identity, Explicit Ceremony Control, and SAS Binding

- **Inputs:** the nine frozen trusted-local ceremony exports (`sas_pairing_connection_start_initiator`, `sas_pairing_run_authorize_exposure`, `sas_pairing_run_expose_key`, `sas_pairing_run_presentation`, `sas_pairing_run_approve_sas`, `sas_pairing_run_emit_bootstrap_mac`, `sas_pairing_run_reject_sas`, `sas_pairing_run_cancel_sas`, `sas_pairing_run_emit_initiator_finish`) and the two records `sas_pairing_action_t` and `sas_pairing_sas_presentation_t` in [`sas_pairing.h`](../../core/include/sas_pairing.h), [ABI contract §18.6](../p7-native-abi/abi-contract.md#186-run-handles) and [§20](../p7-native-abi/abi-contract.md#20-trusted-local-ceremony-control) ([P7-D-009](../p7-native-abi/decisions.md#p7-d-009--connection--run-reference-semantics), [P7-D-011](../p7-native-abi/decisions.md#p7-d-011--trusted-local-ceremony-action-abi), [P7-D-012](../p7-native-abi/decisions.md#p7-d-012--sas-presentation-identity-binding-and-local-action-statuses), [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff)), and the local-completion boundary of [P6-D-005](../p6-remediation/decisions.md#p6-d-005--local-completion-and-final-ack-deadline-boundary), rechecked against `core/src/abi/control.rs` and `mod.rs` for P9.4: every export zeroes its output record before any state check and fills it only on `OK`; the refusal order is structure, platform, Bootstrap (start only), fatal, handles, listener, connection and exact run, run cap and handle space (start only), then `WRITE_PENDING` (the connection retains a frame: nothing reached the core), then the core; a start succeeds only as `INITIATOR_STARTED` with a new run handle and the flag `WRITE_PENDING` (anything else is native `FATAL`) and never reports `DEADLINE`; an action on an existing run keeps the same handle while that exact run stays live (a different live run is native `FATAL`) and reports run `0` once the run is terminal; the action flag is set exactly when the action (or a deadline's timeout CANCEL) left a retained frame; `RUN_ENDED` removes the stale run handle; a ceremony refusal keeps the handle (the core alone knows whether it ended the run); `CONNECTION_ENDED` unbinds that connection and its runs; `OWNERSHIP_UNCERTAIN` and `OWNER_LOOP_CLOSED` clear every binding of the host; presentation is read-only, never returns `WRITE_PENDING`, and answers `available = 0` with every other byte zero or `available = 1` with exactly `NNNN NNNN NNNN` (a malformed display is native `FATAL`). The P9-D-003 network wrapper, which this decision builds on unchanged (including its accepted socket handoff, W and X). The P8 Dart ceremony wrapper ([P8-D-004](../p8-dart-package/decisions.md#p8-d-004--dart-run-identity-explicit-ceremony-control-and-sas-binding)) as reference evidence for wrapper semantics, not for C# surface syntax.
- **Decision (owner-selected in the P9.4 task; A–X are the task's frozen points):**
  - **A. One handle, one object.** One exact native run handle maps to at most one public `SasPairingRun`, held by its connection's exact-handle map; the wrapper is never recreated per event or per action.
  - **B. Not a request ID.** A run's identity is never its request ID. The request ID is routing metadata of the internal `NativeRunRef`, never a key and never a public run property (events already expose it).
  - **C. One reference.** The exact `NativeRunRef` of P9.3 is the reference behind the public run: `SasPairingEvent.Run` and `SasPairingLocalAction.Run` carry the same object for the same native handle.
  - **D. Unknown request ID.** `connection_start_initiator` returns no request ID, so a locally started run exists at once with an explicitly unknown request ID; nothing is invented, generated, or represented by empty bytes.
  - **E. Learned once.** The first drive event naming that exact run handle teaches its request ID. Before that, no request-ID retirement can match the run. On learning, the other references routed under that request ID are retired first (a live new run proves them ended), then this run is bound to it.
  - **F. Never changed.** A different request ID later reported for the same handle is a contract violation (`SasPairingContractException`, process latch).
  - **G. Reuse is a new run.** A new native run handle under a reused request ID is a new `SasPairingRun`, and the earlier known run under that request ID is ended; no object is retargeted.
  - **H. One call.** Every public ceremony method makes exactly one native ceremony export call.
  - **I. No chaining.** No ceremony method performs another step: `AuthorizeExposure` does not expose, `ApproveSas` does not emit BOOTSTRAP_MAC, `EmitBootstrapMac` does not emit INITIATOR_FINISH, and no helper chains them.
  - **J. No drive.** No ceremony method calls `Drive()` or `RecheckAfterResume()`.
  - **K. Status 205.** The native status `SasPairingStatus.WritePending` (205) means the requested action did NOT run: a `SasPairingNativeException`, no action returned, no run state changed, nothing driven or retried.
  - **L. Flag.** `SasPairingLocalAction.WritePending` means the action DID run and its frame (or a deadline's timeout CANCEL) is retained for a later drive.
  - **M. No write-pending state.** The wrapper keeps no authoritative write-pending state; the native library decides every refusal.
  - **N. Presentation always reaches native.** `Presentation()` is read-only and, on a run not known to have ended, always makes its native call, also while an outbound frame is retained.
  - **O. Exact identity.** MATCH, MISMATCH, and CANCEL name the exact 32-byte `ceremony_identity` returned by a presentation (`SasPairingCeremonyIdentity`).
  - **P. Native is authoritative.** The wrapper does not check that an identity came from the same run: it passes its exact 32 bytes, and a wrong or stale identity surfaces as native `CeremonyIdentityMismatch` (208). No synthetic status exists.
  - **Q. No raw SAS.** No raw SAS byte is public; a presentation exposes the 32-byte identity and the 14-character decimal display only.
  - **R. No final-ACK API.** The native library writes every frame and confirms the final ACK itself; no confirmation method exists under any name.
  - **S. Not disposable.** `SasPairingRun` is not `IDisposable` (ABI v1 has no run destroy), has no finalizer, and holds no `SafeHandle`.
  - **T. Known-ended runs refuse locally.** Every method of a run known to have ended throws `SasPairingRunEndedException` (`Operation`; no status code, no restart flag) before any latch admission or native call.
  - **U. The first RUN_ENDED is native.** When native returns `RunEnded` (204) for a run not known to have ended, the run becomes ended and its reference is removed, and the original `SasPairingNativeException` (204) is thrown; only later calls throw `SasPairingRunEndedException`.
  - **V. Invisible endings.** An ending native does not make visible (for example a ceremony refusal that ended the run) leaves `IsEnded` false until a later `RunEnded`, a visible event, or a teardown. `IsEnded` means "ending observed", never "definitely live".
  - **W. Operation outcomes.** Every ceremony status and local event is an operation outcome, never a trust verdict about the peer.
  - **X. Results deferred.** The PairingResult surface (read, copy, destroy) stays with P9.5; events keep `HasResult` only.
- **Admission order.** A run method, under the runtime lock: (1) the known-ended check; (2) `AdmitNormal` (contract latch, then fatal latch); (3) the one native call. A known-ended run therefore reports `SasPairingRunEndedException` even after the process became fatal or contract-latched. `SasPairingConnection.StartInitiator(local, expected = null)`: (1) the connection disposed check (`ObjectDisposedException`); (2) `AdmitNormal`; (3) the one native call; the Bootstraps go through the one P9.3 Bootstrap path. All nine operations are normal: after native `FATAL` or a contract violation they make no native call, while every cleanup operation still does.
- **Successful outcomes.** Every successful record must have `reserved == 0`, no flag bit other than `WRITE_PENDING`, a known local event (native `INVALID` 0 is not a public value; an unknown value is a contract violation), a known deadline kind that is not `None` exactly for `Deadline`, and an outcome the called method allows; anything else latches a contract violation before any run state changes:

  | Method | Event | Run | `WritePending` |
  |---|---|---|---|
  | `StartInitiator` | `InitiatorStarted` | a new non-zero handle not live in the host | true |
  | `AuthorizeExposure` | `ExposureAuthorized` | the same run | false |
  | `ExposeKey` | `KeyExposed` | the same run | true |
  | `ApproveSas` | `SasApproved` or `SasAlreadyApproved` | the same run | false |
  | `EmitBootstrapMac` | `BootstrapMacEmitted` / `BootstrapMacAlreadyEmitted` | the same run | true / false |
  | `RejectSas` | `SasRejected` | none (the run ends) | either |
  | `CancelSas` | `SasCancelled` | none (the run ends) | either |
  | `EmitInitiatorFinish` | `InitiatorFinishEmitted` / `InitiatorFinishAlreadyEmitted` | the same run | true / false |
  | any existing-run action | `Deadline` (deadline kind not `None`) | none (the run ends) | either |

  "The same run" means native `run` equals the target's exact handle; `0` or another handle is a contract violation, and the public run is never retargeted. A terminal outcome with a non-zero `run` is a contract violation. A start never reports `Deadline`.
- **Presentation.** `available = 0` requires every other byte (reserved, the 32 identity bytes, the 14 decimal bytes, the 2 tail bytes) to be zero and returns null; `available = 1` requires `reserved == 0`, a zero tail, and a decimal of exactly 14 ASCII bytes with spaces at positions 4 and 9 and `'0'`–`'9'` elsewhere, and returns an immutable `SasPairingSasPresentation` (`CeremonyIdentity`, `DecimalDisplay`); any other `available` value or byte is a contract violation. The decimal is display data only: it authenticates, approves, and trusts nothing, and the application or user owns the comparison policy; the package never compares displays and never approves. Naming: the task named the display property `Decimal`, but the enforced `latest-recommended` analyzers reject it (CA1720: an identifier that is a type name) and P9-D-001 B forbids suppressing a warning, so the property is `DecimalDisplay`, with exactly the specified meaning and type (`string`).
- **Ceremony identity.** `SasPairingCeremonyIdentity` is exactly 32 bytes copied from native, exposed as a read-only span of a package-owned copy, with value equality (`Equals`, `==`, `!=`) and a value hash; it has no public constructor. It binds a decision to one presented ceremony transcript and is not a request ID, run, connection, peer, authority, or trust identity, and not a secret.
- **Failure side effects (one handler).** For a non-zero status of any of the nine calls: `RunEnded` ends exactly the target run; `ConnectionEnded` disposes the connection locally, removes it from its host, and ends every run of it, with no `connection_close` call; `OwnershipUncertain` and `OwnerLoopClosed` fail the host closed (`FailedClosed`, every connection disposed, every run ended, no child cleanup call); `Fatal` latches the process (no run or connection is ended because of it; cleanup stays available); every other status (`WritePending`, `MissingAuthorization`, `Busy`, `Exhausted`, `CeremonyIdentityMismatch`, `NotLocallyApproved`, `NotInitiator`, any other refusal, or an unknown value) changes nothing. Then the exact status is thrown as `SasPairingNativeException`.
- **Ended runs.** A run becomes ended (its reference invalidated and removed from the live map, never retargeted) on a terminal local action, native `RunEnded`, a visible drive ending under its known request ID (including a result event), a replacement run under its known request ID, `ConnectionEnded`, connection disposal or `ConnectionClosed`, listener detach, an owner-loop failure, and host, authority, or runtime disposal. The ended `SasPairingRun` stays usable only for `IsEnded`. A run owns no connection, host, or result.
- **Private ceremony service.** One internal `INativeCeremonyApi` with exactly nine methods, raw statuses and raw copied records; production `FfiNativeCeremonyApi` calls exactly those nine fields of the one function table, built in `NativeProcessContext` from the same binding as the lifecycle and network services (no second loader, image, or context). Each action passes one zeroed, aligned stack-local `sas_pairing_action_t`, the presentation one zeroed stack-local `sas_pairing_sas_presentation_t`, and a decision the identity's 32 bytes pinned for the call; the record is copied into a private managed `NativeActionRecord` or `NativePresentationRecord` only on `OK`, and no output field is interpreted on any other status. No pointer escapes. The start reuses the one P9.3 Bootstrap pinning and view path, now shared by attach and start.
- **Why:** an exact-handle object identity is the only identity the ABI guarantees (P7-D-009), so drive events and local actions must resolve to it; one native call per method with no chaining keeps every security-relevant step a deliberate caller decision (P7-D-011, ABI contract §21 item 8); validating each successful record against the frozen per-method outcomes turns any drift into a fail-closed contract violation instead of a silently wrong state; applying exactly the lifetime effects native defines (and no guessed ones) keeps the managed graph as valid as the native one, as P8-D-004 established for Dart.
- **Unchanged:** P9-D-001, P9-D-002, and P9-D-003 (including W and X: the package-owned handoff descriptor and the `IDisposable` token); every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision; P6-D-005 (a result is local verified completion only).
- **Status:** decided by the owner for P9.4, 2026-10-04; implemented in `dotnet/` (P9.4).

## P9-D-005 — .NET PairingResult Ownership, Reads, and Immutable Snapshots

- **Inputs:** the three frozen result-data exports (`sas_pairing_result_info`, `sas_pairing_result_copy`, `sas_pairing_result_destroy`), the record `sas_pairing_result_info_t`, the role values `SAS_PAIRING_ROLE_INVALID` 0, `INITIATOR` 1, `RESPONDER` 2, and the field selectors `SAS_PAIRING_RESULT_FIELD_*` 1–4 in [`sas_pairing.h`](../../core/include/sas_pairing.h), [ABI contract §6](../p7-native-abi/abi-contract.md#6-fatal-semantics) and [§19](../p7-native-abi/abi-contract.md#19-results) ([P7-D-010](../p7-native-abi/decisions.md#p7-d-010--pairingresult-ownership-and-foreign-access), [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff)), and the local-completion boundary of [P6-D-005](../p6-remediation/decisions.md#p6-d-005--local-completion-and-final-ack-deadline-boundary), rechecked against `core/src/abi/result.rs`, `core/src/ceremony.rs` (`PairingResult`), and `core/src/protocol.rs` for P9.5: info, copy, and destroy run under the runtime slot through `Admission::Data` (allowed after fatal, never entering the core, creating nothing, resuming nothing, changing no accounting); info zeroes `*out_info` and fills it only on `OK`, copying the result's own fields (`peer_role` is the PEER's role and never `INVALID` for a real result); copy rejects bad pointers and an unknown field with `INVALID_ARGUMENT` (nothing written), otherwise sets `*out_required` to 0, then to the field's exact length once the result is found, answers `BUFFER_TOO_SMALL` with nothing copied when the capacity is smaller, and otherwise copies exactly that many bytes (never truncated, never NUL-terminated); destroy removes the handle first (invalid forever), then drops the immutable result; runtime destroy drops every result of the runtime; results survive connection close, listener detach, host destroy, authority release, owner-loop failure, and fatal. The P8 Dart result wrapper ([P8-D-005](../p8-dart-package/decisions.md#p8-d-005--dart-pairingresult-ownership-data-access-and-local-completion)) as reference evidence for wrapper semantics, not for C# surface syntax.
- **Variable-field bounds (source recheck, independent of the Dart wrapper).** Each bound is what the frozen core can ever put in a result; a length above it is impossible output, so it is an ABI contract violation, detected before any buffer is allocated:

  | Field | Bound | Source |
  |---|---|---|
  | Request ID | ≤ 64 bytes | `protocol.rs`: `bounded(request_id, 1, 64, "request_id")` on encode and on every decoded frame; `SAS_PAIRING_MAX_REQUEST_ID_LEN` = 64 in the header; profile §4 (1–64 bytes) |
  | Authenticated peer Bootstrap | ≤ 16,384 bytes | `protocol.rs`: `MAX_BOOTSTRAP_FRAME = 16_384`, enforced by `Bootstrap::new` (`encode_frame(…, MAX_BOOTSTRAP_FRAME)`) and `Bootstrap::decode`; the result keeps `peer_bootstrap.canonical_bytes()` unchanged; profile §4 (complete bootstrap frame at most 16,384 bytes) |
  | Authenticated shared context | ≤ 8,192 bytes | `protocol.rs`: `bounded(&self.shared_context, 0, 8192, "shared_context")` in `Bootstrap::validate`; the result keeps `peer_bootstrap.shared_context()`; profile §4 (0–8,192 bytes, may be empty) |
  | Profile identifier | ≤ 38 bytes | `ceremony.rs`: `PairingResult::new` always stores `protocol::PROFILE_ID`, the `&'static [u8]` constant `b"sas-pairing-vodozemac-profile-draft-01"` (38 bytes); no other profile identifier can reach a result of ABI v1 |

  The package adds no memory cap of its own: every allocation is bounded by these source-proven values (at most 24,678 bytes for one read). Lower bounds (for example a request ID of at least one byte) are not checked: the native core is the validator, and the wrapper refuses only lengths that cannot have been produced. `profile_version` is a `u16` in the core and is exposed exactly as the `uint32_t` native reports, with no compatibility check.
- **Decision (owner-selected in the P9.5 task; A–AL are the task's frozen points):**
  - **A. Local completion.** A result represents ONE endpoint's local verified ceremony completion.
  - **B. Not bilateral.** It is NOT bilateral completion.
  - **C. No peer claim.** It does not mean that the peer received the final message, holds its own result, or persisted anything, or that trust was established. Either endpoint may be the only result holder (P6-D-005).
  - **D. Runtime-owned.** A result belongs to its `SasPairingRuntime`.
  - **E. Not below.** It does not belong to a connection, run, host, or authority.
  - **F. Survival.** It survives connection close, listener detach, owner-loop failure, host disposal, authority disposal, and native `FATAL`.
  - **G. Two endings.** Only `SasPairingResult.Dispose()` or `SasPairingRuntime.Dispose()` ends its native lifetime.
  - **H. `IDisposable`.** `SasPairingResult` implements `IDisposable`.
  - **I. No finalizer.** There is no result finalizer and no `SafeHandle`: the runtime's native cascade stays explicit.
  - **J. One destroy.** The first `Dispose` makes exactly one `sas_pairing_result_destroy`.
  - **K. Consuming.** The result becomes disposed whatever the native destroy status; a failure is then thrown once as `SasPairingNativeException` and never retried.
  - **L. Idempotent.** A second `Dispose` makes no native call and throws nothing.
  - **M. No child destroys.** `SasPairingRuntime.Dispose()` does not call `result_destroy` for any child result.
  - **N. Native cascade.** Native `runtime_destroy` owns that cascade; the runtime's managed cleanup only marks every live result disposed locally.
  - **O. Data access.** `Read()` is data access, not a normal pairing operation.
  - **P. Read after fatal.** `Read()` stays allowed after native `FATAL`.
  - **Q. No read after a contract violation.** `Read()` is refused locally (`SasPairingContractException`, no native call) after a wrapper contract violation: successful native output is no longer trusted.
  - **R. Cleanup always.** `Dispose()` stays allowed after native `FATAL` and after a wrapper contract violation.
  - **S. One coherent snapshot.** A read is exactly one `result_info` and one `result_copy` of each of the four fields.
  - **T. No negotiation.** There is no buffer-negotiation loop, size query, or retry.
  - **U. Info lengths are authoritative** for that immutable result.
  - **V. `BUFFER_TOO_SMALL` is a contract violation** when copying at the length info reported.
  - **W. Required mismatch.** A copy reporting a required length other than the info length is a contract violation.
  - **X. Byte-count mismatch.** A successful copy returning a byte count other than the info length is a contract violation.
  - **Y. Nothing partial.** A failed read returns no `SasPairingResultData`.
  - **Z. Failure keeps the result open.** A failed read does not dispose the result.
  - **AA. Detached snapshot.** A returned `SasPairingResultData` is detached managed data and stays usable after `Result.Dispose()` and `Runtime.Dispose()`.
  - **AB. Binary.** Byte fields are exact binary bytes.
  - **AC. No text.** No UTF-8, string, or NUL conversion is performed.
  - **AD. Unparsed Bootstrap.** `AuthenticatedPeerBootstrap` is the exact canonical frame; the package does not parse it.
  - **AE. Peer role.** `PeerRole` is the PEER's ceremony role, never this endpoint's.
  - **AF. One identity type.** `CeremonyIdentity` is the existing P9-D-004 `SasPairingCeremonyIdentity`, built through its internal constructor; no new public constructor and no second identity type.
  - **AG. One object per handle.** One exact native result handle maps to one `SasPairingResult`.
  - **AH. Never reused.** A native result handle is never reused (ABI contract §4).
  - **AI. Duplicate delivery.** A second delivery of a result handle, also after that result was disposed, is a contract violation; the delivered-handle history lives as long as the runtime object.
  - **AJ. Event integration.** `SasPairingEvent.Result` exposes that public result.
  - **AK. `HasResult`** is exactly `Result is not null`.
  - **AL. No automatic trust.** No trust decision, persistence, or enrollment happens anywhere in the package.
- **Public surface.** `SasPairingResult` (sealed, `IDisposable`; `IsDisposed`, `Read()`, `Dispose()`; reference identity, no `Equals` or `GetHashCode` override, no handle property), `SasPairingResultData` (sealed, no public constructor; `CeremonyIdentity`, `PeerRole`, `ProfileVersion` as `uint`, and `RequestId`, `AuthenticatedPeerBootstrap`, `AuthenticatedSharedContext`, `ProfileIdentifier` as `ReadOnlySpan<byte>` views of package-owned copies; no `byte[]`, `Memory<byte>`, or segment is exposed), `SasPairingPeerRole` (`Initiator = 1`, `Responder = 2`; no `Invalid` or `Unknown`), and `SasPairingEvent.Result`. The field selectors, the info record, the result handle, the result service, and the result store stay internal. There is no result polling, lookup, or enumeration (`GetResults`, `PollResults`, `FindResult`, by request ID or by handle): the only source of a new result is the drive event that delivered it.
- **Data admission.** `NativeProcessContext.AdmitData(operation)` refuses only after a wrapper contract violation (`SasPairingContractException`); unlike `AdmitNormal` it never refuses because native `FATAL` was observed. `AdmitNormal` is unchanged. `Read()` order under the runtime lock: (1) the result's disposed check (`ObjectDisposedException`, covering explicit disposal and the runtime cascade); (2) `AdmitData`; (3) one `result_info`; (4) the info validated: exactly 32 identity bytes, peer role 1 or 2 (0, 3, `uint.MaxValue`, or any other value is a contract violation), every length within its source-proven bound; (5) one `result_copy` per field, in the order request ID, peer Bootstrap, shared context, profile identifier, each at exactly the info length; (6) each copy validated (`BUFFER_TOO_SMALL` at that capacity, any other required length, or another byte count is a contract violation); (7) only then is the immutable snapshot built, from defensive copies. A non-zero info or copy status is thrown as `SasPairingNativeException` (`FATAL` latches the process, and a later `Read()` is still admitted); nothing is returned and the result stays open. Each read is a fresh complete native read; nothing is cached.
- **Dispose.** `SasPairingResult.Dispose()` under the runtime lock: an already disposed result returns at once; otherwise the result is marked disposed and removed from the runtime's live set first (consuming), then exactly one `result_destroy` is made, never admission-checked; a non-zero status is then thrown (`FATAL` latches). `SasPairingRuntime.Dispose()` keeps exactly one `runtime_destroy` and, in its `finally` path, marks every live result disposed and clears the live set; a later `Dispose` of such a result makes no native call (no `INVALID_HANDLE` is manufactured), and its `Read()` is `ObjectDisposedException`.
- **Retention.** A drive retains each new result handle at the runtime before the rest of its batch is mapped, so a contract violation later in the same batch never loses it: the result stays in the runtime's live set (no public batch is returned and no hidden destroy is attempted), and the native runtime cascade still drops it.
- **Private result service.** One internal `INativeResultApi` with exactly three methods (`ResultInfo`, `ResultCopy`, `ResultDestroy`), raw statuses and raw copied values; production `FfiNativeResultApi` calls exactly those three fields of the one function table and is built in `NativeProcessContext` from the same binding as the lifecycle, network, and ceremony services (no second loader, image, or context). Info passes one zeroed, aligned stack `sas_pairing_result_info_t` and copies it into a private `NativeResultInfoRecord` only on `OK`. Copy passes the field selector, a buffer of exactly the requested capacity pinned for the one call (`NULL` with capacity 0, never a terminator byte), and a writable stack `size_t` slot; on `OK` it returns at most the capacity bytes it wrote, on any other status no bytes (the required value is kept for diagnosis). No pointer escapes and nothing native is retained.
- **Concurrency.** Read and dispose run under the existing one lock of the runtime tree (P9-D-002 P): no new lock and no asynchronous API (`ReadAsync`, `DisposeAsync`, `IAsyncDisposable`, `Task`, `ValueTask`).
- **Why:** owning a result at the runtime keeps a completion that already happened independent of every transport and frontend lifetime, as P7-D-010 does natively; reading a frozen immutable result at its reported lengths makes any drift between info and copy a fail-closed contract violation rather than a negotiation; admitting data access after fatal but not after a wrapper contract violation follows the native fatal classification while refusing to trust output the wrapper has already seen break the contract; detached snapshots let applications apply their own policy after every native object is gone, as P8-D-005 established for Dart.
- **Unchanged:** P9-D-001 to P9-D-004 (including the accepted `DecimalDisplay` name and the P9-D-003 W/X socket handoff); every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision; P6-D-005.
- **Status:** decided by the owner for P9.5, 2026-10-04; implemented in `dotnet/` (P9.5).
