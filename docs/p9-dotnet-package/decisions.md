## P9-D-001 — .NET ABI v1 Binding and Loader Architecture

- **Inputs:** the frozen ABI v1 surface (version 1, 25 exports, 48 statuses, 84 namespace values, 11 scalar constants, 6 records; [manifest](../p7-native-abi/abi-v1-manifest.md), [`sas_pairing.h`](../../core/include/sas_pairing.h)); the loader invariant of [P7-D-002](../p7-native-abi/decisions.md#p7-d-002--native-library-residency-and-loader-lifetime) and [ABI contract §14](../p7-native-abi/abi-contract.md#14-native-library-loading-and-residency) (one native image per OS process, resident until exit, no unload, reload, or alternate copy, process restart as the only recovery from `SAS_PAIRING_FATAL`); the wrapper handoff of [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff) item 13 and [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9), which names `NativeLibrary.Free` explicitly for P9; the P8 Dart implementation ([P8-D-001](../p8-dart-package/decisions.md#p8-d-001--dart-native-binding-and-loader-architecture)) as reference evidence for wrapper semantics, not as a source. .NET facts that shape the design: `NativeLibrary.Load(string)` loads a module by path and returns an OS handle, `NativeLibrary.TryGetExport` looks a symbol up without calling it, and only `NativeLibrary.Free` releases a handle (nothing frees it implicitly); `[DllImport]` / `[LibraryImport]` resolve a library name through the runtime's probing and the OS search order; `delegate* unmanaged[Cdecl]<...>` is an allocation-free, exactly typed unmanaged function pointer; C# statics are per assembly instance, so another `AssemblyLoadContext` loading the assembly gets its own.
- **Decision (owner-selected in the P9.1 task):**
  - **A. Package.** `dotnet/` holds one library project `SasPairing` (package ID, root namespace, and assembly `SasPairing`, version `0.1.0-dev.1`, `net10.0`) and one test project `SasPairing.Tests` (xUnit v3), in `dotnet/SasPairing.sln`. .NET 10 is the current LTS baseline for this new experimental package; there is no multi-targeting, `netstandard`, or downgrade. The library has no runtime package dependency. `IsPackable` is `false` in P9.1: no NuGet package is built or published; P9.6 decides distribution.
  - **B. Build settings.** Nullable reference types, implicit usings, unsafe blocks (for `Interop/` only), warnings as errors, `latest-recommended` built-in analyzers, deterministic builds, XML documentation generation, and locked restore (`packages.lock.json` committed). No warning is suppressed. The SDK is pinned by `dotnet/global.json` to `10.0.401` with `rollForward: latestPatch` (a later 10.0.4xx patch is accepted; no other feature band or major version), and `dotnet test` uses the Microsoft.Testing.Platform runner selected there.
  - **C. Exact ABI v1 only.** The wrapper binds exactly `SAS_PAIRING_ABI_VERSION = 1`, required by a C# literal that the tests compare with the header and the manifest. There is no ABI negotiation, fallback, legacy mode, compatibility shim, or second ABI. `sas_pairing_abi_version()` returning anything but `1` fails initialization.
  - **D. Explicit native image, never default resolution.** No `[DllImport]`, `[LibraryImport]`, `extern` method, `DllImportResolver`, library basename, or OS / runtime search is used. The one production load is `NativeLibrary.Load(path)` of a validated, canonical, fully qualified path, followed by `NativeLibrary.TryGetExport` of each frozen export by exact name.
  - **E. One private function table.** `AbiV1FunctionTable` holds exactly 25 `internal readonly delegate* unmanaged[Cdecl]<...>` fields, each named exactly as its export and resolved by that name (`nameof`), so a field and its symbol cannot drift apart. There are no 25 P/Invoke methods, no managed delegates, and no public function pointer.
  - **F. Type mapping.** `int32_t` → `int` (`sas_pairing_status_t`); `uint32_t` → `uint` (every `uint32_t` namespace); `uint64_t` → `ulong` (the six opaque handles, `0` invalid, never a pointer or identity); `uint8_t` → `byte`; `size_t` → `nuint`; `uintptr_t` → `nuint` (`sas_pairing_socket_t`, invalid `nuint.MaxValue`); pointers → unmanaged pointer types; inline arrays → fixed buffers. `size_t` and `uintptr_t` are never `ulong`, even where both are 8 bytes. The raw layer spells every ABI identifier exactly as the header does (constants, records, fields, exports); idiomatic C# names begin with the high-level API in P9.2.
  - **G. Records.** The six frozen records are internal `LayoutKind.Sequential` structs with fixed buffers for inline arrays and no managed array, string, `bool`, `char`, or reference, so each is blittable with exactly the native layout (bytes view 16/8, bootstrap view 64/8, event 128/8, result info 56/4, action 24/8, SAS presentation 56/4, with the manifest offsets).
  - **H. Pointer width.** Initialization requires `IntPtr.Size == 8` before any path work or load; the 64-bit layouts are never reinterpreted in a 32-bit process.
  - **I. Loader.** One internal `NativeAbiV1Loader` with a process instance (`NativeAbiV1Loader.Process`). Order: (1) pointer width 8; (2) the explicit path must be non-empty, fully qualified (`Path.IsPathFullyQualified`), and an existing file, and is canonicalized (full path, final link target); (3) exactly one `NativeLibrary.Load` of the canonical path; (4) the image is retained; (5) all 25 exports are preflighted by exact name (a lookup, never a call); (6) the function table is bound; (7) `sas_pairing_abi_version()` is called, the only native call during initialization; (8) it must return `1`; (9) the binding is published. Initialization is serialized by a lock, so concurrent callers load one image.
  - **J. Loader states.** `Uninitialized`, `Ready`, `PermanentlyFailedAfterLoad`. Pre-load failures (`UnsupportedPointerWidth`, `InvalidLibraryPath`, `OpenFailed`: `NativeLibrary.Load` threw, so no handle exists) leave the loader `Uninitialized` with nothing retained, and a later call may retry after the cause is fixed. Post-load failures (`MissingSymbol`, `BindingFailed`, `AbiVersionQueryFailed` for version `0`, `AbiVersionMismatch` for any other value) are permanent for the loader: the handle stays retained and is never freed, no other path is ever inspected or loaded, no second image is opened, and every later call throws the same exception, whose message says to correct the native library and restart the OS process. Version `0` means the native query itself failed; it is never "an old ABI" or "try again". A missing export is never optional and no partial table is kept.
  - **K. Ready is final.** Once ready, every later initialization returns the identical `NativeAbiV1` without inspecting its path argument, opening anything, or querying again. There is no reset, reload, or replacement, in production or for tests: state-machine tests construct their own loaders over fake platforms, never through the process loader.
  - **L. No release of the image.** Production never calls `NativeLibrary.Free`; there is no `Dispose`, `SafeHandle`, finalizer, `ProcessExit` or `AssemblyLoadContext.Unloading` handler, or other path that releases the module. The retained handle is intentionally kept until the OS process exits, because the native state is module state of the loaded image (P7-D-002): freeing it would end that state, and reloading would start fresh state, which is not a supported recovery.
  - **M. Assembly load context.** The supported model is one `SasPairing` assembly instance, loaded normally into the default `AssemblyLoadContext`, owning the one native image of the OS process. Loading the assembly again in another load context (or a copied native module) would create a second loader; that is outside the supported model, is never presented as a recovery mechanism, and cannot be detected or prevented by the wrapper. P9.1 builds no cross-load-context logic.
  - **N. Private raw interop.** Every raw type (constants, records, function table, loader, platform seam, failure categories, initialization exception) is `internal` under `dotnet/src/SasPairing/Interop/`, visible only to `SasPairing.Tests` through `InternalsVisibleTo`. P9.1 exports no public type at all; no handle, pointer, function pointer, record, constant, or `NativeLibrary` handle is public now or as the basis of the later API. P9.2 defines the public initialization error surface.
  - **O. Unsafe code is localized.** Every `unsafe` declaration lives under `Interop/` and is preceded by a `// UNSAFE:` justification: the bytes-view record (a raw `const uint8_t *`), the records with inline arrays (fixed buffers), and the function table (unmanaged function pointers and their casts). Nothing else is unsafe.
  - **P. No protocol or cryptography in C#.** No frame building or parsing, hashing, MAC, SAS, request ID, transcript, deadline, opportunity accounting, or START limiting; no networking, thread, task, or timer. The native Rust core stays the only protocol implementation, and no status is a trust verdict.
  - **Q. Source of the binding.** The C# ABI definition derives from the frozen header and manifest only, never from the Dart generated bindings, and depends on nothing in `dart/`.
  - **R. Platform scope.** Windows (x64) is the only pairing-networking platform, as P7 defines. On Linux the same ABI v1 library is loaded in CI only to verify the version and exports; that is not Linux pairing support.
- **Why:** an explicit absolute path with no search keeps the one-image decision with the application and makes the loaded file auditable; function pointers resolved by exact name give one exact, private table instead of runtime-generated marshalling stubs; separating pre-load from post-load failures follows P7-D-002 exactly (before an image exists nothing needs undoing; after it exists nothing can be undone); checking every constant, record, and signature against the header and the manifest makes drift a test failure instead of a silent incompatibility.
- **Unchanged:** every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision; the frozen protocol candidate.
- **Status:** decided by the owner for P9.1, 2026-10-04; implemented in `dotnet/` (P9.1).

## P9-D-002 — .NET Lifecycle Ownership, Public Errors, and Fail-Closed State

- **Inputs:** the seven frozen lifecycle exports and their exact semantics in [`sas_pairing.h`](../../core/include/sas_pairing.h) and [ABI contract §5](../p7-native-abi/abi-contract.md#5-runtime-lifecycle), [§6](../p7-native-abi/abi-contract.md#6-fatal-semantics), [§15](../p7-native-abi/abi-contract.md#15-authorities), and [§16](../p7-native-abi/abi-contract.md#16-hosting-contexts), rechecked against `core/src/abi` for P9.2: `sas_pairing_runtime_create` creates the one runtime of the process (`ALREADY_INITIALIZED` while one is active, never replaced; no platform gate); `sas_pairing_runtime_destroy` removes the runtime from its slot first and then destroys its hosts and releases its authorities (cleanup, allowed in the fatal state, never clears it); `sas_pairing_authority_register` copies `scope_len` bytes (not a C string; `NULL` only with length 0, which the core answers with `INVALID_SCOPE`; on non-Windows the OS ownership lease fails closed with `UNSUPPORTED_PLATFORM`); `sas_pairing_authority_release` destroys every host of the authority, then removes its handle, then runs the core release, and the handle and its hosts are consumed whatever is returned (for example `OWNERSHIP_UNCERTAIN`), with process-session accounting never reset; `sas_pairing_authority_status` reports `READY` with 1–10, or `BUSY` or `EXHAUSTED` with 0; `sas_pairing_host_create` is accounting neutral and does no networking; `sas_pairing_host_destroy` invalidates the host handle whatever is returned. A caught panic makes the process permanently fatal: the four creates and the status query (normal) then return `SAS_PAIRING_FATAL` without entering the core, while destroy, release, and host destroy (cleanup) still work. The P9-D-001 loader, which this decision builds on unchanged. The P8 Dart lifecycle ([P8-D-002](../p8-dart-package/decisions.md#p8-d-002--dart-lifecycle-ownership-and-fail-closed-state)) as reference evidence for wrapper semantics, not for C# surface syntax.
- **Decision (owner-selected in the P9.2 task):**
  - **A. Public types.** P9.2 introduces exactly ten public types in namespace `SasPairing`: `SasPairingRuntime`, `SasPairingAuthority`, `SasPairingHost` (sealed classes, `IDisposable`), `SasPairingInitializationFailure`, `SasPairingInitializationException`, `SasPairingStatus`, `SasPairingNativeException`, `SasPairingContractException`, `SasPairingAuthorityState`, and the immutable `readonly record struct SasPairingAuthorityStatus(State, RemainingOpportunities)`. No raw handle, pointer, function pointer, native record, `NativeAbiV1`, `AbiV1FunctionTable`, loader, `NativeLibrary` handle, `NativeInitializationException`, or lifecycle service is public, now or as a member type.
  - **B. Lifecycle convention.** `IDisposable.Dispose()` is the one deterministic cleanup convention, with `bool IsDisposed { get; }` on all three wrappers. There is no `Close`, no finalizer, no `SafeHandle`, and no `CriticalFinalizerObject`: these handles take part in explicit parent-to-child native cascades that a per-handle release object would duplicate or reorder. An undisposed wrapper keeps its native object until its parent is disposed or the process exits.
  - **C. Runtime factory.** `SasPairingRuntime.Create(string nativeLibraryPath)` (synchronous; a null path is `ArgumentNullException`) initializes the one P9.1 process loader (no discovery or default resolution; once loaded, later paths are ignored), translates a loader failure, obtains the one process context, admits a normal operation, calls `sas_pairing_runtime_create`, and requires `OK` and a non-zero handle. A second `Create` while a runtime is active is answered by the native library (`AlreadyInitialized`); the active runtime is never returned or aliased. Loader idempotence is not runtime creation.
  - **D. Initialization failures.** `SasPairingInitializationFailure` has exactly the seven P9.1 loader categories (`UnsupportedPointerWidth`, `InvalidLibraryPath`, `OpenFailed`, `MissingSymbol`, `BindingFailed`, `AbiVersionQueryFailed`, `AbiVersionMismatch`). `SasPairingInitializationException` has `Failure` and `ProcessRestartRequired` (false for the three pre-load categories, true for the four post-load ones). The private-to-public translation is one exhaustive `switch` by name (no integer index, `Enum.Parse`, reflection, or default-to-other); a future internal category fails loudly until it is given a public meaning, and the tests enumerate every category. The message text is preserved, but the private `NativeInitializationException` is never the thrown type and never the `InnerException`. No native status is invented for a loader failure.
  - **E. Native statuses.** `SasPairingStatus : int` has the 48 frozen statuses with exactly their native values, in idiomatic PascalCase (`Ok = 0` … `ConnectionEnded = 405`, `Fatal = 900`). `SasPairingNativeException` has `Operation` (the public operation), `StatusCode` (the exact `int`, known or not), `KnownStatus` (null for a value the enum does not name: an unknown non-zero status is a failure, never success, and never blindly cast), and `ProcessRestartRequired` (true only for 900; unknown is not fatal). Statuses are operation outcomes: no property or message classifies a peer as trusted, malicious, attacking, or compromised.
  - **F. Contract violations.** An `OK` whose outputs break the frozen contract (a zero create handle; an authority state other than `READY` 1–10, `BUSY` 0, or `EXHAUSTED` 0) throws `SasPairingContractException` (`Operation`, `ProcessRestartRequired` always true) and latches a process contract violation. No wrapper is constructed from it.
  - **G. Use after dispose.** Every operation on a disposed wrapper throws the idiomatic `ObjectDisposedException` locally, without a native call; no synthetic native status is used.
  - **H. Process context.** One internal `NativeProcessContext` per process sits below every runtime. It holds the one verified binding and the lifecycle-native service over it, and two latches that are never reset: native `FATAL` observed and wrapper contract violation observed. Production obtains it from one static `NativeProcessContextSource` over `NativeAbiV1Loader.Process`: no second image, alternate loader, or loader reset. Disposing a runtime and creating another reuses the same context, binding, and latches. Tests construct their own contexts and sources over fake lifecycle services and fake platforms; there is no `ResetForTesting`.
  - **I. Normal and cleanup operations.** Normal: runtime create, authority register, authority status, host create. Cleanup: runtime destroy, authority release, host destroy. This is the native fatal classification of ABI contract §6. A normal operation is admitted in this order: (1) the object-local disposed check (`ObjectDisposedException`); (2) the contract latch (`SasPairingContractException`); (3) the fatal latch (`SasPairingNativeException` with `StatusCode` 900, `KnownStatus` `Fatal`, `ProcessRestartRequired` true); (4) the native call. Steps 1–3 make no native call. Cleanup is never admission-checked: an undisposed wrapper always makes its one cleanup call, also after either latch.
  - **J. Native fatal.** Whenever any lifecycle export returns 900, normal or cleanup, the fatal latch is set before the exception is thrown. There is no reset, clear, recover, reload, re-initialize, or alternate-library operation; runtime disposal and re-creation do not clear it (a later `Create` fails locally with no `runtime_create` and no load). Only an OS process restart recovers.
  - **K. Lifecycle-native service.** One internal `INativeLifecycleApi` with exactly seven methods, one per lifecycle export, returning raw statuses and handles and interpreting nothing; production `FfiNativeLifecycleApi` calls the P9.1 function table. All of its pointer code (stack-local output slots passed for the one synchronous call, the scope pinned for the one call) stays under `Interop/` behind a `// UNSAFE:` justification; no public wrapper is `unsafe`. No output pointer escapes a call, and no native allocation exists.
  - **L. Authority scope.** `RegisterAuthority(ReadOnlySpan<byte> scope)`: arbitrary binary, passed as the exact span bytes and `scope.Length`; an empty span passes a null pointer and length 0 and the native core answers `InvalidScope`. No string, encoding, terminator, copy into text, or duplicated scope validation; the pointer is not retained.
  - **M. Ownership graph.** Runtime → Authority → Host, by private parent references and child sets. Native parent cleanup performs the real cascade, so the wrapper makes exactly one cleanup call per `Dispose`: `Host.Dispose` → one `host_destroy`; `Authority.Dispose` → one `authority_release` and no `host_destroy`; `Runtime.Dispose` → one `runtime_destroy` and no release or destroy of any descendant. After the native attempt, whatever its status, the object is disposed, every descendant is marked disposed locally, the child sets are cleared, and the object is removed from its parent; then a non-zero status is thrown as `SasPairingNativeException`. A later `Dispose` of the object or of a cascaded child makes no native call and throws nothing. A cleanup failure is consuming: never retried.
  - **N. Authority status.** `GetStatus()` validates one native snapshot: `READY` requires 1 ≤ remaining ≤ 10 (the frozen core maximum, a private constant, not configurable), `BUSY` and `EXHAUSTED` require 0; anything else (including state `INVALID`, an unknown state, `READY` 0, `READY` 11, `READY` `uint.MaxValue`) is a contract violation. The wrapper keeps no previous count, expected decrement, budget, or limiter: snapshots `READY 1`, `READY 10`, `READY 4` in that order are each accepted; the native core is the only accounting authority.
  - **O. Identity and leakage.** Wrappers use reference identity (no `Equals` or `GetHashCode` over a handle, scope, or parent). No public `Handle`, `NativeHandle`, or `RawHandle`; no handle or scope byte in `ToString`, an exception message, or library logging (the library logs nothing).
  - **P. Concurrency.** Calls on one runtime and its authorities and hosts are serialized by one lock of that object tree, so concurrent `Dispose` calls make one native call. Everything is synchronous: no `Task`, `ValueTask`, `async`, thread, timer, channel, or background worker.
  - **Q. Runtime is not a security reset.** Destroying and re-creating a runtime reuses the loaded image and the process context and resets no authority opportunity accounting, START limiting, or other same-process security state ([P6-D-002](../p6-remediation/decisions.md#p6-d-002--f-003-owner-session-policy)), and no latch. It is never described as a fresh security session; only an OS process restart is.
  - **R. Scope of P9.2.** No listener, socket, network drive, event, connection, run, ceremony control, SAS presentation, result, Bootstrap, protocol, or cryptography, and no placeholder public type for any of them; P9.3–P9.5 own them. Linux: runtime creation works and authority registration fails closed with `UnsupportedPlatform`; that is not Linux pairing support.
- **Why:** `IDisposable` is the idiomatic, analyzable deterministic-cleanup contract of .NET, and a throwing first `Dispose` is the only honest way to surface a native cleanup failure that has nevertheless consumed the handle; mirroring the native cascade locally (one native call, local invalidation of descendants) keeps the managed graph exactly as valid as the native one and never issues a cleanup call the native library already performed; latching both native `FATAL` and impossible success outputs process-wide, below every runtime, is the fail-closed reading of P7-D-001 and P6-D-004, while leaving cleanup open matches the native fatal classification; keeping the loader exception private and translating it exhaustively gives consumers one stable public error type per class of failure without committing to internal structure.
- **Unchanged:** P9-D-001 and the P9.1 loader, binding, and layouts; every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision.
- **Status:** decided by the owner for P9.2, 2026-10-04; implemented in `dotnet/` (P9.2).
