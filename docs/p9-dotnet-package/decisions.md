## P9-D-001 — .NET ABI v1 Binding and Loader Architecture

- **Inputs:** the frozen ABI v1 surface (version 1, 25 exports, 48 statuses, 84 namespace values, 11 scalar constants, 6 records; [manifest](../p7-native-abi/abi-v1-manifest.md), [`sas_pairing.h`](../../core/include/sas_pairing.h)); the loader invariant of [P7-D-002](../p7-native-abi/decisions.md#p7-d-002--native-library-residency-and-loader-lifetime) and [ABI contract §14](../p7-native-abi/abi-contract.md#14-native-library-loading-and-residency) (one native image per OS process, resident until exit, no unload, reload, or alternate copy, process restart as the only recovery from `SAS_PAIRING_FATAL`); the wrapper handoff of [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff) item 13 and [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9), which names `NativeLibrary.Free` explicitly for P9; the P8 Dart implementation ([P8-D-001](../p8-dart-package/decisions.md#p8-d-001--dart-native-binding-and-loader-architecture)) as reference evidence for wrapper semantics, not as a source. .NET facts that shape the design: `NativeLibrary.Load(string)` loads a module by path and returns an OS handle, `NativeLibrary.TryGetExport` looks a symbol up without calling it, and only `NativeLibrary.Free` releases a handle (nothing frees it implicitly); `[DllImport]` / `[LibraryImport]` resolve a library name through the runtime's probing and the OS search order; `delegate* unmanaged[Cdecl]<...>` is an allocation-free, exactly typed unmanaged function pointer; C# statics are per assembly instance, so another `AssemblyLoadContext` loading the assembly gets its own.
- **Decision (owner-selected in the P9.1 task):**
  - **A. Package.** `dotnet/` holds one library project `SasPairing` (package ID, root namespace, and assembly `SasPairing`, version `0.1.0-dev.1`, `net10.0`) and one test project `SasPairing.Tests` (xUnit v3), in `dotnet/SasPairing.sln`. .NET 10 is the current LTS baseline for this new experimental package; there is no multi-targeting, `netstandard`, or downgrade. The library has no runtime package dependency. `IsPackable` is `false` in P9.1: no NuGet package is built or published; P9.6 decides distribution.
  - **B. Build settings.** Nullable reference types, implicit usings, unsafe blocks (for `Interop/` only), warnings as errors, `latest-recommended` built-in analyzers, deterministic builds, XML documentation generation, and locked restore (`packages.lock.json` committed). No warning is suppressed. The SDK is pinned by `dotnet/global.json` to `10.0.401` with `rollForward: latestPatch` (a later 10.0.4xx patch is accepted; no other feature band or major version), and `dotnet test` uses the Microsoft.Testing.Platform runner selected there.
  - **C. Exact ABI v1 only.** The wrapper binds exactly `SAS_PAIRING_ABI_VERSION = 1`, required by a C# literal that the tests compare with the header and the manifest. There is no ABI negotiation, fallback, legacy mode, compatibility shim, or second ABI. `sas_pairing_abi_version()` returning anything but `1` fails initialization.
  - **D. Explicit native image, never default resolution.** No `[DllImport]`, `[LibraryImport]`, `extern` method, `DllImportResolver`, library basename, or OS / runtime search is used. The one production load is `NativeLibrary.Load(path)` of a validated, canonical, fully qualified path, followed by `NativeLibrary.TryGetExport` of each frozen export by exact name.
  - **E. One private function table.** `AbiV1FunctionTable` holds exactly 25 `internal readonly delegate* unmanaged[Cdecl]<...>` fields, each named exactly as its export and resolved by that name (`nameof`), so a field and its symbol cannot drift apart. There are no 25 P/Invoke methods, no managed delegates, and no public function pointer.
  - **F. Type mapping.** `int32_t` → `int` (`sas_pairing_status_t`); `uint32_t` → `uint` (every `uint32_t` namespace); `uint64_t` → `ulong` (the six opaque handles, `0` invalid, never a pointer or identity); `uint8_t` → `byte`; `size_t` → `nuint`; `uintptr_t` → `nuint` (`sas_pairing_socket_t`, invalid `nuint.MaxValue`); pointers → unmanaged pointer types; inline arrays → fixed buffers. `size_t` and `uintptr_t` are never `ulong`, even where both are 8 bytes. The raw layer spells every ABI identifier exactly as the header does (constants, records, fields, exports); idiomatic C# names begin with the high-level API in P9.2.
  - **G. Records.** The six frozen records are internal `LayoutKind.Sequential` structs with fixed buffers for inline arrays and no managed array, string, `bool`, `char`, or reference, so each is blittable with exactly the native layout (bytes view 16/8, bootstrap view 64/8, event 128/8, result info 56/4, action 24/8, SAS presentation 56/4, with the manifest offsets).
  - **H. Pointer width.** Initialization requires `IntPtr.Size == 8` before any path work or load; the 64-bit layouts are never reinterpreted in a 32-bit process.
  - **I. Loader.** One internal `NativeAbiV1Loader` with a process instance (`NativeAbiV1Loader.Process`). Order: (1) pointer width 8; (2) the explicit path must be non-empty, fully qualified (`Path.IsPathFullyQualified`), and an existing file, and is canonicalized (full path, final link target); (3) exactly one `NativeLibrary.Load` of the canonical path; (4) the image is retained; (5) all 25 exports are preflighted by exact name (a lookup, never a call); (6) the function table is bound; (7) `sas_pairing_abi_version()` is called, the only native call during initialization; (8) it must return `1`; (9) the binding is published. Initialization is serialized by a lock, so concurrent callers load one image.
  - **J. Loader states.** `Uninitialized`, `Ready`, `PermanentlyFailedAfterLoad`. Pre-load failures (`UnsupportedPointerWidth`, `InvalidLibraryPath`, `OpenFailed`: `NativeLibrary.Load` threw, so no handle exists) leave the loader `Uninitialized` with nothing retained, and a later call may retry after the cause is fixed. Post-load failures (`MissingSymbol`, `BindingFailed`, `AbiVersionQueryFailed` for version `0`, `AbiVersionMismatch` for any other value) are permanent for the loader: the handle stays retained and is never freed, no other path is ever inspected or loaded, no second image is opened, and every later call throws the same exception, whose message says to correct the native library and restart the OS process. Version `0` means the native query itself failed; it is never "an old ABI" or "try again". A missing export is never optional and no partial table is kept.
  - **K. Ready is final.** Once ready, every later initialization returns the identical `NativeAbiV1` without inspecting its path argument, opening anything, or querying again. There is no reset, reload, or replacement, in production or for tests: state-machine tests construct their own loaders over fake platforms, never through the process loader.
  - **L. No release of the image.** Production never calls `NativeLibrary.Free`; there is no `Dispose`, `SafeHandle`, finalizer, `ProcessExit` or `AssemblyLoadContext.Unloading` handler, or other path that releases the module. The retained handle is intentionally kept until the OS process exits, because the native state is module state of the loaded image (P7-D-002): freeing it would end that state, and reloading would start fresh state, which is not a supported recovery.
  - **M. Assembly load context.** The supported model is one `SasPairing` assembly instance, loaded normally into the default `AssemblyLoadContext`, owning the one native image of the OS process. Loading the assembly again in another load context (or a copied native module) would create a second loader; that is outside the supported model, is never presented as a recovery mechanism, and cannot be detected or prevented by the wrapper. P9.1 builds no cross-load-context logic.
  - **N. Private raw interop.** Every raw type (constants, records, function table, loader, platform seam, failure categories, initialization exception) is `internal` under `dotnet/src/SasPairing/Interop/`, visible only to `SasPairing.Tests` through `InternalsVisibleTo`. P9.1 exports no public type at all; no handle, pointer, function pointer, record, constant, or `NativeLibrary` handle is public now or as the basis of the later API. P9.2 defines the public initialization error surface.
  - **O. Unsafe code is localized.** Every `unsafe` declaration lives under `Interop/` and is preceded by a `// UNSAFE:` justification: the bytes-view record (a raw `const uint8_t *`), the records with inline arrays (fixed buffers), and the function table (unmanaged function pointers and their casts). Nothing else is unsafe.
  - **P. No protocol or cryptography in C#.** No frame building or parsing, hashing, MAC, SAS, request ID, transcript, deadline, opportunity accounting, or START limiting; no networking, thread, task, or timer. The native Rust core stays the only protocol implementation, and no status is a trust verdict.
  - **Q. Source of the binding.** The C# ABI definition derives from the frozen header and manifest only, never from the Dart generated bindings, and depends on nothing in `dart/`.
  - **R. Platform scope.** Windows (x64) is the only pairing-networking platform, as P7 defines. On Linux the same ABI v1 library is loaded in CI only to verify the version and exports; that is not Linux pairing support.
- **Why:** an explicit absolute path with no search keeps the one-image decision with the application and makes the loaded file auditable; function pointers resolved by exact name give one exact, private table instead of runtime-generated marshalling stubs; separating pre-load from post-load failures follows P7-D-002 exactly (before an image exists nothing needs undoing; after it exists nothing can be undone); checking every constant, record, and signature against the header and the manifest makes drift a test failure instead of a silent incompatibility.
- **Unchanged:** every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); every P8 file and decision; the frozen protocol candidate.
- **Status:** decided by the owner for P9.1, 2026-10-04; implemented in `dotnet/` (P9.1).
