## P8-D-001 — Dart Native Binding and Loader Architecture

- **Inputs:** the frozen ABI v1 surface (version 1, 25 exports, 48 statuses, 84 namespace values, 11 scalar constants, 6 records; [manifest](../p7-native-abi/abi-v1-manifest.md), [`sas_pairing.h`](../../core/include/sas_pairing.h)); the loader invariant of [P7-D-002](../p7-native-abi/decisions.md#p7-d-002--native-library-residency-and-loader-lifetime) and [ABI contract §14](../p7-native-abi/abi-contract.md#14-native-library-loading-and-residency) (one native image per OS process, resident until exit, no unload, reload, or alternate copy, process restart as the only recovery from `SAS_PAIRING_FATAL`); the wrapper handoff of [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff) item 13 and [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9); the drive, run, result, and ceremony-control rules of [P7-D-008](../p7-native-abi/decisions.md#p7-d-008--bounded-drive-and-foreign-event-model) to [P7-D-012](../p7-native-abi/decisions.md#p7-d-012--sas-presentation-identity-binding-and-local-action-statuses), which later P8 increments wrap. `dart:ffi` facts that shape the design: `DynamicLibrary.open` of the same file loads it into the VM process once, even across isolates; `DynamicLibrary.close()` exists (Dart 3.1+) and may let the OS unload the library; Dart statics are isolate-local, not process-global.
- **Decision (owner-selected in the P8.1 task):**
  - **A.** `dart/` is one pure-Dart package named `sas_pairing` (version `0.1.0-dev.1`, `publish_to: none`). It does not depend on Flutter; a pure-Dart package stays usable from Flutter applications.
  - **B.** P8 binds the one frozen native ABI v1. It adds, renames, or changes no export, signature, status, record, or ownership rule, and adds no Dart-specific native helper.
  - **C.** The raw FFI layer is generated by `ffigen` from `core/include/sas_pairing.h` into `dart/lib/src/native/generated/sas_pairing_bindings.g.dart` (class `SasPairingNativeBindings`), committed, and reproducible. It is the only raw C declaration layer: no handwritten `lookupFunction` copy or second set of signatures exists. Every declaration is listed explicitly in `dart/ffigen.yaml` and everything else is excluded, so a future header addition needs conscious P8 work.
  - **D.** The raw layer stays private under `lib/src/native/` and is not exported from `lib/sas_pairing.dart`, which exports nothing in P8.1. No `Pointer`, `DynamicLibrary`, generated `Struct`, allocator helper, or native callback is part of the public API now or as the basis of the later one.
  - **E.** The high-level Dart API wraps this private layer in later P8 increments (P8.2 onwards).
  - **F.** Exactly one supported native library image is loaded for the process.
  - **G.** The package retains the `DynamicLibrary` (and the one `SasPairingNativeBindings` built over it) for the process lifetime, strongly referenced from package-private state.
  - **H.** There is no unload, close, dispose, reload, native reset, replace, or recovery by opening another copy; the package never calls `DynamicLibrary.close()`, and no `Finalizer` or `NativeFinalizer` touches the library.
  - **I.** Recovery from `SAS_PAIRING_FATAL` (and from a loaded image that failed verification) means an OS process restart.
  - **J.** The native ABI version must be exactly `1`. The required version is a Dart literal checked against the header and the manifest by tests, not the header macro itself, so a header that changed its version fails the build instead of being accepted.
  - **K.** P8.1 does not bundle or distribute native binaries: no committed `.dll` or `.so`, no package asset, no native-assets build hook, no download.
  - **L.** The native binary location is supplied explicitly: `NativeLibraryLoader.initialize(libraryPath: ...)` takes an absolute path to an existing file. There is no search path, working-directory scan, alternate file name, fallback directory, download, or runtime Rust build. Discovery and packaging are a later P8 decision.
  - **M.** P8.1 adds no protocol or cryptographic implementation in Dart: no SAS, MAC, hash, DH, request ID, ceremony identity, frame encoding or decoding, transcript, final ACK, timeout, security budget, or START limiting. Rust stays authoritative; no native status is interpreted as a trust verdict.
  - **N.** Supported direct native ownership is one Dart owner isolate per OS process. Other isolates do not load the library or call the bindings themselves; they talk to the owner at a higher layer or do not use the native package. P8.1 builds no isolate façade, and the loader is not claimed to be process-global: a Dart static cannot stop another isolate from opening an image. A later isolate-facing façade needs its own decision.
  - **O.** P8 claims pairing transport support only where P7 does: Windows TCP. The package loads and tests the same ABI v1 library on Linux, which is not Linux pairing support: there pairing operations fail closed with `SAS_PAIRING_UNSUPPORTED_PLATFORM` as P7 defines.
- **Loader rules chosen in P8.1:**
  1. **Initialization order.** (1) The process pointer width must be 8 bytes (the frozen layouts are 64-bit), else failure before any path work; (2) the path must be non-empty, absolute, and an existing file, else failure; (3) it is canonicalized (`resolveSymbolicLinksSync`); (4) exactly one `DynamicLibrary.open` of the canonical path; (5) the image is retained; (6) all 25 frozen exports are preflighted by exact name with `providesSymbol` (a lookup, never a call); (7) the generated bindings are built; (8) `sas_pairing_abi_version()` is called, the only native call during initialization; (9) it must return `1`; (10) the ready library is published. No stateful export is called.
  2. **Failure before an image is loaded** (pointer width, path, or an OS load error from `DynamicLibrary.open`) leaves the loader uninitialized with nothing retained; a later attempt may try again.
  3. **Failure after an image is loaded** (a missing export, version `0`, a version other than `1`, or an unexpected error while binding or verifying) is permanent for the process: the image stays referenced, no other library is ever opened, every later `initialize` and `instance` rethrows the same exception, and its message says to correct the native library and restart the OS process. Version `0` means the version query itself caught a panic; it is never "an old ABI" or "try again". A missing export is never optional, and no partial binding is kept.
  4. **Second initialization.** Once ready, `initialize` returns the identical `LoadedNativeLibrary` (and bindings) without inspecting its new `libraryPath` argument or opening anything, so no path swap is possible. Chosen over rejection because initialization stays idempotent for one owner isolate while the path is never re-read.
  5. **Tests never reset the process loader.** There is no `resetForTesting` or similar. State-machine tests construct their own `NativeLibraryLoader` over a fake platform, which never touches the isolate's process loader; scenarios that need a fresh real loader run in a child OS process.
- **Generation and toolchain choices:** `ffigen` is pinned exactly (`22.0.0`) with the YAML configuration (deprecated from `ffigen` 22.1, so a future upgrade must move to the Dart configuration API and regenerate byte-identically); CI uses the exact Dart SDK the bindings were generated and formatted with (`3.13.4`); the package's SDK constraint is `^3.11.0`, the lowest that `package:test` 1.32 (the newest of the four dependencies' minimums) allows. Records are named by their C typedef names (`sas_pairing_event_t`, ...), exactly as in the manifest, because the struct tag `sas_pairing_result_info` collides with the export of the same name. Every preprocessor constant is generated faithfully (`SAS_PAIRING_SOCKET_INVALID`, `UINTPTR_MAX`, is the all-ones pattern that a Dart `int` reads as `-1` on the 64-bit target), so the private ABI table in `lib/src/native/abi_v1.dart` refers to the generated constants and is checked against the manifest row by row; there is no unchecked hand-copied value list.
- **Why:** generating the one declaration layer from the frozen header, and checking it against the frozen manifest, makes accidental drift a test failure instead of a silent incompatibility. Keeping it private leaves the public API free to be designed around Dart objects rather than pointers. An explicit path with no discovery keeps the "one image" decision with the application until distribution is decided. Distinguishing pre-load from post-load failure follows P7-D-002 exactly: before an image exists nothing needs undoing, and after it exists nothing can be undone.
- **Unchanged:** every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); the frozen protocol candidate.
- **Status:** decided by the owner for P8.1, 2026-10-03; implemented in `dart/` (P8.1).
