## P8-D-001 — Dart Native Binding and Loader Architecture

- **Inputs:** the frozen ABI v1 surface (version 1, 25 exports, 48 statuses, 84 namespace values, 11 scalar constants, 6 records; [manifest](../p7-native-abi/abi-v1-manifest.md), [`sas_pairing.h`](../../core/include/sas_pairing.h)); the loader invariant of [P7-D-002](../p7-native-abi/decisions.md#p7-d-002--native-library-residency-and-loader-lifetime) and [ABI contract §14](../p7-native-abi/abi-contract.md#14-native-library-loading-and-residency) (one native image per OS process, resident until exit, no unload, reload, or alternate copy, process restart as the only recovery from `SAS_PAIRING_FATAL`); the wrapper handoff of [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff) item 13 and [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9); the drive, run, result, and ceremony-control rules of [P7-D-008](../p7-native-abi/decisions.md#p7-d-008--bounded-drive-and-foreign-event-model) to [P7-D-012](../p7-native-abi/decisions.md#p7-d-012--sas-presentation-identity-binding-and-local-action-statuses), which later P8 increments wrap. `dart:ffi` facts that shape the design: `DynamicLibrary.open` of the same file loads it into the VM process once, even across isolates; `DynamicLibrary.close()` exists (Dart 3.1+) and may let the OS unload the library; Dart statics are isolate-local, not process-global.
- **Decision (owner-selected in the P8.1 task):**
  - **A.** `dart/` is one pure-Dart package named `sas_pairing` (version `0.1.0-dev.1`, `publish_to: none`). It does not depend on Flutter; a pure-Dart package stays usable from Flutter applications.
  - **B.** P8 binds the one frozen native ABI v1. It adds, renames, or changes no export, signature, status, record, or ownership rule, and adds no Dart-specific native helper.
  - **C.** The raw FFI layer is generated by `ffigen` from `core/include/sas_pairing.h` into `dart/lib/src/native/generated/sas_pairing_bindings.g.dart` (class `SasPairingNativeBindings`), committed, and reproducible. It is the only raw C declaration layer: no handwritten `lookupFunction` copy or second set of signatures exists. Every declaration is listed explicitly in `dart/ffigen.yaml` and everything else is excluded, so a future header addition needs conscious P8 work.
  - **D.** The raw layer stays private under `lib/src/native/` and is not exported from `lib/sas_pairing.dart`, which exports nothing in P8.1. No `Pointer`, `DynamicLibrary`, generated `Struct`, allocator helper, or native callback is part of the public API now or as the basis of the later one.
  - **E.** The high-level Dart API wraps this private layer in later P8 increments (P8.2 onwards).
  - **F.** Exactly one supported native library image is loaded for the process.
  - **G.** The package retains the `DynamicLibrary` (and the one `SasPairingNativeBindings` built over it) for the process lifetime, strongly referenced from package-private state.
  - **H.** There is no unload, close, dispose, reload, native reset, replace, or recovery by opening another copy; the package never calls `DynamicLibrary.close()`, and no `Finalizer` or `NativeFinalizer` touches the library.
  - **I.** Recovery from `SAS_PAIRING_FATAL` (and from a loaded image that failed verification) means an OS process restart.
  - **J.** The native ABI version must be exactly `1`. The required version is a Dart literal checked against the header and the manifest by tests, not the header macro itself, so a header that changed its version fails the build instead of being accepted.
  - **K.** P8.1 does not bundle or distribute native binaries: no committed `.dll` or `.so`, no package asset, no native-assets build hook, no download.
  - **L.** The native binary location is supplied explicitly: `NativeLibraryLoader.initialize(libraryPath: ...)` takes an absolute path to an existing file. There is no search path, working-directory scan, alternate file name, fallback directory, download, or runtime Rust build. Discovery and packaging are a later P8 decision.
  - **M.** P8.1 adds no protocol or cryptographic implementation in Dart: no SAS, MAC, hash, DH, request ID, ceremony identity, frame encoding or decoding, transcript, final ACK, timeout, security budget, or START limiting. Rust stays authoritative; no native status is interpreted as a trust verdict.
  - **N.** Supported direct native ownership is one Dart owner isolate per OS process. Other isolates do not load the library or call the bindings themselves; they talk to the owner at a higher layer or do not use the native package. P8.1 builds no isolate façade, and the loader is not claimed to be process-global: a Dart static cannot stop another isolate from opening an image. A later isolate-facing façade needs its own decision.
  - **O.** P8 claims pairing transport support only where P7 does: Windows TCP. The package loads and tests the same ABI v1 library on Linux, which is not Linux pairing support: there pairing operations fail closed with `SAS_PAIRING_UNSUPPORTED_PLATFORM` as P7 defines.
- **Loader rules chosen in P8.1:**
  1. **Initialization order.** (1) The process pointer width must be 8 bytes (the frozen layouts are 64-bit), else failure before any path work; (2) the path must be non-empty, absolute, and an existing file, else failure; (3) it is canonicalized (`resolveSymbolicLinksSync`); (4) exactly one `DynamicLibrary.open` of the canonical path; (5) the image is retained; (6) all 25 frozen exports are preflighted by exact name with `providesSymbol` (a lookup, never a call); (7) the generated bindings are built; (8) `sas_pairing_abi_version()` is called, the only native call during initialization; (9) it must return `1`; (10) the ready library is published. No stateful export is called.
  2. **Failure before an image is loaded** (pointer width, path, or an OS load error from `DynamicLibrary.open`) leaves the loader uninitialized with nothing retained; a later attempt may try again.
  3. **Failure after an image is loaded** (a missing export, version `0`, a version other than `1`, or an unexpected error while binding or verifying) is permanent for the process: the image stays referenced, no other library is ever opened, every later `initialize` and `instance` rethrows the same exception, and its message says to correct the native library and restart the OS process. Version `0` means the version query itself caught a panic; it is never "an old ABI" or "try again". A missing export is never optional, and no partial binding is kept.
  4. **Second initialization.** Once ready, `initialize` returns the identical `LoadedNativeLibrary` (and bindings) without inspecting its new `libraryPath` argument or opening anything, so no path swap is possible. Chosen over rejection because initialization stays idempotent for one owner isolate while the path is never re-read.
  5. **Tests never reset the process loader.** There is no `resetForTesting` or similar. State-machine tests construct their own `NativeLibraryLoader` over a fake platform, which never touches the isolate's process loader; scenarios that need a fresh real loader run in a child OS process.
- **Generation and toolchain choices:** `ffigen` is pinned exactly (`22.0.0`) with the YAML configuration (deprecated from `ffigen` 22.1, so a future upgrade must move to the Dart configuration API and regenerate byte-identically); CI uses the exact Dart SDK the bindings were generated and formatted with (`3.13.4`); the package's SDK constraint is `^3.11.0`, the lowest that `package:test` 1.32 (the newest of the four dependencies' minimums) allows. Records are named by their C typedef names (`sas_pairing_event_t`, ...), exactly as in the manifest, because the struct tag `sas_pairing_result_info` collides with the export of the same name. Every preprocessor constant is generated faithfully (`SAS_PAIRING_SOCKET_INVALID`, `UINTPTR_MAX`, is the all-ones pattern that a Dart `int` reads as `-1` on the 64-bit target), so the private ABI table in `lib/src/native/abi_v1.dart` refers to the generated constants and is checked against the manifest row by row; there is no unchecked hand-copied value list.
- **Why:** generating the one declaration layer from the frozen header, and checking it against the frozen manifest, makes accidental drift a test failure instead of a silent incompatibility. Keeping it private leaves the public API free to be designed around Dart objects rather than pointers. An explicit path with no discovery keeps the "one image" decision with the application until distribution is decided. Distinguishing pre-load from post-load failure follows P7-D-002 exactly: before an image exists nothing needs undoing, and after it exists nothing can be undone.
- **Unchanged:** every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); the frozen protocol candidate.
- **Status:** decided by the owner for P8.1, 2026-10-03; implemented in `dart/` (P8.1).

## P8-D-002 — Dart Lifecycle Ownership and Fail-Closed State

- **Inputs:** the seven lifecycle exports of the frozen ABI v1 and their fatal classes ([manifest §2](../p7-native-abi/abi-v1-manifest.md#2-exports-25): `sas_pairing_runtime_create`, `sas_pairing_authority_register`, `sas_pairing_authority_status`, and `sas_pairing_host_create` are *normal*; `sas_pairing_runtime_destroy`, `sas_pairing_authority_release`, and `sas_pairing_host_destroy` are *cleanup*); the runtime lifecycle and fatal semantics ([ABI contract §5, §6](../p7-native-abi/abi-contract.md#5-runtime-lifecycle)); authorities ([§15](../p7-native-abi/abi-contract.md#15-authorities): a released authority handle and all of its host handles are invalid forever *whatever the result*; process-session accounting outlives every handle and runtime); hosting contexts ([§16](../p7-native-abi/abi-contract.md#16-hosting-contexts): a destroyed host handle is invalid forever *whatever is returned*; authority release and runtime destroy cascade to their hosts natively); [P8-D-001](#p8-d-001--dart-native-binding-and-loader-architecture) (one process loader, one owner isolate, no reset); [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9) items 3, 4, and 11.
- **Decision (owner-selected in the P8.2 task):**
  - **A. Public lifecycle types.** `SasPairingRuntime`, `SasPairingAuthority`, `SasPairingHost`, the immutable `SasPairingAuthorityStatus` with the enum `SasPairingAuthorityState` (`ready`, `busy`, `exhausted`), the enum `SasPairingStatus` (all 48 frozen statuses), and the exceptions `SasPairingNativeException`, `SasPairingClosedException`, and `SasPairingContractException`; since P8.2.1 also `SasPairingInitializationException` with the enum `SasPairingInitializationFailure` (M). Nothing else is exported: no raw handle, `Pointer`, `DynamicLibrary`, generated `Struct`, `SasPairingNativeBindings`, `NativeLibraryLoader`, or the private native lifecycle service. Every call is synchronous: no `Future`, `Stream`, `Timer`, or `Isolate`.
  - **B. Runtime factory.** `SasPairingRuntime.create(nativeLibraryPath: ...)` initializes the P8.1 process loader (once ready it returns the identical library and opens nothing), takes the one package-private *process context* associated with that loaded image, refuses locally if the context is latched (G, H), then calls `sas_pairing_runtime_create` and requires `SAS_PAIRING_OK` and a nonzero handle. A `SasPairingRuntime` is one native runtime lifetime, not the process security session: after `close()` a later `create` may make a new native runtime over the same image, but it never reloads, reopens, or replaces the image, never clears a latch, and never resets accounting. A second live runtime is never aliased: native `SAS_PAIRING_ALREADY_INITIALIZED` is thrown as a `SasPairingNativeException`.
  - **C. Normal and cleanup operations.** Normal: runtime create, authority register, authority status, host create. Cleanup: runtime destroy (`SasPairingRuntime.close`), authority release (`SasPairingAuthority.close`), host destroy (`SasPairingHost.close`). This is exactly the manifest fatal classification of these seven exports.
  - **D. Ownership.** `SasPairingRuntime` owns its `SasPairingAuthority` wrappers and each `SasPairingAuthority` owns its `SasPairingHost` wrappers, in private per-parent collections (nothing is stored globally). A child wrapper exists only after its native creation returned `SAS_PAIRING_OK` with a nonzero handle; a failed creation makes no wrapper. Handles stay private fields. Wrappers use ordinary object identity: no equality, hash code, `toString`, exception, or debug text is derived from a handle, scope, or parent.
  - **E. Explicit, idempotent, consuming close.** Each wrapper has `void close()` and `bool get isClosed`. There is no `Finalizer` or `NativeFinalizer`, so callers close explicitly (`try`/`finally`). The first `close()` marks the wrapper closed, makes exactly one native cleanup call, and then performs the local cascade, whatever the call returned (also if it threw): native handles are consumed by their cleanup call and are not retryable cleanup tokens. A failing status is then thrown once as a `SasPairingNativeException`. A later `close()` makes no native call and throws nothing. Host close removes the host from its authority and never releases the authority. Authority close calls `sas_pairing_authority_release` once, never `sas_pairing_host_destroy` for its hosts first, then marks every child host closed and leaves its runtime. Runtime close calls `sas_pairing_runtime_destroy` once, never authority release or host destroy first, then marks every authority and host closed. Dart mirrors the invalidation of the native cascade and never duplicates its cleanup calls.
  - **F. Local closed state.** A normal operation on a closed wrapper, including one closed by its parent's cascade, throws `SasPairingClosedException` (object kind and operation, no handle) before any native call.
  - **G. Native FATAL latch.** Any lifecycle call, normal or cleanup, that returns `SAS_PAIRING_FATAL` (900) sets a fatal latch in the process context. The latch lives below every runtime, so closing or recreating a runtime and closing wrappers never clear it. While it is set, every normal operation, `SasPairingRuntime.create` included, throws a `SasPairingNativeException` with status 900 without a native call (P7: no normal re-entry after FATAL), while cleanup of a still-open wrapper still makes its one native call (native cleanup stays admitted after FATAL). Only status 900 sets the latch. There is no `clearFatal`, reset, reopen, reload, or recovery API: the only recovery is an OS process restart.
  - **H. Contract-violation latch.** `SAS_PAIRING_OK` with an output that breaks a frozen success invariant (a zero handle from runtime create, authority register, or host create; authority state `INVALID` or an unknown state value; `READY` with a remaining count outside 1–10, that is 0 or more than 10 (the upper bound since P8.2.1); `BUSY` or `EXHAUSTED` with a nonzero remaining) throws `SasPairingContractException` and marks the process context unusable for normal operations: ABI version 1 claimed success without obeying its contract. Later normal operations throw `SasPairingContractException` without a native call; cleanup of existing wrappers stays allowed; a process restart is required. No zero handle is ever wrapped, and no fourth authority state is invented.
  - **I. Status model.** `SasPairingStatus` has one value per frozen status with its exact `code`, checked against the private P8.1 table; `SasPairingStatus.fromCode` returns `null` for an unknown code. Every nonzero status, known or not, is a failure: an unknown code is thrown as a `SasPairingNativeException` with its integer preserved and `knownStatus == null`, never treated as success or as fatal. `SasPairingNativeException.processRestartRequired` is true exactly for status 900. Frozen native outcomes (`BUSY`, `EXHAUSTED`, `OWNERSHIP_UNAVAILABLE`, `OWNERSHIP_UNCERTAIN`, `UNSUPPORTED_PLATFORM`, and the rest) are always a `SasPairingNativeException` with their exact status, never a vague `StateError`. Statuses and exceptions are operation outcomes, never trust verdicts, peer-malice verdicts, authentication policy, or consumer authorization, and no such property exists.
  - **J. Authority scope.** `registerAuthority(Uint8List scope)` takes arbitrary bytes. They are copied exactly into temporary native memory for the one call and passed as pointer plus length; an empty scope is passed as a null pointer with length 0 so that the native core decides (`INVALID_SCOPE`). No text encoding, NUL terminator, C-string handling, Dart-side scope validation, or retention of the caller's buffer.
  - **K. Authority status.** `queryStatus()` returns an immutable `SasPairingAuthorityStatus(state, remainingOpportunities)`: native `READY` with 1–10 remaining ([ABI contract §15](../p7-native-abi/abi-contract.md#15-authorities)) → `ready` with the reported remaining, `BUSY` with 0 → `busy`, `EXHAUSTED` with 0 → `exhausted`; every other `OK` output is a contract violation (H). The bound 10 is a private constant used only to validate that one success output: it is not public, not configurable, and not an ABI v1 constant (the frozen header exposes no such scalar). `SasPairingAuthorityState` is successful status data and stays separate from the failure status `SasPairingStatus.busy` (105). Dart caches or reconstructs no budget, guard, or START limiter; the native core stays authoritative.
  - **L. Native lifecycle service.** One private service, `NativeLifecycleApi`, is the only P8.2 code that touches FFI memory: it allocates the typed output slots (`Uint64` handles, `Uint32` state and remaining) and the scope copy, makes the one generated-binding call, and frees everything before it returns, so no allocation outlives a call. It is not a second declaration layer (the generated bindings stay the only one), and it keeps the lifecycle classes free of `Pointer`. Tests replace it with a deterministic fake; the production loader gains no test reset.
  - **M. Initialization failures (corrected by P8.2.1).** `SasPairingRuntime.create` never lets the private P8.1 loader exception escape. At one package-private boundary directly below it (`initializeProcessContext` in `lifecycle.dart`), the private `NativeLibraryInitializationException` is caught and translated into the public `SasPairingInitializationException(failure, message)`, whose `SasPairingInitializationFailure` has exactly the seven loader categories: `unsupportedPointerWidth`, `invalidLibraryPath`, `openFailed`, `missingSymbol`, `abiVersionQueryFailed`, `abiVersionMismatch`, `verificationFailed`. The mapping is an exhaustive switch with no default, wildcard, name, or index conversion, so a new private category does not compile until it has a public meaning. The message is preserved; the private exception is not exposed as a cause, inner exception, or field. `processRestartRequired` keeps the loader's classes: false for the pre-load failures (pointer width, path, OS load failure: no image was retained, and `create` may be called again after correcting the cause), true for the post-load failures (missing export, version query 0, version mismatch, verification failure: an image is resident and cannot be replaced, so every later `create` in the process fails the same way). An initialization failure has no `sas_pairing_status_t`: no status code or known status is invented. The private `NativeLibraryInitializationException`, `NativeLoadFailure`, `NativeLibraryLoader`, and `LoadedNativeLibrary` stay private, and the loader's state machine (P8-D-001) is unchanged: no reset, reload, or second open. The four public error classes stay distinct: initialization failure, nonzero native status (`SasPairingNativeException`; FATAL is status 900), local use after close, and contract violation.
  - **P8.2.1 correction record.** The P8.2 implementation (evidence unchanged below) let `SasPairingRuntime.create` throw the private loader exception, which consumers could not name, and deferred its public type; and it accepted `READY` with any remaining count above 0. Independent review found both; P8.2.1 replaced item M and tightened items H and K as written above, additively and without changing any other P8.2 behavior or any native code.
- **Why:** native cleanup consumes its handle whatever it returns, so a Dart wrapper that stayed open after a failed cleanup would hold a dead handle and invite a retry the ABI does not define. Mirroring the native cascade locally, without issuing child cleanup calls that the native parent already performs, keeps the Dart object graph exactly as valid as the native one. Latching FATAL and contract violations below the runtime keeps the P7 rule that nothing normal re-enters native code after FATAL and that no runtime recreation is a security reset.
- **Unchanged:** every P7 file, export, value, layout, and ownership rule; P8-D-001 (loader, one owner isolate, no unload or reset).
- **Status:** decided by the owner for P8.2, 2026-10-03; implemented in `dart/lib/src/lifecycle.dart`, `status.dart`, `exceptions.dart`, and `native/native_lifecycle_api.dart` / `native/native_process_context.dart` (P8.2, [evidence](README.md#p82-evidence)); items A, H, K, and M corrected/clarified by P8.2.1, 2026-10-03, in `lifecycle.dart`, `exceptions.dart`, and the entrypoint ([evidence](README.md#p821-evidence)).

## P8-D-003 — Dart Windows Listener, Cooperative Drive, and Connection Lifetime

- **Inputs:** the five network exports of the frozen ABI v1 and their fatal classes ([manifest §2](../p7-native-abi/abi-v1-manifest.md#2-exports-25): `sas_pairing_host_attach_windows_listener`, `sas_pairing_host_drive`, and `sas_pairing_host_recheck_after_resume` are *normal*; `sas_pairing_host_detach_listener` and `sas_pairing_connection_close` are *cleanup*); Windows listener ownership ([ABI contract §17](../p7-native-abi/abi-contract.md#17-windows-listener-ownership), [P7-D-006](../p7-native-abi/decisions.md#p7-d-006--windows-listener-ownership-and-responder-configuration): the in/out socket slot, adoption as the linearization point, `LISTENER_SETUP_FAILED` and a late `FATAL` after adoption, detach as idempotent cleanup, replacement as detach then attach); the bounded drive and event model ([§18](../p7-native-abi/abi-contract.md#18-network-drive-connections-runs-and-events), [P7-D-008](../p7-native-abi/decisions.md#p7-d-008--bounded-drive-and-foreign-event-model): one bounded step, 17 event records, the return value versus `*out_failure`, every event consumed also when the owner loop failed); connection and run references ([§18.5–§18.7](../p7-native-abi/abi-contract.md#185-connection-handles), [P7-D-009](../p7-native-abi/decisions.md#p7-d-009--connection--run-reference-semantics): one handle per connection, run handles never reached through a request ID, `RUN_UNTRACKED`); results ([§19](../p7-native-abi/abi-contract.md#19-results), [P7-D-010](../p7-native-abi/decisions.md#p7-d-010--pairingresult-ownership-and-foreign-access): runtime-owned, surviving connection close, detach, host destroy, authority release, and owner-loop failure; local verified completion only, [P6-D-005](../p6-remediation/decisions.md#p6-d-005--local-completion-and-final-ack-deadline-boundary)); [ABI contract §20.13 and §21](../p7-native-abi/abi-contract.md#2013-untracked-runs-wrapper-handoff) items 4–7, 9, and 10; [P8-D-001](#p8-d-001--dart-native-binding-and-loader-architecture) (one owner isolate) and [P8-D-002](#p8-d-002--dart-lifecycle-ownership-and-fail-closed-state) (explicit consuming cleanup, native-cascade mirroring, the two latches).
- **Decision (owner-selected in the P8.3 task):**
  - **A. Ownership tree.** `SasPairingRuntime` → `SasPairingAuthority` → `SasPairingHost`, and a host has zero or one native network context, which owns zero or more `SasPairingConnection` wrappers. A connection never outlives listener detach, host close, authority close, runtime close, or an owner-loop failure. Native results are runtime-owned and follow a different lifetime (N).
  - **B. Public types.** `SasPairingBootstrap`, `SasPairingWindowsListenerSocket`, the enum `SasPairingHostNetworkState`, `SasPairingConnection`, `SasPairingDriveBatch`, `SasPairingDriveFailure`, `SasPairingEvent`, and the enums `SasPairingEventKind`, `SasPairingStepKind`, `SasPairingProtocolEvent`, `SasPairingEventReason`, `SasPairingDeadlineKind`, `SasPairingCancelState`, and `SasPairingCancelReason`; on `SasPairingHost`: `attachWindowsListener`, `detachListener`, `drive`, `recheckAfterResume`, and `networkState`. Nothing else: no raw connection, run, result, or socket value, no generated record, no `Pointer`, no native event array, and no raw ABI integer for an enumeration or flag. Every call is synchronous.
  - **C. Bootstrap value.** `SasPairingBootstrap` holds exactly four byte fields, `applicationIdentity`, `keyAlgorithm`, `publicKey`, and `sharedContext`, taken as `Uint8List`, defensively copied at construction, and exposed only as unmodifiable views (a write through a getter, its buffer, or a view of its buffer throws). Bytes are arbitrary: no text constructor, encoding, terminator, normalization, or parsing. Dart validates nothing semantic: field bounds, the key-algorithm alphabet, and the canonical frame bound stay with the core's `Bootstrap::new`, whose refusal is `SAS_PAIRING_INVALID_BOOTSTRAP`, thrown as a `SasPairingNativeException`. Marshalling builds one `sas_pairing_bootstrap_view_t` of four `sas_pairing_bytes_view_t` per call: an empty field is a null pointer with length 0, any other field an exact copy in temporary native memory freed before the call returns; no pointer is kept.
  - **D. Listener socket token.** `SasPairingWindowsListenerSocket.fromNativeSocket(int socket)` wraps one caller-owned Windows `SOCKET` offered for ownership transfer; the raw value is accepted only at construction and has no public getter afterwards. Windows `INVALID_SOCKET` (`SAS_PAIRING_SOCKET_INVALID`) is refused at construction (`ArgumentError`): it is never a socket, and its slot value could not show whether a transfer happened. P7's trusted-caller precondition is the caller's: at attach entry the value is a valid Windows `SOCKET`, already bound, already listening, owned exclusively by the caller, and not used or closed concurrently. The package cannot prove that an integer is such a socket. The socket, its address, and its port are not peer, protocol, authenticated, or trust identity. P8.3 does not bind, choose an address, interface, port, or IP version, or configure discovery, a firewall, UPnP, or NAT traversal; obtaining the bound socket is an advanced integration boundary, and a binding convenience is a later decision. Construction is not guarded by platform: off Windows the native core refuses attach with `SAS_PAIRING_UNSUPPORTED_PLATFORM` before adoption, and no host can exist there anyway.
  - **E. Transfer state.** `isTransferred` is false until a call leaves the in/out slot at `SAS_PAIRING_SOCKET_INVALID`, then true for ever. While false the caller owns the socket (and closes it when done, also after a failed attach); once true the caller and Dart never close, use, mutate, or hand on the old value. A transferred token offered again fails locally (`StateError`) and the stale value never reaches native code. No production socket closer exists or is needed; tests have a test-only WinSock harness.
  - **F. Attach.** `attachWindowsListener({required listener, required local, expected})` is a *normal* operation: host open check, transferred check, process-context admission, then exactly one native attach over one typed `sas_pairing_socket_t` slot holding the offered value. After the call the slot is read **first** and the token updated before any status is processed or any exception is thrown. The only valid post-call slot values are the offered socket and `SAS_PAIRING_SOCKET_INVALID`; any other value is a contract violation. `SAS_PAIRING_OK` requires `INVALID` (otherwise a contract violation) and sets the network state to `attached`. A pre-adoption failure (`INVALID_ARGUMENT`, `UNSUPPORTED_PLATFORM`, `INVALID_BOOTSTRAP`, an early `FATAL`, `INVALID_HANDLE`, `LISTENER_ALREADY_ATTACHED`) leaves the slot and the caller's ownership unchanged and the host's network state untouched. A post-adoption failure (`LISTENER_SETUP_FAILED`, a late `FATAL`) consumes the token, and the host claims no network context. `FATAL` latches the process FATAL latch through the existing status check. `expected == null` means no exact expected peer Bootstrap; nothing replaces it. Attach performs no drive or accept and creates no connection.
  - **G. Network state.** `SasPairingHostNetworkState` has four distinct values: `detached` (no network context; the initial state, and the state after detach and after the host or a parent closes), `attached` (after attach `OK`), `listenerDisabled` (a `LISTENER_DISABLED` event: the listening socket is gone and nothing new is accepted, but existing connections continue; replacement is detach then attach), and `failedClosed` (the owner loop failed closed: every connection is gone; detach or close the host). A top-level drive error (`LISTENER_NOT_ATTACHED`, `INVALID_HANDLE`, `HANDLES_EXHAUSTED`, `UNSUPPORTED_PLATFORM`) changes no state.
  - **H. Detach.** `detachListener()` is cleanup: never refused by a latch, allowed after `SAS_PAIRING_FATAL`. On an open host every call makes exactly one native detach (native detach is idempotent, `OK` with no listener, so Dart never skips it on the strength of its own state); then, in finally-style cleanup whatever the result, the network state becomes `detached` and every connection wrapper of the host is closed with its private run references invalidated, with no `sas_pairing_connection_close` call. A failure such as `OWNERSHIP_UNCERTAIN` is thrown once and never retried. The host, authority, runtime, and all accounting stay. On a closed host it does nothing. There is no replace-in-place method.
  - **I. Cooperative drive.** `drive()` makes exactly one `sas_pairing_host_drive` and `recheckAfterResume()` exactly one `sas_pairing_host_recheck_after_resume`, each with the fixed capacity `SAS_PAIRING_MAX_DRIVE_EVENTS` (17), as normal operations. The package adds no loop, retry, polling, `Timer`, `Stream`, isolate, callback, or background work: one public call is one bounded native call. Native drive may wait up to about 250 ms, so blindly calling it on a Flutter UI isolate is not recommended; the one direct native owner isolate rule still holds, and a scheduling or isolate façade is later work. Persistent readiness can make calls return at once, so consumers must not spin `while (true) host.drive()` without a scheduling or yield policy. `recheckAfterResume()` is only for trusted outer code that observed an OS resume; P8.3 does not detect resume and never calls it periodically. Both share one event mapper, batch type, failure model, and connection rules.
  - **J. Return value versus `out_failure`.** A nonzero return value of drive or recheck means the call itself failed: no batch, a `SasPairingNativeException` through the existing status check (FATAL latched). With `SAS_PAIRING_OK`, every returned event is copied, mapped in native order, and delivered in an unmodifiable list inside `SasPairingDriveBatch`, also when `*out_failure` is not `OK`; the owner-loop failure is `SasPairingDriveBatch.failure`, a `SasPairingDriveFailure` (`statusCode` preserved exactly, `knownStatus` or `null`, `processRestartRequired` true exactly for 900), never a thrown exception. Order for a successful call: copy every record, map every event, apply the event-visible connection and network transitions, build the failure, latch FATAL when it is 900 (a package-private non-throwing observation), and, because any nonzero owner-loop failure means the loop failed closed, close every remaining connection wrapper, invalidate its run references, and set `failedClosed`; then return all events with the failure. Nothing future is synthesized: a later drive is sent to native, which reports `OWNER_LOOP_CLOSED`.
  - **K. Event model and mapping.** One immutable package-constructed `SasPairingEvent` with `kind`, `connection` (the Dart wrapper, or null), `stepKind`, `protocolEvent`, `reason`, `deadlineKind`, `cancelState`, `cancelReason`, `writePending`, `runUntracked`, `requestId` (an unmodifiable copy of exactly `request_id[0..request_id_len]`), and `hasTrackedRun`, `hasResult`, and `shouldCloseConnection` (`runUntracked && connection != null`). Each public enumeration names every frozen value of its namespace explicitly (the five produced event kinds; `INVALID` is never a produced event); there is no wildcard and no "unknown" member. A successful drive whose record breaks a frozen ABI v1 output invariant is a contract violation (`SasPairingContractException`, contract latch; cleanup stays allowed): event count above 17, an unknown or `INVALID` kind, an unknown value in any namespace, a flag bit other than `WRITE_PENDING` and `RUN_UNTRACKED`, `reserved != 0`, `request_id_len > 64` or a nonzero byte past it, a missing connection on `CONNECTION_ACCEPTED`, `CONNECTION_STEP`, or `CONNECTION_CLOSED` (or one on `ACCEPT_REFUSED` or `LISTENER_DISABLED`), a run, result, or flag on a non-step event, both a run and a result, `RUN_UNTRACKED` with a run, a duplicate accepted connection, a step or closed event for a connection the host does not hold, or a result handle already held. Dart does not rebuild the protocol state machine or judge a sequence; Rust stays authoritative. Request IDs are routing and correlation bytes only: never decoded, stringified as identity, or terminated.
  - **L. Connections.** `CONNECTION_ACCEPTED` creates exactly one `SasPairingConnection` for its native handle, held privately by the host; every later event of that handle carries the identical object. `CONNECTION_CLOSED` returns that wrapper already closed, removes it from the host, and invalidates its run references, with no native call. `SasPairingConnection.close()` is cleanup: allowed after FATAL, locally idempotent and consuming (the first call marks it closed, removes it, invalidates its run references, then makes exactly one `sas_pairing_connection_close` and throws a failure once; later calls do nothing). `OWNERSHIP_UNCERTAIN` from it means the loop failed closed: every connection of the host is closed and the state becomes `failedClosed` before the exception is thrown, with no sibling close call. `FATAL` from it latches FATAL; the connection stays closed. `LISTENER_DISABLED` closes no connection. A connection exposes only `isClosed` and `close()`: no handle, socket, peer identity, or run API.
  - **M. Parent cascade (extends P8-D-002 E).** Host close still makes exactly one `sas_pairing_host_destroy`, authority close one `sas_pairing_authority_release`, and runtime close one `sas_pairing_runtime_destroy`, with no detach, connection close, or child cleanup call first. In finally-style cleanup every descendant connection wrapper is closed, its run references invalidated, and every descendant host's network state becomes `detached`.
  - **N. Private run and result references.** Native run handles are kept package-privately, never exposed: one private reference per exact native run handle per connection, the same handle always mapping to the same reference, never re-targeted or identified by request ID. A reference is invalidated where the frozen rules make the run's end visible (§18.6): an event with a result, `STEP_INBOUND` with run 0 other than `START_DUPLICATE` (and other than `RUN_UNTRACKED`, whose path invalidates nothing), and `STEP_DEADLINE` with a request ID invalidate the connection's references under that request ID; a new handle first invalidates earlier references under its request ID, exactly as the native library does; and connection close, a closed event, detach, owner-loop failure, host close, and parent close invalidate all of the connection's references. Endings that the native contract leaves invisible are not guessed: a reference may be stale until P8.4 sees `RUN_ENDED`. `RUN_UNTRACKED` creates no reference and evicts nothing. Result handles are retained package-privately in a runtime-lifetime store, never destroyed, discarded, interpreted, or exposed by P8.3 (no `sas_pairing_result_destroy` call); connection close, detach, owner-loop failure, host close, and authority close leave them, and runtime close invalidates them because native runtime destroy drops them. `hasResult` means only that a local verified result exists and will be exposed by a later P8 increment: not peer success, peer receipt of the final message, a bilateral commit, or persisted trust.
  - **O. `RUN_UNTRACKED` guidance.** The flag is exposed as `runUntracked`, and `shouldCloseConnection` tells the consumer that it SHOULD call `event.connection?.close()` after consuming the batch, because no exact run handle exists for trusted local ceremony actions. Drive never closes it automatically: every event of the call must first be delivered, and a cleanup call could itself fail and lose them. Later orchestration may automate this as an explicit policy.
  - **P. No hidden machinery.** No native callback, `NativeCallable`, `ReceivePort`, listener thread, `Stream`, `Timer`, isolate, finalizer (for the network context, connections, or the socket token), protocol frame parsing or encoding, cryptography, SAS, ceremony action, public run or result API, discovery, or socket binding exists in the production package.
  - **Q. Private native network service.** One package-private service, `NativeNetworkApi`, owns all FFI memory for the five exports: the socket slot, the Bootstrap views and their byte copies, the 17 event records, `out_count`, and `out_failure`, all allocated for one synchronous call and freed before it returns. It copies every produced event record into a plain Dart value before returning and returns raw integers uninterpreted; no generated record or pointer reaches the high-level classes. Tests replace it with a deterministic fake.
- **Why:** the in/out slot is the only evidence of who owns the socket, so it is read before anything can throw. The return value and `out_failure` answer different questions (did the call run, did the loop fail during it), and the frozen contract requires the events of a failed loop to be delivered, so the loop failure is data in the batch rather than an exception. Mirroring the native invalidation locally, without issuing the cleanup calls the native parent or loop already performs, keeps the Dart object graph exactly as valid as the native one. Keeping exact run and result handles private now lets later increments wrap them without reconstructing identity from request IDs, connections, or event order.
- **Unchanged:** every P7 file, export, value, layout, and ownership rule; P8-D-001; P8-D-002 apart from the cascade extension in M.
- **Status:** decided by the owner for P8.3, 2026-10-04; implemented in `dart/lib/src/bootstrap.dart`, `network.dart`, `network_refs.dart`, `lifecycle.dart` (host network methods and the cascade extension), and `native/native_network_api.dart` / `native/native_process_context.dart` (P8.3, [evidence](README.md#p83-evidence)).

## P8-D-004 — Dart Run Identity, Explicit Ceremony Control, and SAS Binding

- **Inputs:** the nine trusted-local ceremony exports of the frozen ABI v1, all *normal* ([manifest §2](../p7-native-abi/abi-v1-manifest.md#2-exports-25): `sas_pairing_connection_start_initiator`, `sas_pairing_run_authorize_exposure`, `sas_pairing_run_expose_key`, `sas_pairing_run_presentation`, `sas_pairing_run_approve_sas`, `sas_pairing_run_emit_bootstrap_mac`, `sas_pairing_run_reject_sas`, `sas_pairing_run_cancel_sas`, `sas_pairing_run_emit_initiator_finish`); the action and presentation records and the refusal order ([ABI contract §20](../p7-native-abi/abi-contract.md#20-trusted-local-ceremony-control), [P7-D-011](../p7-native-abi/decisions.md#p7-d-011--trusted-local-ceremony-action-abi), [P7-D-012](../p7-native-abi/decisions.md#p7-d-012--sas-presentation-identity-binding-and-local-action-statuses)); run and connection handles ([§18.5–§18.7](../p7-native-abi/abi-contract.md#185-connection-handles), [P7-D-009](../p7-native-abi/decisions.md#p7-d-009--connection--run-reference-semantics)); run handle endings ([§20.9](../p7-native-abi/abi-contract.md#209-run-handles-and-endings)); the wrapper handoff ([§21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9) items 8–11); [P8-D-001](#p8-d-001--dart-native-binding-and-loader-architecture) to [P8-D-003](#p8-d-003--dart-windows-listener-cooperative-drive-and-connection-lifetime). Source facts that shape the design (the frozen `core/src/abi/control.rs` and `network.rs`, and the core's `windows_tcp.rs`, `windows_owner_loop.rs`, and `host.rs`): a start returns a new exact run handle but not the request ID the core generated; drive events report a run handle only on inbound steps, which always carry the run's request ID; native binds a local run after retiring the references under its request ID; a mutating action is refused with `WRITE_PENDING` before the host while the connection retains a frame, so a successful action's `WRITE_PENDING` flag is set exactly when that action (or its deadline's timeout CANCEL) produced a frame; an action that keeps its run live returns exactly the input handle (a different live run is a native FATAL), and `SAS_REJECTED`, `SAS_CANCELLED`, and `DEADLINE` return run `0`; `OWNERSHIP_UNCERTAIN` and `OWNER_LOOP_CLOSED` from any of the nine exports are reported only after the owner loop failed closed and every reference of the host was cleared (a core `OwnershipUncertain` refusal ends the session first, which the owner loop escalates to a loop failure); `RUN_ENDED` removes the run handle natively, after which the value is `INVALID_HANDLE`.
- **Decision (owner-selected in the P8.4 task):**
  - **A. Run.** One public `SasPairingRun` represents one exact native run handle of one `SasPairingConnection`. It holds that connection and the package-private `NativeRunRef` of the handle; the handle is never public.
  - **B. Identity.** Run identity is the exact native run handle, never the request ID, the ceremony identity, the connection plus a request ID, or event order. The request ID stays routing and correlation metadata.
  - **C. One object per handle.** A connection holds its runs in a private map keyed by the exact native handle. Every drive event and every local action that names the same live handle returns the identical `SasPairingRun`; no wrapper is made per event or per action.
  - **D. Request-ID reuse.** A new handle under a reused request ID is a new `SasPairingRun`; the earlier one is never retargeted. As in P8.3, a new handle first invalidates the connection's runs under that request ID (the native rule).
  - **E. Explicit steps.** Exposure authorization is not exposure, MATCH is not BOOTSTRAP_MAC emission, and BOOTSTRAP_MAC emission is not INITIATOR_FINISH emission. Each public method makes exactly one native call and never chains another action, a drive, a retry, or a close. There is no combined convenience action.
  - **F. No final ACK.** Dart never confirms the final ACK and has no API for it; the native TCP adapter confirms it after writing the whole frame, and the Initiator's result appears on a later drive (`STEP_CONFIRMED`).
  - **G. Presentation.** `presentation()` is read-only (it changes no state, refreshes no deadline, sends nothing) and is always sent to native, also while a write is pending: Dart never blocks it on a write-pending state of its own.
  - **H. Decisions bound to the presented identity.** `approveSas`, `rejectSas`, and `cancelSas` take one `SasPairingCeremonyIdentity`, exactly the 32 bytes a presentation returned; nothing else (request ID, handle, peer identity) substitutes for it. Dart does not check that an identity belongs to the run: an identity from another presentation reaches native, which returns `CEREMONY_IDENTITY_MISMATCH` and changes nothing.
  - **I. Display only.** Dart exposes the reviewed decimal display (`NNNN NNNN NNNN`) and the ceremony identity, never the raw six SAS bytes, a MAC, a proof, or a trust field. The decimal is comparison data: it authorizes, approves, and proves nothing, and the package never compares displays or decides MATCH; the application obtains a trusted-local user or policy choice and calls `approveSas`, `rejectSas`, or `cancelSas`.
  - **J. `WRITE_PENDING` status.** Native status `SAS_PAIRING_WRITE_PENDING` (205) from a mutating action means the requested action **did not run**: the connection still retains a frame. It is thrown as a `SasPairingNativeException`, no `SasPairingLocalAction` is returned, no state changes, and nothing is driven or retried automatically. The consumer drives, inspects the events, and retries only if still appropriate.
  - **K. `WRITE_PENDING` action flag.** `SasPairingLocalAction.writePending` (from `SAS_PAIRING_ACTION_FLAG_WRITE_PENDING`) on a successful action means the action **did run** and native now retains its output (or a deadline's timeout CANCEL) for a later drive. Nothing is driven automatically. Dart keeps no write-pending state that gates any call; native owns the outbound slot. J and K are never conflated.
  - **L. Known-ended runs.** `SasPairingRun.isEnded` is true once Dart knows the exact run can no longer be used: a visible terminal drive event (the P8.3 visibility rules), a successful terminal local action (`sasRejected`, `sasCancelled`, `deadline`), a `RUN_ENDED` status, connection close, a closed event, detach, owner-loop failure, `CONNECTION_ENDED`, host close, authority close, or runtime close. Every run method on a known-ended run throws `SasPairingRunEndedException` (the operation only, no handle, no native status) without a native call. The local known-ended check comes first, then process admission (the FATAL and contract latches), then the native call, matching the closed-wrapper precedence of P8-D-002.
  - **M. Invisible endings.** A run that ended without a visible event (P8-D-003 N; ABI contract §18.6) may stay locally live (`isEnded == false`). `isEnded == false` means only that Dart has not observed the end, not that native guarantees the run is live. Dart guesses no ending.
  - **N. First native `RUN_ENDED`.** When native returns `RUN_ENDED` (204) for a run Dart thought live, Dart marks that exact run ended, removes it from its connection, and throws the original `SasPairingNativeException` with status 204; the first native observation is never hidden. Later calls on that wrapper are local `SasPairingRunEndedException`s with no native call.
  - **O. Outcomes, not verdicts.** Ceremony and core refusals (`MISSING_AUTHORIZATION`, `BUSY`, `EXHAUSTED`, `NO_LIVE_SAS`, `CEREMONY_IDENTITY_MISMATCH`, `NOT_LOCALLY_APPROVED`, `NOT_INITIATOR`, `TRANSCRIPT_MISMATCH`, `CONNECTION_ENDED`, and every other status) are operation outcomes thrown with their exact status through the existing `SasPairingStatus` / `SasPairingNativeException` model, never trust verdicts. No `isAttack`, `peerMalicious`, `shouldTrustPeer`, or similar property exists, and a refusal is not assumed to have ended the run (native may have ended it; a later call then reports `RUN_ENDED`).
  - **P. No result contents.** P8.4 exposes no `PairingResult` content or ownership API. A local action never returns a result (`SasPairingLocalAction` has no result field); results still arrive only through drive events, are retained privately at runtime lifetime exactly as in P8-D-003 N, and are surfaced only as `event.hasResult`, which means local verified completion only (one local result never implies a peer result; [P6-D-005](../p6-remediation/decisions.md#p6-d-005--local-completion-and-final-ack-deadline-boundary)). No result is destroyed; runtime close remains the only path that drops them. P8.5 wraps results.
- **Rules chosen in P8.4:**
  1. **Public types.** `SasPairingRun` (`isEnded`, the seven run actions, `presentation()`), `SasPairingLocalAction` (`event`, `run`, `deadlineKind`, `writePending`; immutable, package-constructed), the enum `SasPairingLocalEvent` (exactly the twelve produced values: `initiatorStarted`, `exposureAuthorized`, `keyExposed`, `sasApproved`, `sasAlreadyApproved`, `bootstrapMacEmitted`, `bootstrapMacAlreadyEmitted`, `initiatorFinishEmitted`, `initiatorFinishAlreadyEmitted`, `sasRejected`, `sasCancelled`, `deadline`; `INVALID` is no member and the ABI values stay private), `SasPairingSasPresentation` (`ceremonyIdentity`, `decimal`; no public constructor), `SasPairingCeremonyIdentity` (exactly 32 bytes, defensively copied, exposed only as an unmodifiable view, value equality; no public constructor, obtained only from a presentation), and `SasPairingRunEndedException`. `SasPairingConnection` gains `startInitiator`; `SasPairingEvent` gains `SasPairingRun? run`, with `hasTrackedRun == (run != null)`. No run handle, `sas_pairing_action_t`, `sas_pairing_sas_presentation_t`, `Pointer`, raw flag, or raw local-event value is public.
  2. **Local Initiator start.** `SasPairingConnection.startInitiator({required SasPairingBootstrap local, SasPairingBootstrap? expected})` is a normal operation: a closed connection throws `SasPairingClosedException` without a native call; then process admission; then exactly one `sas_pairing_connection_start_initiator`. `local` is the explicit trusted-local Initiator configuration (not the listener's Responder Bootstrap); `expected == null` means no exact expected peer Bootstrap. Both reuse the P8.3 Bootstrap byte semantics and the same private marshaller as attach. No drive, authorization, or exposure follows. Success must be `INITIATOR_STARTED`, a nonzero handle that names no live run of the host, exactly the `WRITE_PENDING` flag, deadline kind `NONE`, and `reserved == 0`; then exactly one new `SasPairingRun` is created. A nonzero status creates no run.
  3. **Unknown request ID.** A locally started run is valid before Dart knows its request ID: its private reference starts with an unknown request ID, and Dart never fabricates or derives one. When a later drive event names that exact handle, its request ID is learned (and, mirroring the native start, the connection's other runs under that request ID are invalidated: the exact run is still bound natively, so none of them is live). The same request ID again changes nothing; a different request ID for the same handle is a frozen-contract violation (`SasPairingContractException`, contract latch). Until its request ID is known, a run cannot be retired by a request-ID ending: it stays locally live until an event names it, a local action returns `RUN_ENDED` or ends it, or its connection or a parent is torn down.
  4. **Action record validation.** Every successful action is checked before any state changes: `reserved == 0`, no flag bit other than `WRITE_PENDING`, a known local event, a known deadline kind (`NONE` for every event except `deadline`, never `NONE` for `deadline`), and an outcome allowed for the called method:

     | Method | Allowed successes (run; `writePending`) |
     |---|---|
     | `startInitiator` | `initiatorStarted` (new run; true) |
     | `authorizeExposure` | `exposureAuthorized` (same run; false) |
     | `exposeKey` | `keyExposed` (same run; true) |
     | `approveSas` | `sasApproved`, `sasAlreadyApproved` (same run; false) |
     | `emitBootstrapMac` | `bootstrapMacEmitted` (same run; true), `bootstrapMacAlreadyEmitted` (same run; false) |
     | `rejectSas` | `sasRejected` (run 0; either) |
     | `cancelSas` | `sasCancelled` (run 0; either) |
     | `emitInitiatorFinish` | `initiatorFinishEmitted` (same run; true), `initiatorFinishAlreadyEmitted` (same run; false) |
     | every run action | `deadline` (run 0; either; deadline kind not `NONE`) |

     "Same run" requires the returned handle to equal the input handle and returns the identical `SasPairingRun`; a different nonzero handle is a contract violation. A terminal success marks the input run ended and removes it before returning, with `action.run == null`. Anything else (a known but wrong event, `INVALID`, an unknown value, a wrong flag) is a contract violation.
  5. **Presentation record validation.** `available` must be 0 or 1, `reserved` 0, and both `reserved_tail` bytes 0. `available == 0` requires every identity and decimal byte to be 0 and returns `null`. `available == 1` requires exactly 14 ASCII bytes with a space (`0x20`) at offsets 4 and 9 and an ASCII digit (`0x30`–`0x39`) everywhere else (no terminator, other whitespace, or non-ASCII digit) and returns an immutable `SasPairingSasPresentation`. Anything else is a contract violation.
  6. **Status side effects (one package-private handler).** Before a nonzero status is thrown, only the frozen lifecycle effects are applied: `RUN_ENDED` ends the target run; `CONNECTION_ENDED` (405) closes the connection wrapper locally, ends every run of it, and removes it from its host, with no `sas_pairing_connection_close`; `OWNERSHIP_UNCERTAIN` and `OWNER_LOOP_CLOSED` close every connection of the host, end every run, and set the network state `failedClosed`, with no cleanup call; `SAS_PAIRING_FATAL` latches the process FATAL latch through the existing status check and implies no ending (cleanup stays available); `WRITE_PENDING` and every ceremony or core refusal change nothing.
  7. **No accounting in Dart.** Dart caches no authorization, opportunity count, guard ownership, spent state, or expected budget. `authorizeExposure()` records fresh ceremony-specific consent only (it exposes, reserves, spends, and sends nothing). **`exposeKey()` is the security-spending step**: native atomically consumes the authorization, reserves the guard and one opportunity, and produces the key frame; nothing in Dart (a retry, reject, cancel, close, or teardown) refunds it. The authority status snapshot of P8.2 stays the only budget view.
  8. **Private native ceremony service.** One package-private `NativeCeremonyApi` (production `FfiNativeCeremonyApi`, built over the same `LoadedNativeLibrary.bindings` and held by the same `NativeProcessContext`) owns all FFI memory of the nine exports: one zeroed `sas_pairing_action_t` or `sas_pairing_sas_presentation_t` per call, the 32 identity bytes (exactly 32, no terminator), and the Bootstrap views (the P8.3 marshaller, moved into one shared private file and reused by attach and start), all freed before the call returns. On `SAS_PAIRING_OK` it copies the record into a plain immutable Dart value; on any other status it returns none, so a zeroed record is never read as an action. No generated record or pointer leaves the service.
- **Why:** the exact native handle is the only identity native accepts for a run, and a local start does not return a request ID, so request IDs can be learned but never be identity. Treating the status 205 and the flag 0x1 as two different facts keeps "retry later" from being confused with "drive now". Refusing known-ended runs locally while letting the first native `RUN_ENDED` surface keeps both the native truth and the local fail-closed behavior. Binding decisions to an identity object that only a presentation can produce makes the safe flow the easy one, while the native identity check stays authoritative.
- **Unchanged:** every P7 file, export, value, layout, and ownership rule; P8-D-001; P8-D-002; P8-D-003 apart from the run references now backing public `SasPairingRun` objects (A–D, L–N above), the unknown-request-ID start (rule 3), and the shared Bootstrap marshaller (rule 8). Result retention (P8-D-003 N) is unchanged.
- **Status:** decided by the owner for P8.4, 2026-10-04; implemented in `dart/lib/src/ceremony.dart` (a part of `network.dart`), `network.dart` (run map, `SasPairingEvent.run`, `startInitiator`), `network_refs.dart`, `exceptions.dart`, and `native/native_ceremony_api.dart` / `native/native_bootstrap.dart` / `native/native_process_context.dart` (P8.4, [evidence](README.md#p84-evidence)).
