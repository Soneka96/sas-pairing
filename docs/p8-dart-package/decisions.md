# P8 Owner Decisions

Stable owner decisions taken during P8. IDs `P8-D-NNN` are never reused. A decision records policy and its rationale; the [P8 package README](README.md) tracks implementation and evidence. ## P8-D-001 — Dart Native Binding and Loader Architecture

- **Inputs:** the frozen ABI v1 surface (version 1, 25 exports, 48 statuses, 84 namespace values, 11 scalar constants, 6 records; [manifest](../p7-native-abi/abi-v1-manifest.md), [`sas_pairing.h`](../../core/include/sas_pairing.h)); the loader invariant of [P7-D-002](../p7-native-abi/decisions.md#p7-d-002--native-library-residency-and-loader-lifetime) and [ABI contract §14](../p7-native-abi/abi-contract.md#14-native-library-loading-and-residency) (one native image per OS process, resident until exit, no unload, reload, or alternate copy, process restart as the only recovery from `SAS_PAIRING_FATAL`); the wrapper handoff of [P7-D-013](../p7-native-abi/decisions.md#p7-d-013--abi-v1-final-freeze-and-wrapper-handoff) item 13 and [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9); the drive, run, result, and ceremony-control rules of [P7-D-008](../p7-native-abi/decisions.md#p7-d-008--bounded-drive-and-foreign-event-model) to [P7-D-012](../p7-native-abi/decisions.md#p7-d-012--sas-presentation-identity-binding-and-local-action-statuses), which later P8 increments wrap. `dart:ffi` facts that shape the design: `DynamicLibrary.open` of the same file loads it into the VM process once, even across isolates; `DynamicLibrary.close()` exists (Dart 3.1+) and may let the OS unload the library; Dart statics are isolate-local, not process-global.
- **Decision (owner-selected in the P8.1 task):**
  - **A.** `dart/` is one pure-Dart package named `sas_pairing` (version `0.1.0-dev.1`, `publish_to: none`). It does not depend on Flutter; a pure-Dart package stays usable from Flutter applications.
  - **B.** P8 binds the one frozen native ABI v1. It adds, renames, or changes no export, signature, status, record, or ownership rule, and adds no Dart-specific native helper.
  - **C.** The raw FFI layer is generated by `ffigen` from `core/include/sas_pairing.h` into `dart/lib/src/native/generated/sas_pairing_bindings.g.dart` (class `SasPairingNativeBindings`), committed, and reproducible. It is the only raw C declaration layer: no handwritten `lookupFunction` copy or second set of signatures exists. Every declaration is listed explicitly in `dart/ffigen.yaml` and everything else is excluded, so a future header addition needs conscious P8 work.
  - **D.** The raw layer stays private under `lib/src/native/` and is not exported from `lib/sas_pairing.dart`, which exports nothing in P8.1. No `Pointer`, `DynamicLibrary`, generated `Struct`, allocator helper, or native callback is part of the public API now or as the basis of the later one.
  - **E.** The high-level Dart API wraps this private layer in later P8 increments (P8.2 onwards).
  - **F.** Exactly one supported native library image is loaded for the process.
  - **G.** The package retains the `DynamicLibrary` (and the one `SasPairingNativeBindings` built over it) for the process lifetime, strongly referenced from package-private state.
  - **H.** There is no unload, close, dispose, reload, native reset, replace, or recovery by opening another copy; the package never calls `DynamicLibrary.close()`, and no `Finalizer` or `NativeFinalizer` touches the library.
  - **I.** Recovery from `SAS_PAIRING_FATAL` (and from a loaded image that failed verification) means an OS process restart.
  - **J.** The native ABI version must be exactly `1`. The required version is a Dart literal checked against the header and the manifest by tests, not the header macro itself, so a header that changed its version fails the build instead of being accepted.
  - **K.** P8.1 does not bundle or distribute native binaries: no committed `.dll` or `.so`, no package asset, no native-assets build hook, no download.
  - **L.** The native binary location is supplied explicitly: `NativeLibraryLoader.initialize(libraryPath: ...)` takes an absolute path to an existing file. There is no search path, working-directory scan, alternate file name, fallback directory, download, or runtime Rust build. Discovery and packaging are a later P8 decision.
  - **M.** P8.1 adds no protocol or cryptographic implementation in Dart: no SAS, MAC, hash, DH, request ID, ceremony identity, frame encoding or decoding, transcript, final ACK, timeout, security budget, or START limiting. Rust stays authoritative; no native status is interpreted as a trust verdict.
  - **N.** Supported direct native ownership is one Dart owner isolate per OS process. Other isolates do not load the library or call the bindings themselves; they talk to the owner at a higher layer or do not use the native package. P8.1 builds no isolate façade, and the loader is not claimed to be process-global: a Dart static cannot stop another isolate from opening an image. A later isolate-facing façade needs its own decision.
  - **O.** P8 claims pairing transport support only where P7 does: Windows TCP. The package loads and tests the same ABI v1 library on Linux, which is not Linux pairing support: there pairing operations fail closed with `SAS_PAIRING_UNSUPPORTED_PLATFORM` as P7 defines.
- **Loader rules chosen in P8.1:**
  1. **Initialization order.** (1) The process pointer width must be 8 bytes (the frozen layouts are 64-bit), else failure before any path work; (2) the path must be non-empty, absolute, and an existing file, else failure; (3) it is canonicalized (`resolveSymbolicLinksSync`); (4) exactly one `DynamicLibrary.open` of the canonical path; (5) the image is retained; (6) all 25 frozen exports are preflighted by exact name with `providesSymbol` (a lookup, never a call); (7) the generated bindings are built; (8) `sas_pairing_abi_version()` is called, the only native call during initialization; (9) it must return `1`; (10) the ready library is published. No stateful export is called.
  2. **Failure before an image is loaded** (pointer width, path, or an OS load error from `DynamicLibrary.open`) leaves the loader uninitialized with nothing retained; a later attempt may try again.
  3. **Failure after an image is loaded** (a missing export, version `0`, a version other than `1`, or an unexpected error while binding or verifying) is permanent for the process: the image stays referenced, no other library is ever opened, every later `initialize` and `instance` rethrows the same exception, and its message says to correct the native library and restart the OS process. Version `0` means the version query itself caught a panic; it is never "an old ABI" or "try again". A missing export is never optional, and no partial binding is kept.
  4. **Second initialization.** Once ready, `initialize` returns the identical `LoadedNativeLibrary` (and bindings) without inspecting its new `libraryPath` argument or opening anything, so no path swap is possible. Chosen over rejection because initialization stays idempotent for one owner isolate while the path is never re-read.
  5. **Tests never reset the process loader.** There is no `resetForTesting` or similar. State-machine tests construct their own `NativeLibraryLoader` over a fake platform, which never touches the isolate's process loader; scenarios that need a fresh real loader run in a child OS process.
- **Generation and toolchain choices:** `ffigen` is pinned exactly (`22.0.0`) with the YAML configuration (deprecated from `ffigen` 22.1, so a future upgrade must move to the Dart configuration API and regenerate byte-identically); CI uses the exact Dart SDK the bindings were generated and formatted with (`3.13.4`); the package's SDK constraint is `^3.11.0`, the lowest that `package:test` 1.32 (the newest of the four dependencies' minimums) allows. Records are named by their C typedef names (`sas_pairing_event_t`, ...), exactly as in the manifest, because the struct tag `sas_pairing_result_info` collides with the export of the same name. Every preprocessor constant is generated faithfully (`SAS_PAIRING_SOCKET_INVALID`, `UINTPTR_MAX`, is the all-ones pattern that a Dart `int` reads as `-1` on the 64-bit target), so the private ABI table in `lib/src/native/abi_v1.dart` refers to the generated constants and is checked against the manifest row by row; there is no unchecked hand-copied value list.
- **Why:** generating the one declaration layer from the frozen header, and checking it against the frozen manifest, makes accidental drift a test failure instead of a silent incompatibility. Keeping it private leaves the public API free to be designed around Dart objects rather than pointers. An explicit path with no discovery keeps the "one image" decision with the application until distribution is decided. Distinguishing pre-load from post-load failure follows P7-D-002 exactly: before an image exists nothing needs undoing, and after it exists nothing can be undone.
- **Unchanged:** every P7 file, export, signature, value, layout, and ownership rule (ABI v1 frozen by P7-D-013); the frozen protocol candidate.
- **Status:** decided by the owner for P8.1, 2026-10-03; implemented in `dart/` (P8.1).

## P8-D-002 — Dart Lifecycle Ownership and Fail-Closed State

- **Inputs:** the seven lifecycle exports of the frozen ABI v1 and their fatal classes ([manifest §2](../p7-native-abi/abi-v1-manifest.md#2-exports-25): `sas_pairing_runtime_create`, `sas_pairing_authority_register`, `sas_pairing_authority_status`, and `sas_pairing_host_create` are *normal*; `sas_pairing_runtime_destroy`, `sas_pairing_authority_release`, and `sas_pairing_host_destroy` are *cleanup*); the runtime lifecycle and fatal semantics ([ABI contract §5, §6](../p7-native-abi/abi-contract.md#5-runtime-lifecycle)); authorities ([§15](../p7-native-abi/abi-contract.md#15-authorities): a released authority handle and all of its host handles are invalid forever *whatever the result*; process-session accounting outlives every handle and runtime); hosting contexts ([§16](../p7-native-abi/abi-contract.md#16-hosting-contexts): a destroyed host handle is invalid forever *whatever is returned*; authority release and runtime destroy cascade to their hosts natively); [P8-D-001](#p8-d-001--dart-native-binding-and-loader-architecture) (one process loader, one owner isolate, no reset); [ABI contract §21](../p7-native-abi/abi-contract.md#21-wrapper-handoff-p8-p9) items 3, 4, and 11.
- **Decision (owner-selected in the P8.2 task):**
  - **A. Public lifecycle types.** `SasPairingRuntime`, `SasPairingAuthority`, `SasPairingHost`, the immutable `SasPairingAuthorityStatus` with the enum `SasPairingAuthorityState` (`ready`, `busy`, `exhausted`), the enum `SasPairingStatus` (all 48 frozen statuses), and the exceptions `SasPairingNativeException`, `SasPairingClosedException`, and `SasPairingContractException`. Nothing else is exported: no raw handle, `Pointer`, `DynamicLibrary`, generated `Struct`, `SasPairingNativeBindings`, `NativeLibraryLoader`, or the private native lifecycle service. Every call is synchronous: no `Future`, `Stream`, `Timer`, or `Isolate`.
  - **B. Runtime factory.** `SasPairingRuntime.create(nativeLibraryPath: ...)` initializes the P8.1 process loader (once ready it returns the identical library and opens nothing), takes the one package-private *process context* associated with that loaded image, refuses locally if the context is latched (G, H), then calls `sas_pairing_runtime_create` and requires `SAS_PAIRING_OK` and a nonzero handle. A `SasPairingRuntime` is one native runtime lifetime, not the process security session: after `close()` a later `create` may make a new native runtime over the same image, but it never reloads, reopens, or replaces the image, never clears a latch, and never resets accounting. A second live runtime is never aliased: native `SAS_PAIRING_ALREADY_INITIALIZED` is thrown as a `SasPairingNativeException`.
  - **C. Normal and cleanup operations.** Normal: runtime create, authority register, authority status, host create. Cleanup: runtime destroy (`SasPairingRuntime.close`), authority release (`SasPairingAuthority.close`), host destroy (`SasPairingHost.close`). This is exactly the manifest fatal classification of these seven exports.
  - **D. Ownership.** `SasPairingRuntime` owns its `SasPairingAuthority` wrappers and each `SasPairingAuthority` owns its `SasPairingHost` wrappers, in private per-parent collections (nothing is stored globally). A child wrapper exists only after its native creation returned `SAS_PAIRING_OK` with a nonzero handle; a failed creation makes no wrapper. Handles stay private fields. Wrappers use ordinary object identity: no equality, hash code, `toString`, exception, or debug text is derived from a handle, scope, or parent.
  - **E. Explicit, idempotent, consuming close.** Each wrapper has `void close()` and `bool get isClosed`. There is no `Finalizer` or `NativeFinalizer`, so callers close explicitly (`try`/`finally`). The first `close()` marks the wrapper closed, makes exactly one native cleanup call, and then performs the local cascade, whatever the call returned (also if it threw): native handles are consumed by their cleanup call and are not retryable cleanup tokens. A failing status is then thrown once as a `SasPairingNativeException`. A later `close()` makes no native call and throws nothing. Host close removes the host from its authority and never releases the authority. Authority close calls `sas_pairing_authority_release` once, never `sas_pairing_host_destroy` for its hosts first, then marks every child host closed and leaves its runtime. Runtime close calls `sas_pairing_runtime_destroy` once, never authority release or host destroy first, then marks every authority and host closed. Dart mirrors the invalidation of the native cascade and never duplicates its cleanup calls.
  - **F. Local closed state.** A normal operation on a closed wrapper, including one closed by its parent's cascade, throws `SasPairingClosedException` (object kind and operation, no handle) before any native call.
  - **G. Native FATAL latch.** Any lifecycle call, normal or cleanup, that returns `SAS_PAIRING_FATAL` (900) sets a fatal latch in the process context. The latch lives below every runtime, so closing or recreating a runtime and closing wrappers never clear it. While it is set, every normal operation, `SasPairingRuntime.create` included, throws a `SasPairingNativeException` with status 900 without a native call (P7: no normal re-entry after FATAL), while cleanup of a still-open wrapper still makes its one native call (native cleanup stays admitted after FATAL). Only status 900 sets the latch. There is no `clearFatal`, reset, reopen, reload, or recovery API: the only recovery is an OS process restart.
  - **H. Contract-violation latch.** `SAS_PAIRING_OK` with an output that breaks a frozen success invariant (a zero handle from runtime create, authority register, or host create; authority state `INVALID` or an unknown state value; `READY` with 0 remaining; `BUSY` or `EXHAUSTED` with a nonzero remaining) throws `SasPairingContractException` and marks the process context unusable for normal operations: ABI version 1 claimed success without obeying its contract. Later normal operations throw `SasPairingContractException` without a native call; cleanup of existing wrappers stays allowed; a process restart is required. No zero handle is ever wrapped, and no fourth authority state is invented.
  - **I. Status model.** `SasPairingStatus` has one value per frozen status with its exact `code`, checked against the private P8.1 table; `SasPairingStatus.fromCode` returns `null` for an unknown code. Every nonzero status, known or not, is a failure: an unknown code is thrown as a `SasPairingNativeException` with its integer preserved and `knownStatus == null`, never treated as success or as fatal. `SasPairingNativeException.processRestartRequired` is true exactly for status 900. Frozen native outcomes (`BUSY`, `EXHAUSTED`, `OWNERSHIP_UNAVAILABLE`, `OWNERSHIP_UNCERTAIN`, `UNSUPPORTED_PLATFORM`, and the rest) are always a `SasPairingNativeException` with their exact status, never a vague `StateError`. Statuses and exceptions are operation outcomes, never trust verdicts, peer-malice verdicts, authentication policy, or consumer authorization, and no such property exists.
  - **J. Authority scope.** `registerAuthority(Uint8List scope)` takes arbitrary bytes. They are copied exactly into temporary native memory for the one call and passed as pointer plus length; an empty scope is passed as a null pointer with length 0 so that the native core decides (`INVALID_SCOPE`). No text encoding, NUL terminator, C-string handling, Dart-side scope validation, or retention of the caller's buffer.
  - **K. Authority status.** `queryStatus()` returns an immutable `SasPairingAuthorityStatus(state, remainingOpportunities)`: native `READY` → `ready` with the reported remaining, `BUSY` → `busy` with 0, `EXHAUSTED` → `exhausted` with 0. `SasPairingAuthorityState` is successful status data and stays separate from the failure status `SasPairingStatus.busy` (105). Dart caches or reconstructs no budget, guard, or START limiter; the native core stays authoritative.
  - **L. Native lifecycle service.** One private service, `NativeLifecycleApi`, is the only P8.2 code that touches FFI memory: it allocates the typed output slots (`Uint64` handles, `Uint32` state and remaining) and the scope copy, makes the one generated-binding call, and frees everything before it returns, so no allocation outlives a call. It is not a second declaration layer (the generated bindings stay the only one), and it keeps the lifecycle classes free of `Pointer`. Tests replace it with a deterministic fake; the production loader gains no test reset.
  - **M. Loader failures.** `SasPairingRuntime.create` lets a loader failure through unchanged (the P8.1 `NativeLibraryInitializationException`, whose message says whether a process restart is required). Its public type is decided together with native artifact distribution; P8.2 exports nothing from `lib/src/native/`.
- **Why:** native cleanup consumes its handle whatever it returns, so a Dart wrapper that stayed open after a failed cleanup would hold a dead handle and invite a retry the ABI does not define. Mirroring the native cascade locally, without issuing child cleanup calls that the native parent already performs, keeps the Dart object graph exactly as valid as the native one. Latching FATAL and contract violations below the runtime keeps the P7 rule that nothing normal re-enters native code after FATAL and that no runtime recreation is a security reset.
- **Unchanged:** every P7 file, export, value, layout, and ownership rule; P8-D-001 (loader, one owner isolate, no unload or reset).
- **Status:** decided by the owner for P8.2, 2026-10-03; implemented in `dart/lib/src/lifecycle.dart`, `status.dart`, `exceptions.dart`, and `native/native_lifecycle_api.dart` / `native/native_process_context.dart` (P8.2, [evidence](README.md#p82-evidence)).
