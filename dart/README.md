# `sas_pairing` (Dart)

Experimental, pre-alpha Dart package for the sas-pairing native core. **Not production-security approved, not audited, not formally verified.** Do not use it to protect production systems.

**Status: P8 IN PROGRESS — P8.3 COMPLETE.** The package binds the frozen [native ABI v1](../docs/p7-native-abi/abi-v1-manifest.md) and offers the native **lifecycle** API (runtime, authority, and host objects with a status and exception model) and, on Windows, the **listener ownership transfer and cooperative network driver** (attach an already-bound listening socket, drive the host one bounded call at a time, read events, close connections). **There is no ceremony, SAS, run, or result API yet**; it starts in P8.4. See the [P8 package](../docs/p8-dart-package/README.md), [P8-D-001](../docs/p8-dart-package/decisions.md#p8-d-001--dart-native-binding-and-loader-architecture), [P8-D-002](../docs/p8-dart-package/decisions.md#p8-d-002--dart-lifecycle-ownership-and-fail-closed-state), and [P8-D-003](../docs/p8-dart-package/decisions.md#p8-d-003--dart-windows-listener-cooperative-drive-and-connection-lifetime).

## What exists

- A pure-Dart package (`sas_pairing`, version `0.1.0-dev.1`, not published; no Flutter dependency, so it stays usable from Flutter applications). Its one runtime dependency is `package:ffi`.
- The public library `package:sas_pairing/sas_pairing.dart`: `SasPairingRuntime`, `SasPairingAuthority`, `SasPairingHost`, `SasPairingAuthorityStatus` with `SasPairingAuthorityState`, `SasPairingStatus`, and the exceptions `SasPairingInitializationException` (with `SasPairingInitializationFailure`), `SasPairingNativeException`, `SasPairingClosedException`, and `SasPairingContractException`; since P8.3 also `SasPairingBootstrap`, `SasPairingWindowsListenerSocket`, `SasPairingHostNetworkState`, `SasPairingConnection`, `SasPairingDriveBatch`, `SasPairingDriveFailure`, `SasPairingEvent`, and the event enums (`SasPairingEventKind`, `SasPairingStepKind`, `SasPairingProtocolEvent`, `SasPairingEventReason`, `SasPairingDeadlineKind`, `SasPairingCancelState`, `SasPairingCancelReason`), with `attachWindowsListener`, `detachListener`, `drive`, `recheckAfterResume`, and `networkState` on `SasPairingHost`. All calls are synchronous.
- Private raw bindings under `lib/src/native/`, generated by `ffigen` from the frozen header [`core/include/sas_pairing.h`](../core/include/sas_pairing.h), and a private process-lifetime native-library loader that opens one native image from an explicit path, preflights all 25 exports, and requires `sas_pairing_abi_version() == 1`. Raw FFI types, pointers, native handles (runtime, authority, host, connection, run, result), raw sockets, native event records, the `DynamicLibrary`, and the loader are never exported.

## Lifecycle

```dart
import 'dart:typed_data';

import 'package:sas_pairing/sas_pairing.dart';

void main() {
  final runtime = SasPairingRuntime.create(
    nativeLibraryPath: r'C:\path\to\sas_pairing_core.dll', // absolute; nothing is searched for
  );
  try {
    // A scope is arbitrary bytes, not text; it is copied for the call and not kept.
    final authority = runtime.registerAuthority(
      Uint8List.fromList([0x61, 0x70, 0x70, 0x00, 0x01]),
    );
    try {
      final status = authority.queryStatus();
      print('${status.state.name}, ${status.remainingOpportunities} remaining');

      final host = authority.createHost(); // no networking happens
      try {
        // Attach a listener and drive the host: see "Network (Windows, P8.3)" below.
      } finally {
        host.close();
      }
    } finally {
      authority.close(); // also closes any host still open
    }
  } on SasPairingNativeException catch (e) {
    print('${e.operation}: native status ${e.statusCode} (${e.knownStatus?.name})');
    if (e.processRestartRequired) {
      // SAS_PAIRING_FATAL: restart the OS process.
    }
    rethrow;
  } finally {
    runtime.close(); // also closes every authority and host still open
  }
}
```

- **Close explicitly.** No finalizer cleans up native objects. Use `try`/`finally`, closing children before parents, or rely on a parent's `close()`.
- **`close()` is locally idempotent and consuming.** The first call makes exactly one native cleanup call and marks the object closed **even if that cleanup reports an error** (for example `ownershipUncertain`): native handles are not retryable cleanup tokens, so the error is thrown once and never retried. Later calls do nothing.
- **Closing a parent closes its children.** `SasPairingAuthority.close()` makes one native release, which already destroys its hosts natively; its `SasPairingHost` objects are then closed, without separate host cleanup calls. `SasPairingRuntime.close()` makes one native destroy, which already releases its authorities and destroys their hosts; every authority and host object is then closed. `SasPairingHost.close()` never releases its authority.
- **Closed objects fail locally.** A normal operation on a closed object throws `SasPairingClosedException` without entering native code.
- **One live runtime.** A second `SasPairingRuntime.create` while one is open throws `SasPairingNativeException` (`alreadyInitialized`); the open runtime is never handed out again.
- **A runtime is not a security reset.** Closing a runtime and creating a new one reuses the same loaded native library and resets nothing: authority opportunity accounting, the START limiter, and every other process-session security state continue. Registering a scope again continues its budget.
- **`queryStatus()` reports native state.** `ready` with the remaining opportunities (1–10), or `busy` / `exhausted` with 0; any other successful answer is a `SasPairingContractException`. The native core stays authoritative; Dart only checks each answer and keeps no accounting copy. `SasPairingAuthorityState.busy` is a state, not the failure status `SasPairingStatus.busy`.

## Network (Windows, P8.3)

The host can take over one already-bound Windows listening socket and is then driven cooperatively: every call is synchronous and bounded, and nothing runs in the background. See [P8-D-003](../docs/p8-dart-package/decisions.md#p8-d-003--dart-windows-listener-cooperative-drive-and-connection-lifetime).

**Obtaining the socket is an advanced integration boundary.** The package does not bind, listen, choose an address, interface, port, or IP version, or configure discovery or a firewall, and it has no bind helper. Your application creates a TCP socket, binds it, and calls `listen` on it (through WinSock), then hands its raw `SOCKET` value over. The socket, its address, and its port are not peer identity, authentication, or trust.

```dart
import 'dart:typed_data';

import 'package:sas_pairing/sas_pairing.dart';

/// [alreadyBoundSocket]: a raw Windows SOCKET your application bound and put into the
/// listening state, owned exclusively by you and used by nobody else.
void serveOnce(SasPairingHost host, int alreadyBoundSocket, SasPairingBootstrap local) {
  final listener = SasPairingWindowsListenerSocket.fromNativeSocket(alreadyBoundSocket);
  try {
    host.attachWindowsListener(listener: listener, local: local); // no drive, no accept
  } finally {
    if (!listener.isTransferred) {
      // The attach failed before the native library took the socket: it is still yours.
      // closesocket(alreadyBoundSocket) here, through your own WinSock code.
    }
    // Once listener.isTransferred is true, never close or use that socket value again.
  }
  try {
    final batch = host.drive(); // ONE bounded native call (it may wait up to ~250 ms)
    for (final event in batch.events) {
      // Consume every event, in order, also when batch.failure is set.
      print('${event.kind.name} ${event.stepKind.name} ${event.reason.name}');
      if (event.hasResult) {
        // A local verified result exists (exposed by a later version): this endpoint
        // completed locally. It does NOT mean the peer succeeded or stored anything.
      }
    }
    for (final event in batch.events) {
      if (event.shouldCloseConnection) event.connection?.close(); // RUN_UNTRACKED guidance
    }
    final failure = batch.failure;
    if (failure != null) {
      // The owner loop failed closed after producing the events above.
      if (failure.processRestartRequired) {
        // SAS_PAIRING_FATAL: clean up, then restart the OS process.
      }
    }
  } finally {
    host.detachListener(); // closes the listener and every connection natively
  }
}

SasPairingBootstrap exampleBootstrap(Uint8List publicKey) => SasPairingBootstrap(
  applicationIdentity: Uint8List.fromList('my-app'.codeUnits),
  keyAlgorithm: Uint8List.fromList('x25519'.codeUnits),
  publicKey: publicKey,
  sharedContext: Uint8List(0),
);
```

- **Bootstrap.** `SasPairingBootstrap` is four byte fields (`applicationIdentity`, `keyAlgorithm`, `publicKey`, `sharedContext`), copied when created and readable only through unmodifiable views. Dart does not validate it; the native core does, and refuses an invalid one with `invalidBootstrap`.
- **Socket ownership follows `isTransferred`.** While it is false (also after a failed attach such as `invalidBootstrap`, `listenerAlreadyAttached`, or `unsupportedPlatform`) the socket is yours to close. Once it is true (success, or `listenerSetupFailed` or `fatal` after the native library took the socket) never close, use, or hand on that socket value again; a transferred token cannot be attached again.
- **`drive()` is one bounded call, and you decide the cadence.** It makes exactly one native drive: deadline sweeps, at most one readiness wait of at most about 250 ms, at most one socket operation per connection, at most one accept. There is no background thread, timer, stream, isolate, or callback, and no stream API yet. Because the call blocks, do not call it blindly on a Flutter UI isolate, and never spin `while (true) host.drive();` without a scheduling or yield policy: persistent readiness can make calls return at once. All native access stays on one owner isolate.
- **`recheckAfterResume()`** makes one deadline sweep with no socket work, for trusted code that observed an OS resume notification. The package does not detect resume and never calls it by itself.
- **A nonzero native result is an exception; an owner-loop failure is data.** `drive()` throws `SasPairingNativeException` when the call itself failed (for example `listenerNotAttached`, `handlesExhausted`, or `fatal`) and then returns no events. When the call ran but the owner loop failed during it, `batch.failure` is set (`networkPollFailed`, `ownershipUncertain`, `ownerLoopClosed`, or `fatal`) and **every event of the batch is still valid and must be consumed**. Afterwards the network state is `failedClosed` and every connection is closed: call `detachListener()` or close the host. When the failure is `fatal`, restart the process after cleanup.
- **`RUN_UNTRACKED`: close that connection.** When `event.runUntracked` is true, `event.shouldCloseConnection` is true: after consuming the batch, call `event.connection?.close()`. The run exists in the native core but has no exact run handle, so no trusted local ceremony action could ever target it. The drive never closes it for you, so that no event of the call is lost and a failing cleanup cannot hide the batch.
- **`writePending`** means the connection still holds one outbound frame, which the native library writes itself on a later drive. It is not a failure or a trust signal.
- **Network states stay distinct.** `detached`: no network context. `attached`: listener and owner loop running. `listenerDisabled`: the listening socket is gone and nothing new is accepted, but existing connections continue and may still be driven; to replace the listener, call `detachListener()` and attach a new socket. `failedClosed`: the owner loop is gone and every connection is closed.
- **Connections.** Each accepted connection is one `SasPairingConnection`, and every event of that connection carries the same object. It is closed by `close()` (one native call, consuming, never retried; allowed after `fatal`), by its `connectionClosed` event, by `detachListener()`, by an owner-loop failure, or by closing its host or a parent. It exposes no handle, socket, or peer identity.
- **Request IDs** are exact routing and correlation bytes (0–64), never text, identity, or authentication.
- **No ceremony API yet.** There is no SAS, exposure, MATCH, REJECT, CANCEL, run, or result API in this version; it comes in later P8 increments.

## Errors

Four exception classes, kept distinct:

- **`SasPairingInitializationException`**: `SasPairingRuntime.create` could not load or set up the native library; `failure` (a `SasPairingInitializationFailure`) says why and `message` gives the detail. It has no native status. With `processRestartRequired == false` (`unsupportedPointerWidth`, `invalidLibraryPath`, `openFailed`) no library image was kept: correct the cause and call `create` again. With `processRestartRequired == true` (`missingSymbol`, `abiVersionQueryFailed`, `abiVersionMismatch`, `verificationFailed`) a library image is already loaded and cannot be replaced: every later `create` fails the same way; correct the library and restart the OS process.
- **`SasPairingNativeException`**: a native operation returned a nonzero status. `statusCode` is the exact value, including codes ABI v1 does not define (`knownStatus` is then `null`). Frozen outcomes such as `busy`, `exhausted`, `ownershipUnavailable`, `ownershipUncertain`, and `unsupportedPlatform` are always reported this way. Status `fatal` (900) requires an OS process restart (below).
- **`SasPairingClosedException`**: an operation on an object that is already closed. Raised locally.
- **`SasPairingContractException`**: the native library reported success but broke the frozen ABI v1 contract (for example a zero handle, or `ready` with more than 10 remaining). Every later normal operation is refused; closing existing objects stays allowed; restart the process with a correct library.
- **Statuses are not trust verdicts.** A status or exception is the outcome of one operation. It never says that a peer is trusted or malicious, that an attack happened, or that anything is authorized.

## `SAS_PAIRING_FATAL` means restart the OS process

If any native call reports `SAS_PAIRING_FATAL` (`SasPairingStatus.fatal`, `processRestartRequired == true`), the package permanently refuses every new or normal operation in this process, `SasPairingRuntime.create` included, without entering native code again. Closing existing objects still works. There is no reset, reload, or recovery API, and creating a new runtime is not recovery: restart the OS process.

## Rules the package keeps

- **No protocol in Dart.** The native Rust core implements the protocol and its cryptography. This package implements no SAS, MAC, hash, key agreement, request ID, ceremony identity, frame encoding or decoding, transcript, final ACK, timeout, or attempt accounting, and never sends or reads protocol bytes.
- **ABI v1 exactly.** The native library must report ABI version `1`. Version `0` (the version query itself failed) and any other version are permanent initialization failures.
- **One process-lifetime library image.** The native library is opened once and kept loaded for the rest of the process. There is no close, unload, reload, or reset. A native image that was loaded but failed verification also stays loaded: correct the library and restart the process. Load failures are reported as `SasPairingInitializationException`.
- **One owner isolate.** Dart statics are per isolate, not per process. All direct native access belongs to one Dart isolate per OS process; other isolates must not create runtimes or open the library.
- **Native artifact not bundled yet.** You build it and pass its absolute path; nothing is discovered, searched for, or downloaded. Distribution is a later P8 decision.

## Platforms

| Platform | Native ABI v1 | Pairing |
|---|---|---|
| Windows x64 | `sas_pairing_core.dll` loads and binds; the lifecycle and network APIs work | Windows TCP is the only supported pairing transport (P7): listener attach, bounded drive, events, and connections are available; the ceremony API comes in later P8 increments |
| Linux x64 | `libsas_pairing_core.so` loads and binds; a runtime can be created | Not supported: `registerAuthority` fails closed with `unsupportedPlatform`, so no host or listener exists; the network types compile and are tested against a fake only |
| 32-bit | Refused before any library is opened | Not supported |

## Development

Build the native artifact from the repository root, then run the checks from `dart/`:

```bash
cargo build --manifest-path core/Cargo.toml --release --features native-abi
```

```bash
dart pub get
```

```bash
dart format --output=none --set-exit-if-changed .
```

```bash
dart analyze --fatal-infos
```

```bash
SAS_PAIRING_NATIVE_LIBRARY="$(cd .. && pwd)/core/target/release/libsas_pairing_core.so" dart test
```

On Windows, point `SAS_PAIRING_NATIVE_LIBRARY` at the absolute path of `core\target\release\sas_pairing_core.dll`. Without it, the real-artifact tests are skipped locally (and fail in CI). The real lifecycle and network scenarios run in child processes (`test/support/lifecycle_child.dart`, `test/support/network_child.dart`) so that each process has one native owner isolate. The network scenarios get their loopback listening sockets from a test-only WinSock harness (`test/support/winsock.dart`); the package itself binds no socket.

Regenerate the raw bindings after a deliberate, owner-approved ABI change only (requires libclang). The result must match the committed file exactly:

```bash
dart run ffigen --config ffigen.yaml
```
