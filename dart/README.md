# `sas_pairing` (Dart)

Experimental, pre-alpha Dart package for the sas-pairing native core. **Not production-security approved, not audited, not formally verified.** Do not use it to protect production systems.

**Status: P8 IN PROGRESS — P8.5 COMPLETE.** The package binds the frozen [native ABI v1](../docs/p7-native-abi/abi-v1-manifest.md) and offers the native **lifecycle** API (runtime, authority, and host objects with a status and exception model) and, on Windows, the **listener ownership transfer and cooperative network driver** (attach an already-bound listening socket, drive the host one bounded call at a time, read events, close connections), **trusted-local ceremony control** (runs, the explicit ceremony steps, and the SAS presentation), and **local verified results** (runtime-owned results with an explicit snapshot read). The native artifact is not bundled yet (P8.6). See the [P8 package](../docs/p8-dart-package/README.md), [P8-D-001](../docs/p8-dart-package/decisions.md#p8-d-001--dart-native-binding-and-loader-architecture), [P8-D-002](../docs/p8-dart-package/decisions.md#p8-d-002--dart-lifecycle-ownership-and-fail-closed-state), [P8-D-003](../docs/p8-dart-package/decisions.md#p8-d-003--dart-windows-listener-cooperative-drive-and-connection-lifetime), [P8-D-004](../docs/p8-dart-package/decisions.md#p8-d-004--dart-run-identity-explicit-ceremony-control-and-sas-binding), and [P8-D-005](../docs/p8-dart-package/decisions.md#p8-d-005--dart-pairingresult-ownership-data-access-and-local-completion).

## What exists

- A pure-Dart package (`sas_pairing`, version `0.1.0-dev.1`, not published; no Flutter dependency, so it stays usable from Flutter applications). Its one runtime dependency is `package:ffi`.
- The public library `package:sas_pairing/sas_pairing.dart`: `SasPairingRuntime`, `SasPairingAuthority`, `SasPairingHost`, `SasPairingAuthorityStatus` with `SasPairingAuthorityState`, `SasPairingStatus`, and the exceptions `SasPairingInitializationException` (with `SasPairingInitializationFailure`), `SasPairingNativeException`, `SasPairingClosedException`, and `SasPairingContractException`; since P8.3 also `SasPairingBootstrap`, `SasPairingWindowsListenerSocket`, `SasPairingHostNetworkState`, `SasPairingConnection`, `SasPairingDriveBatch`, `SasPairingDriveFailure`, `SasPairingEvent`, and the event enums (`SasPairingEventKind`, `SasPairingStepKind`, `SasPairingProtocolEvent`, `SasPairingEventReason`, `SasPairingDeadlineKind`, `SasPairingCancelState`, `SasPairingCancelReason`), with `attachWindowsListener`, `detachListener`, `drive`, `recheckAfterResume`, and `networkState` on `SasPairingHost`; since P8.4 also `SasPairingRun` (from `SasPairingEvent.run` or `SasPairingConnection.startInitiator`), `SasPairingLocalAction` with `SasPairingLocalEvent`, `SasPairingSasPresentation` with `SasPairingCeremonyIdentity`, and `SasPairingRunEndedException`; since P8.5 also `SasPairingResult` (from `SasPairingEvent.result`), `SasPairingResultData`, and `SasPairingPeerRole`. All calls are synchronous.
- Private raw bindings under `lib/src/native/`, generated by `ffigen` from the frozen header [`core/include/sas_pairing.h`](../core/include/sas_pairing.h), and a private process-lifetime native-library loader that opens one native image from an explicit path, preflights all 25 exports, and requires `sas_pairing_abi_version() == 1`. Raw FFI types, pointers, native handles (runtime, authority, host, connection, run, result), raw sockets, native event, action, presentation, and result records, result field numbers, the `DynamicLibrary`, and the loader are never exported.

## Lifecycle

```dart
import 'dart:typed_data';

import 'package:sas_pairing/sas_pairing.dart';

void main() {
  final runtime = SasPairingRuntime.create(
    nativeLibraryPath: r'C:\path\to\sas_pairing_core.dll', // absolute; nothing is searched for
  );
  try {
    // A scope is arbitrary bytes, not text; it is copied for the call and not kept.
    final authority = runtime.registerAuthority(
      Uint8List.fromList([0x61, 0x70, 0x70, 0x00, 0x01]),
    );
    try {
      final status = authority.queryStatus();
      print('${status.state.name}, ${status.remainingOpportunities} remaining');

      final host = authority.createHost(); // no networking happens
      try {
        // Attach a listener and drive the host: see "Network (Windows, P8.3)" below.
      } finally {
        host.close();
      }
    } finally {
      authority.close(); // also closes any host still open
    }
  } on SasPairingNativeException catch (e) {
    print('${e.operation}: native status ${e.statusCode} (${e.knownStatus?.name})');
    if (e.processRestartRequired) {
      // SAS_PAIRING_FATAL: restart the OS process.
    }
    rethrow;
  } finally {
    runtime.close(); // also closes every authority and host still open
  }
}
```

- **Close explicitly.** No finalizer cleans up native objects. Use `try`/`finally`, closing children before parents, or rely on a parent's `close()`.
- **`close()` is locally idempotent and consuming.** The first call makes exactly one native cleanup call and marks the object closed **even if that cleanup reports an error** (for example `ownershipUncertain`): native handles are not retryable cleanup tokens, so the error is thrown once and never retried. Later calls do nothing.
- **Closing a parent closes its children.** `SasPairingAuthority.close()` makes one native release, which already destroys its hosts natively; its `SasPairingHost` objects are then closed, without separate host cleanup calls. `SasPairingRuntime.close()` makes one native destroy, which already releases its authorities and destroys their hosts; every authority and host object is then closed. `SasPairingHost.close()` never releases its authority.
- **Closed objects fail locally.** A normal operation on a closed object throws `SasPairingClosedException` without entering native code.
- **One live runtime.** A second `SasPairingRuntime.create` while one is open throws `SasPairingNativeException` (`alreadyInitialized`); the open runtime is never handed out again.
- **A runtime is not a security reset.** Closing a runtime and creating a new one reuses the same loaded native library and resets nothing: authority opportunity accounting, the START limiter, and every other process-session security state continue. Registering a scope again continues its budget.
- **`queryStatus()` reports native state.** `ready` with the remaining opportunities (1–10), or `busy` / `exhausted` with 0; any other successful answer is a `SasPairingContractException`. The native core stays authoritative; Dart only checks each answer and keeps no accounting copy. `SasPairingAuthorityState.busy` is a state, not the failure status `SasPairingStatus.busy`.

## Network (Windows, P8.3)

The host can take over one already-bound Windows listening socket and is then driven cooperatively: every call is synchronous and bounded, and nothing runs in the background. See [P8-D-003](../docs/p8-dart-package/decisions.md#p8-d-003--dart-windows-listener-cooperative-drive-and-connection-lifetime).

**Obtaining the socket is an advanced integration boundary.** The package does not bind, listen, choose an address, interface, port, or IP version, or configure discovery or a firewall, and it has no bind helper. Your application creates a TCP socket, binds it, and calls `listen` on it (through WinSock), then hands its raw `SOCKET` value over. The socket, its address, and its port are not peer identity, authentication, or trust.

```dart
import 'dart:typed_data';

import 'package:sas_pairing/sas_pairing.dart';

/// [alreadyBoundSocket]: a raw Windows SOCKET your application bound and put into the
/// listening state, owned exclusively by you and used by nobody else.
void serveOnce(SasPairingHost host, int alreadyBoundSocket, SasPairingBootstrap local) {
  final listener = SasPairingWindowsListenerSocket.fromNativeSocket(alreadyBoundSocket);
  try {
    host.attachWindowsListener(listener: listener, local: local); // no drive, no accept
  } finally {
    if (!listener.isTransferred) {
      // The attach failed before the native library took the socket: it is still yours.
      // closesocket(alreadyBoundSocket) here, through your own WinSock code.
    }
    // Once listener.isTransferred is true, never close or use that socket value again.
  }
  try {
    final batch = host.drive(); // ONE bounded native call (it may wait up to ~250 ms)
    for (final event in batch.events) {
      // Consume every event, in order, also when batch.failure is set.
      print('${event.kind.name} ${event.stepKind.name} ${event.reason.name}');
      final result = event.result; // see "Results (P8.5)" below
      if (result != null) {
        // A local verified result: this endpoint completed locally. It does NOT mean the
        // peer succeeded or stored anything. It survives the detach below.
      }
    }
    for (final event in batch.events) {
      if (event.shouldCloseConnection) event.connection?.close(); // RUN_UNTRACKED guidance
    }
    final failure = batch.failure;
    if (failure != null) {
      // The owner loop failed closed after producing the events above.
      if (failure.processRestartRequired) {
        // SAS_PAIRING_FATAL: clean up, then restart the OS process.
      }
    }
  } finally {
    host.detachListener(); // closes the listener and every connection natively
  }
}

SasPairingBootstrap exampleBootstrap(Uint8List publicKey) => SasPairingBootstrap(
  applicationIdentity: Uint8List.fromList('my-app'.codeUnits),
  keyAlgorithm: Uint8List.fromList('x25519'.codeUnits),
  publicKey: publicKey,
  sharedContext: Uint8List(0),
);
```

- **Bootstrap.** `SasPairingBootstrap` is four byte fields (`applicationIdentity`, `keyAlgorithm`, `publicKey`, `sharedContext`), copied when created and readable only through unmodifiable views. Dart does not validate it; the native core does, and refuses an invalid one with `invalidBootstrap`.
- **Socket ownership follows `isTransferred`.** While it is false (also after a failed attach such as `invalidBootstrap`, `listenerAlreadyAttached`, or `unsupportedPlatform`) the socket is yours to close. Once it is true (success, or `listenerSetupFailed` or `fatal` after the native library took the socket) never close, use, or hand on that socket value again; a transferred token cannot be attached again.
- **`drive()` is one bounded call, and you decide the cadence.** It makes exactly one native drive: deadline sweeps, at most one readiness wait of at most about 250 ms, at most one socket operation per connection, at most one accept. There is no background thread, timer, stream, isolate, or callback, and no stream API yet. Because the call blocks, do not call it blindly on a Flutter UI isolate, and never spin `while (true) host.drive();` without a scheduling or yield policy: persistent readiness can make calls return at once. All native access stays on one owner isolate.
- **`recheckAfterResume()`** makes one deadline sweep with no socket work, for trusted code that observed an OS resume notification. The package does not detect resume and never calls it by itself.
- **A nonzero native result is an exception; an owner-loop failure is data.** `drive()` throws `SasPairingNativeException` when the call itself failed (for example `listenerNotAttached`, `handlesExhausted`, or `fatal`) and then returns no events. When the call ran but the owner loop failed during it, `batch.failure` is set (`networkPollFailed`, `ownershipUncertain`, `ownerLoopClosed`, or `fatal`) and **every event of the batch is still valid and must be consumed**. Afterwards the network state is `failedClosed` and every connection is closed: call `detachListener()` or close the host. When the failure is `fatal`, restart the process after cleanup.
- **`RUN_UNTRACKED`: close that connection.** When `event.runUntracked` is true, `event.shouldCloseConnection` is true: after consuming the batch, call `event.connection?.close()`. The run exists in the native core but has no exact run handle, so no trusted local ceremony action could ever target it. The drive never closes it for you, so that no event of the call is lost and a failing cleanup cannot hide the batch.
- **`writePending`** means the connection still holds one outbound frame, which the native library writes itself on a later drive. It is not a failure or a trust signal.
- **Network states stay distinct.** `detached`: no network context. `attached`: listener and owner loop running. `listenerDisabled`: the listening socket is gone and nothing new is accepted, but existing connections continue and may still be driven; to replace the listener, call `detachListener()` and attach a new socket. `failedClosed`: the owner loop is gone and every connection is closed.
- **Connections.** Each accepted connection is one `SasPairingConnection`, and every event of that connection carries the same object. It is closed by `close()` (one native call, consuming, never retried; allowed after `fatal`), by its `connectionClosed` event, by `detachListener()`, by an owner-loop failure, or by closing its host or a parent. It exposes no handle, socket, or peer identity.
- **Request IDs** are exact routing and correlation bytes (0–64), never text, identity, or authentication.
- **Runs.** `event.run` is the live run an event names (null when none); see "Ceremony control" below.

## Ceremony control (Windows, P8.4)

A ceremony runs on a connection: endpoint A starts a local Initiator on its connection, and endpoint B's Responder run appears through B's drive events. Each local step is **one explicit call** into the native core, which alone decides authorization, exposure, the SAS, and completion. Nothing is chained, driven, or retried for you. See [P8-D-004](../docs/p8-dart-package/decisions.md#p8-d-004--dart-run-identity-explicit-ceremony-control-and-sas-binding).

The sketch below shows the Initiator side. It is **not** one synchronous script: every `...` is a point where you keep driving the host (and consuming every event) until the peer's next message has arrived, which may take many drives or never happen.

```dart
import 'package:sas_pairing/sas_pairing.dart';

/// [askUser] is your trusted-local UI: it shows the decimal SAS and returns the user's choice.
Future<void> pairAsInitiator(
  SasPairingHost host,
  SasPairingConnection connection,
  SasPairingBootstrap local,
  SasPairingBootstrap expectedPeer,
  Future<bool> Function(String decimalSas) askUser,
) async {
  // Start. Nothing else happens: no drive, no authorization, no exposure.
  final run = connection.startInitiator(local: local, expected: expectedPeer).run!;

  // ... drive: an event with identical(event.run, run) and protocolEvent `accept` arrives.

  run.authorizeExposure(); // records consent only: exposes, spends, and sends nothing
  run.exposeKey();         // THE SECURITY-SPENDING STEP (one opportunity, never refunded)

  // ... drive: the key is written; then the peer's key arrives (protocolEvent `responderKey`).

  final presentation = run.presentation(); // read-only; null while no SAS is live
  if (presentation == null) return;
  if (await askUser(presentation.decimal)) {
    run.approveSas(presentation.ceremonyIdentity); // MATCH only: nothing is sent
    run.emitBootstrapMac();                        // a separate step; its frame waits for a drive

    // ... drive: the MAC is written; the peer's MAC arrives (`bootstrapMacAuthenticated`).

    run.emitInitiatorFinish(); // Initiator only; a Responder gets `notInitiator`

    // ... drive: the native library writes the frames and confirms the final ACK itself;
    //     an event with a `result` reports this endpoint's local verified completion.
  } else {
    run.rejectSas(presentation.ceremonyIdentity); // ends the run; drive to send its CANCEL
  }
}
```

- **The package does not decide whether the SAS matches.** `presentation.decimal` (exactly `NNNN NNNN NNNN`) is comparison display data: it authorizes, approves, and proves nothing. Your application displays it, gets a trusted-local user (or policy) choice, and then calls `approveSas`, `rejectSas`, or `cancelSas` with exactly `presentation.ceremonyIdentity`. Equal displays on two screens are not an approval, and the package never compares them.
- **Ceremony identity.** `SasPairingCeremonyIdentity` is the exact 32-byte identity of the presented ceremony. You only get one from a presentation (there is no public constructor); its bytes are an unmodifiable copy and two identities with equal bytes are equal. It is not a peer identity, an authority, a request ID, or a secret. Passing an identity from another presentation still reaches the native core, which refuses it with `ceremonyIdentityMismatch` and changes nothing.
- **`exposeKey()` is the security-spending step.** `authorizeExposure()` records fresh consent for exactly this run and spends nothing. `exposeKey()` makes the native core consume that consent, reserve the authority's guard, and spend one opportunity before producing the key; a retry, reject, cancel, close, or teardown never refunds it. `queryStatus()` is the only budget view; the package keeps no accounting of its own.
- **`WRITE_PENDING` has two different meanings.** A `SasPairingNativeException` with `knownStatus == SasPairingStatus.writePending` means the requested action **did not run**: an earlier frame of the connection is still waiting to be written. Drive, then retry if it is still appropriate. `SasPairingLocalAction.writePending == true` means the action **ran** and the native library now holds its output: drive to send it. Neither is driven or retried automatically, and `presentation()` is never blocked by a pending write.

  ```dart
  try {
    run.emitBootstrapMac();
  } on SasPairingNativeException catch (e) {
    if (e.knownStatus != SasPairingStatus.writePending) rethrow;
    // Did not run. Drive, consume the events, and call it again only if still appropriate.
  }
  ```

- **Run lifetime.** A run can end without any event that says so (for example a deadline that names no request ID). So `run.isEnded == false` means only that the package has not yet seen the end, not that the native run is live. A later call may then throw `SasPairingNativeException` with `runEnded` (204): this is expected; from then on `isEnded` is true and every call throws `SasPairingRunEndedException` without entering native code. A run is known to have ended after a terminal action (`rejectSas`, `cancelSas`, or a `deadline` outcome, whose `action.run` is null), a visible ending or a result in a drive event, `runEnded`, or the end of its connection, host, or a parent. A ceremony refusal such as `notInitiator`, `noLiveSas`, or `missingAuthorization` does not by itself mean the run ended.
- **Identity of runs.** Every event and action that names the same native run carries the same `SasPairingRun` object; a run is never identified by its request ID, so a new run under a reused request ID is a different object. A run you start learns its request ID from the first event that names it; until then it has none.
- **Connection and loop endings.** `connectionEnded` from a ceremony call means the native library ended that connection: it is closed locally with all of its runs (no close call is needed). `ownershipUncertain` or `ownerLoopClosed` means the host's owner loop failed closed: every connection and run of the host is closed and its network state is `failedClosed`.
- **No final ACK call.** There is no API to confirm the final ACK; the native library writes every frame and confirms the final ACK itself after writing it completely.
- **Results.** A completed ceremony is reported by a drive event's `result` (see below). A local result means only that this endpoint completed locally: never that the peer completed, received the final message, or stored anything. A local action never returns a result.
- **Statuses are outcomes, not verdicts.** `ceremonyIdentityMismatch`, `notInitiator`, `connectionEnded`, and every other status describe one operation. None says the peer is malicious or trusted.

## Results (P8.5)

A drive event that completes a ceremony locally carries a `SasPairingResult` in `event.result` (`event.hasResult` is exactly `event.result != null`). See [P8-D-005](../docs/p8-dart-package/decisions.md#p8-d-005--dart-pairingresult-ownership-data-access-and-local-completion).

> **A result is ONE local verified completion: this endpoint's, and nothing more.** It does not mean that the peer completed, holds a result of its own, received the final message, or committed, and it is not persisted or established trust. Either side may be the only one holding a result. Two results on two screens are one healthy example, not a guarantee. The package never persists, enrolls, or trusts a peer; your application decides.

```dart
import 'package:sas_pairing/sas_pairing.dart';

void consumeResults(SasPairingHost host) {
  final batch = host.drive();
  for (final event in batch.events) {
    final result = event.result;
    if (result == null) continue;
    try {
      final data = result.read(); // one explicit, synchronous snapshot read

      // Application policy may decide what to do with (exact bytes, never parsed here):
      //   data.authenticatedPeerBootstrap   the peer's exact canonical Bootstrap frame
      //   data.authenticatedSharedContext   the authenticated shared context (may be empty)
      // data.peerRole is the PEER's role; data.ceremonyIdentity equals the identity of the SAS
      // presentation of the same ceremony. A local result is not bilateral success.
    } finally {
      result.close(); // or leave it to runtime.close()
    }
  }
}
```

- **The runtime owns results.** A result stays open across connection close, a `connectionClosed` event, `detachListener()`, an owner-loop failure (also one reported in the same batch as the result), host close, authority close, and `SAS_PAIRING_FATAL`. Only `result.close()` and `runtime.close()` end it.
- **Nothing is read for you.** Delivering an event reads nothing; `read()` is the only call that reads, every time you call it. It returns an immutable `SasPairingResultData`: `ceremonyIdentity` (the same `SasPairingCeremonyIdentity` type as a presentation), `peerRole` (`initiator` or `responder`: the **peer's** role, so the Initiator's result says `responder`), `profileVersion` (as reported, not validated), and four `Uint8List` byte fields: `requestId` (routing bytes, not text and not an identity), `authenticatedPeerBootstrap`, `authenticatedSharedContext`, and `profileIdentifier` (bytes, not decoded into text). Every byte field is a copy behind an unmodifiable view.
- **Authenticated, not trusted.** `authenticatedPeerBootstrap` and `authenticatedSharedContext` were authenticated inside this endpoint's locally completed SAS ceremony. They are useful inputs to your own policy, not proof of bilateral completion, persistent trust, or enrollment.
- **Reading after `SAS_PAIRING_FATAL` is allowed.** Result reads and `close()` are deliberately available after native FATAL, because they only touch already-owned, immutable ABI data and never re-enter the pairing core. This is the one exception to the normal-operation FATAL rule. After the package observed a native **contract violation**, however, `read()` is refused (`SasPairingContractException`, no native call); `close()` still works.
- **Failures.** A closed result throws `SasPairingClosedException` on `read()`. A native failure (for example `invalidHandle`) is a `SasPairingNativeException`, a success output that breaks the frozen contract (an unknown peer role, a length that contradicts the reported one) is a `SasPairingContractException`, and a failed read returns nothing partial and leaves the result open.
- **`close()` is consuming and idempotent.** The first call makes one native destroy and the result is closed even if it reports an error (thrown once, never retried); later calls do nothing. `runtime.close()` closes every remaining result with its one native destroy. Data you already read stays usable after both: it is plain Dart data.

## Errors

Five exception classes, kept distinct:

- **`SasPairingInitializationException`**: `SasPairingRuntime.create` could not load or set up the native library; `failure` (a `SasPairingInitializationFailure`) says why and `message` gives the detail. It has no native status. With `processRestartRequired == false` (`unsupportedPointerWidth`, `invalidLibraryPath`, `openFailed`) no library image was kept: correct the cause and call `create` again. With `processRestartRequired == true` (`missingSymbol`, `abiVersionQueryFailed`, `abiVersionMismatch`, `verificationFailed`) a library image is already loaded and cannot be replaced: every later `create` fails the same way; correct the library and restart the OS process.
- **`SasPairingNativeException`**: a native operation returned a nonzero status. `statusCode` is the exact value, including codes ABI v1 does not define (`knownStatus` is then `null`). Frozen outcomes such as `busy`, `exhausted`, `ownershipUnavailable`, `ownershipUncertain`, and `unsupportedPlatform` are always reported this way. Status `fatal` (900) requires an OS process restart (below).
- **`SasPairingClosedException`**: an operation on an object that is already closed (including `read()` on a closed `SasPairingResult`). Raised locally.
- **`SasPairingRunEndedException`**: an operation on a `SasPairingRun` already known to have ended. Raised locally; no native status. The first native report of an ended run is a `SasPairingNativeException` with `runEnded`.
- **`SasPairingContractException`**: the native library reported success but broke the frozen ABI v1 contract (for example a zero handle, or `ready` with more than 10 remaining). Every later normal operation and every result read is refused; closing existing objects stays allowed; restart the process with a correct library.
- **Statuses are not trust verdicts.** A status or exception is the outcome of one operation. It never says that a peer is trusted or malicious, that an attack happened, or that anything is authorized.

## `SAS_PAIRING_FATAL` means restart the OS process

If any native call reports `SAS_PAIRING_FATAL` (`SasPairingStatus.fatal`, `processRestartRequired == true`), the package permanently refuses every new or normal operation in this process, `SasPairingRuntime.create` included, without entering native code again. Closing existing objects still works, and results that already exist can still be read (`SasPairingResult.read()`) and closed: that only touches already-owned ABI data and never re-enters the pairing core. There is no reset, reload, or recovery API, and creating a new runtime is not recovery: restart the OS process.

## Rules the package keeps

- **No protocol in Dart.** The native Rust core implements the protocol and its cryptography. This package implements no SAS, MAC, hash, key agreement, request ID, ceremony identity, frame encoding or decoding, transcript, final ACK, timeout, or attempt accounting, and never sends or reads protocol bytes. It only checks the shape of the native decimal SAS display and passes the presented ceremony identity back unchanged. Result fields are returned as the exact bytes native reported; the authenticated peer Bootstrap is never parsed. Nothing is persisted, enrolled, or trusted automatically.
- **ABI v1 exactly.** The native library must report ABI version `1`. Version `0` (the version query itself failed) and any other version are permanent initialization failures.
- **One process-lifetime library image.** The native library is opened once and kept loaded for the rest of the process. There is no close, unload, reload, or reset. A native image that was loaded but failed verification also stays loaded: correct the library and restart the process. Load failures are reported as `SasPairingInitializationException`.
- **One owner isolate.** Dart statics are per isolate, not per process. All direct native access belongs to one Dart isolate per OS process; other isolates must not create runtimes or open the library.
- **Native artifact not bundled yet.** You build it and pass its absolute path; nothing is discovered, searched for, or downloaded. Distribution is a later P8 decision.

## Platforms

| Platform | Native ABI v1 | Pairing |
