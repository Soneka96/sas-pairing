# `sas_pairing` (Dart)

Experimental, pre-alpha Dart package for the sas-pairing native core. **Not production-security approved, not audited, not formally verified.** Do not use it to protect production systems.

**Status: P8 IN PROGRESS — P8.1 COMPLETE.** The package foundation and the private bindings of the frozen [native ABI v1](../docs/p7-native-abi/abi-v1-manifest.md) exist. **There is no pairing API yet:** the public library `package:sas_pairing/sas_pairing.dart` intentionally exports nothing. The high-level API (runtime, authority, and host lifecycle first) begins in P8.2. See the [P8 package](../docs/p8-dart-package/README.md) and [P8-D-001](../docs/p8-dart-package/decisions.md#p8-d-001--dart-native-binding-and-loader-architecture).

## What exists in P8.1

- A pure-Dart package (`sas_pairing`, version `0.1.0-dev.1`, not published; no Flutter dependency, so it stays usable from Flutter applications). Its one runtime dependency is `package:ffi`.
- Private raw bindings under `lib/src/native/`, generated by `ffigen` from the frozen header [`core/include/sas_pairing.h`](../core/include/sas_pairing.h): exactly the 25 frozen functions, the frozen constants, and the six frozen records. They are not exported.
- A private process-lifetime native-library loader that opens one native image from an explicit path, preflights all 25 exports, and requires `sas_pairing_abi_version() == 1`.
- Tests that compare all of it with the [ABI v1 manifest](../docs/p7-native-abi/abi-v1-manifest.md) and the header, and smoke tests against a real native artifact on Windows and Linux.

## Rules the package keeps

- **No protocol in Dart.** The native Rust core implements the protocol and its cryptography. This package implements no SAS, MAC, hash, key agreement, request ID, ceremony identity, frame encoding or decoding, transcript, final ACK, timeout, or attempt accounting, and never sends or reads protocol bytes.
- **ABI v1 exactly.** The native library must report ABI version `1`. Version `0` (the version query itself failed) and any other version are permanent initialization failures.
- **One process-lifetime library image.** The native library is opened once and kept loaded for the rest of the process. There is no close, unload, reload, or reset. A native image that was loaded but failed verification also stays loaded: correct the library and restart the process.
- **`SAS_PAIRING_FATAL` means restart the OS process.** No API recovers from it in the same process.
- **One owner isolate.** Dart statics are per isolate, not per process. All direct native access belongs to one Dart isolate per OS process; other isolates must not open the library or call it directly.
- **Native artifact not bundled yet.** You build it and pass its absolute path; nothing is discovered, searched for, or downloaded. Distribution is a later P8 decision.
- **No status is a trust verdict.** Native status values are mirrored raw.

## Platforms

| Platform | Native ABI v1 | Pairing |
|---|---|---|
| Windows x64 | `sas_pairing_core.dll` loads and binds | Windows TCP is the only supported pairing transport (P7); its Dart API starts in later increments |
| Linux x64 | `libsas_pairing_core.so` loads and binds | Not supported: pairing operations fail closed with `SAS_PAIRING_UNSUPPORTED_PLATFORM` |
| 32-bit | Refused before any library is opened | Not supported |

## Development

Build the native artifact from the repository root, then run the checks from `dart/`:

```bash
cargo build --manifest-path core/Cargo.toml --release --features native-abi
```

```bash
dart pub get
```

```bash
dart format --output=none --set-exit-if-changed .
```

```bash
dart analyze --fatal-infos
```

```bash
SAS_PAIRING_NATIVE_LIBRARY="$(cd .. && pwd)/core/target/release/libsas_pairing_core.so" dart test
```

On Windows, point `SAS_PAIRING_NATIVE_LIBRARY` at the absolute path of `core\target\release\sas_pairing_core.dll`. Without it, the real-artifact smoke test is skipped locally (and fails in CI).

Regenerate the raw bindings after a deliberate, owner-approved ABI change only (requires libclang). The result must match the committed file exactly:

```bash
dart run ffigen --config ffigen.yaml
```
