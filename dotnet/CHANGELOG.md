# Changelog

## 0.1.0-dev.1

First experimental, pre-alpha version of the .NET wrapper `SasPairing` (phase P9; `net10.0`). Not published to nuget.org or any other feed and not a release; there is no stable API or semantic-versioning promise yet. Not production-security approved, not audited, and not formally verified.

- **Native ABI v1 loader.** Binds exactly the frozen native ABI v1 (25 exports, ABI version 1) through private interop. The native library is loaded once per process from an explicit absolute path and stays loaded until the process exits (never `NativeLibrary.Free`); there is no search, download, unload, or reload.
- **Lifecycle.** `SasPairingRuntime`, `SasPairingAuthority`, and `SasPairingHost` (`IDisposable`, one native cleanup call each, the native cascade mirrored locally), the 48 frozen statuses, and distinct initialization, native, and contract exceptions. `SasPairingStatus.Fatal` requires an OS process restart; re-creating a runtime resets no security accounting.
- **Windows network driver.** Hand over an already-bound, listening `Socket` through `SasPairingWindowsListenerSocket` (a package-owned duplicate descriptor), then drive the host cooperatively, one bounded synchronous `Drive()` or `RecheckAfterResume()` at a time; every event of a batch is delivered, also when the owner loop failed; `RUN_UNTRACKED` disposal guidance; one `IDisposable` connection per native connection.
- **Ceremony and SAS.** One `SasPairingRun` per exact native run, one explicit call per ceremony step (`StartInitiator`, `AuthorizeExposure`, `ExposeKey`, `ApproveSas`, `EmitBootstrapMac`, `RejectSas`, `CancelSas`, `EmitInitiatorFinish`), and the read-only SAS presentation (`DecimalDisplay`, `NNNN NNNN NNNN`) with its exact 32-byte `CeremonyIdentity`. The application compares the SAS and decides; nothing is chained or approved automatically, and there is no final-ACK API.
- **Pairing results.** Runtime-owned `SasPairingResult` objects delivered by drive events and read explicitly into immutable, detached `SasPairingResultData`. A result is this endpoint's local verified completion only, never proof that the peer completed or that trust exists.
- **Experimental distribution.** Each commit's CI packs this Release assembly into `SasPairing.0.1.0-dev.1.nupkg` (no native library inside; byte-identical to the tested assembly) and stages the Windows x64 native library separately, uploading the GitHub Actions artifacts `sas-pairing-dotnet-nuget-<commit>` and `sas-pairing-dotnet-windows-x64-abi1-<commit>` with manifests, SHA-256 checksums, the project licenses, and a third-party dependency inventory. Both are unsigned, expire after 90 days, and must be used together from the same commit.

Limitations: pairing works on Windows x64 only (Linux loads the library but pairing fails closed; no macOS, mobile, ARM64, or 32-bit support); the application creates the listening socket and schedules every drive; one native image per process; nothing is persisted, enrolled, or trusted automatically.
