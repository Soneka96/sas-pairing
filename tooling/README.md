# Tooling

Keep repository tooling small and reproducible. Add tools only when a documented workflow or CI check needs them. No protocol generator, release automation, or package publishing tooling exists or is required at this stage: the P8 and P9 packaging tools stage and verify experimental CI artifacts and publish nothing ([P8-D-006](../docs/p8-dart-package/decisions.md#p8-d-006--dart-native-artifact-distribution-and-p8-final-closure), [P9-D-006](../docs/p9-dotnet-package/decisions.md#p9-d-006--net-managed-package-native-artifact-distribution-and-p9-closure)).

## Checks used by CI

| Script | What it checks | Where it runs |
|---|---|---|
| [`check_markdown_links.py`](check_markdown_links.py) | Every internal Markdown link in the repository names an existing file, and every `#fragment` into a Markdown file names a heading slug or an explicit `id` anchor | `consistency` job |
| [`check_abi_exports.py`](check_abi_exports.py) | A built native library exports exactly the 25 exports of the [ABI v1 manifest](../docs/p7-native-abi/abi-v1-manifest.md) (`--expect manifest`), or no `sas_pairing_` symbol for an ordinary build (`--expect none`); reads PE and ELF directly | `windows-core` and `unsupported-platform-fails-closed` jobs |
| [`package_dart_native.py`](package_dart_native.py) | `stage`: copies a built Windows x64 `sas_pairing_core.dll` (PE32+ AMD64, exactly the 25 manifest exports) byte for byte into the nine-file bundle `sas-pairing-dart-windows-x64-abi1` and generates its artifact manifest, SHA-256 checksums, README, and third-party license inventory (from `cargo metadata --locked`); `verify`: checks a bundle's file set, manifest, checksums, PE machine, exports, copied files, and (with `--source-library`) byte identity with the build output. It compiles nothing | `dart-package (windows-latest)` job (stage, verify, re-verify before upload) |
| [`package_dotnet_native.py`](package_dotnet_native.py) | The .NET counterpart of the P8 tool for the nine-file bundle `sas-pairing-dotnet-windows-x64-abi1` (manifest field `dotnet_package_version`); it imports the P8 tool's PE reader, export audit, and dependency walk unchanged. It compiles nothing | `dotnet-package (windows-latest)` job (stage, verify, re-verify before upload) |
| [`package_dotnet_nuget.py`](package_dotnet_nuget.py) | `stage`: copies the packed `SasPairing.0.1.0-dev.1.nupkg` byte for byte into the four-file bundle `sas-pairing-dotnet-nuget` with its manifest, checksums, and README; `verify`: reads the package as a ZIP and its `.nuspec` as XML (exact entries, id, version, `net10.0`, license, README, repository commit, no dependency, no native or test file) and, with `--assembly`, requires the packed assembly to be byte-identical to the built and tested one. It builds and publishes nothing | `dotnet-package (windows-latest)` job (stage, verify, re-verify before upload) |
| [`tests/`](tests/test_package_dart_native.py) | `test_package_dart_native.py`: the packaging tool on synthetic in-memory PE images (every bundle mutation must fail `verify`) and, when `SAS_PAIRING_NATIVE_LIBRARY` names the Windows DLL, on the real DLL; `test_p8_distribution_contract.py`: the workflow, package-metadata, license-copy, and current-documentation guards of P8-D-006; `test_package_dotnet_native.py` and `test_package_dotnet_nuget.py`: the P9 tools on synthetic PE images and packages (every mutation must fail) and, in the Windows .NET job, on the real staged DLL and package; `test_p9_distribution_contract.py`: the workflow, package-metadata, consumer-smoke, and current-documentation guards of P9-D-006; `test_p10_dovahlink_bootstrap_mapping.py`: the DovahLink consumer mapping vectors of P10-D-002 (every byte re-derived, the frame encoder checked against the frozen P3 core-generated Bootstrap frames, exact-comparison negatives) and the P10-D-003 audit and authorization-model guards; it implements no cryptography and no Bootstrap decoder | `consistency` job (`python3 -m unittest discover -s tooling/tests`), and with the real staged artifacts in `dart-package (windows-latest)` and `dotnet-package (windows-latest)` |

They need only Python 3 and Git (the packaging tool also runs `cargo metadata`).
