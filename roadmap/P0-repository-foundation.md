# P0 — Repository Foundation

## Status

✅ Complete. The repository history and current files establish this phase.

## Goal

Establish the project boundary and documentation needed to develop a security-sensitive pairing library deliberately.

## Why this phase exists

The project needs clear security, contribution, architecture, and protocol-status boundaries before protocol research can be evaluated.

## Inputs / prerequisites

Initial repository creation.

## Scope

The repository established its pre-alpha status, application-neutral intent, one-native-core direction, language-binding roles, security policy, contribution guidance, and documentation structure. It also added a repository-consistency CI check and an initial architecture ADR.

## Out of scope

Selecting or implementing a production protocol or cryptography.

## Deliverables

Root project, security, and contribution documents; architecture and protocol-status documents; decision-record structure; planned core, binding, vector, and tooling areas; repository-consistency CI.

## Security invariants

Documentation is not a security claim. Production readiness remains gated on protocol selection, implementation, and independent assessment.

## Exit criteria

The repository has an explicit project boundary, documented intended architecture, contribution and security guidance, and a consistency check.

## What this unlocks

Formalizing the threat model and protocol requirements in P1.
